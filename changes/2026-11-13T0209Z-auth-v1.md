## What and why

The assistant key presets of `SetAssistantKeys` now include statement export.
`READ_ONLY`, and so `TRADE_WITH_APPROVAL` too, grant `READ_STATEMENTS` on the
main account and on sub-accounts, beside the other read actions: exporting an
account statement moves no value, like reading balances.

## How clients use it

Nothing changes in the call. Setting a key with a preset binds it to the
preset's API policy, whose actions now include `READ_STATEMENTS`:

```http
POST /auth.v1.ApiKeyService/SetAssistantKeys
{ "keys": [ { "subaccountId": "9000000001", "publicKeyEd25519": "<base64>", "preset": "READ_ONLY",
              "registrationProof": "<proof>", "registrationDeadline": "2026-11-13T02:30:00Z" } ] }
```

`READ_ONLY` holds `READ_BALANCES`, `READ_SPOT`, `READ_INTERNAL_TRANSFERS`,
`READ_AUTO_WITHDRAW`, `READ_API_KEYS`, `READ_SUBACCOUNTS`,
`READ_DEPOSIT_ADDRESSES` and `READ_STATEMENTS`; on the main account also
`READ_PRICE_ALERTS`. `TRADE_WITH_APPROVAL` adds `TRADE_SPOT`, `SWAP` and
`CREATE_DEPOSIT_ADDRESS`; on the main account also `MANAGE_PRICE_ALERTS`.

## Migration

None required. A key set with a preset before this change keeps the policy it
was bound to; setting the preset again binds it to a policy with the new
actions.
