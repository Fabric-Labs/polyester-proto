## What and why

A trailing stop is no longer accepted in a state where it would act at once,
as stop-loss and take-profit triggers already are not:

- A trailing stop created with an activation price the price it watches has
  already reached (at or above it for a SELL, at or below it for a BUY) ends
  `FAILED` with `TRIGGER_FAILURE_REASON_TRIGGER_WOULD_TRIGGER_IMMEDIATELY`
  (244). It never activates and sends no order; its reserved funds are
  released. Before, it activated at the next trade.
- `ModifyTrigger` that moves the activation price of a trailing stop not yet
  activated onto a price already reached, or changes the trailing distance of
  an activated one so its trigger price is already reached, is refused with
  `ERROR_CODE_TRIGGER_WOULD_TRIGGER_IMMEDIATELY` (302). Nothing changes.
  Before, the stop activated or fired at once.
- An order modify that moves an attached trailing stop of an order with a fill
  in the same way is refused whole with the same error.

A trailing stop without an activation price, and clearing the activation price
(a present zero), still start trailing from the market at once. The comments
on `ERROR_CODE_TRIGGER_WOULD_TRIGGER_IMMEDIATELY` and
`TRIGGER_FAILURE_REASON_TRIGGER_WOULD_TRIGGER_IMMEDIATELY` now describe this.
No field, enum value, status or event is added or removed.

## How clients use it

Nothing new to call. Handle the existing error and failure reason for trailing
stops as for stop-loss and take-profit triggers: choose an activation price or
a distance the market has not reached, and retry.

```bash
# Authenticate as for any private write (omitted here).
curl -sS https://<api-host>/triggers.v1.TriggersService/ModifyTrigger \
  -H 'Content-Type: application/json' \
  -d '{"triggerId": "<trigger-id>", "symbolId": <symbol-id>, "activationPriceTicks": "<a price the last trade reached>"}'
# => error whose details carry ERROR_CODE_TRIGGER_WOULD_TRIGGER_IMMEDIATELY;
#    REST PUT /v1/triggers/<trigger public ID> answers code
#    TRIGGER_WOULD_TRIGGER_IMMEDIATELY.
```

## Migration

The message shapes are unchanged, but a request that used to act on a
trailing stop at once is now refused, so a client that relied on that must
change:

1. Handle `ERROR_CODE_TRIGGER_WOULD_TRIGGER_IMMEDIATELY` (302) from
   `ModifyTrigger` and order modifies for trailing stops, as for stop-loss and
   take-profit triggers.
2. Handle a trailing stop that ends `FAILED` with
   `TRIGGER_FAILURE_REASON_TRIGGER_WOULD_TRIGGER_IMMEDIATELY` (244) after its
   create.
3. To make a trailing stop start trailing from the market now, clear its
   activation price (a present zero) instead of setting one the market has
   already reached.
