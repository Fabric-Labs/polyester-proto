## What and why

The assistant can now change the user's display settings itself, instead of
pointing them to their settings: light or dark mode, language, display
currency, date and time formats, number format, first day of the week and
sounds. The client stays in charge: it declares which settings it can change,
receives each change as a run event, applies it and offers an Undo.

**Availability:** devnet only.

- `SendMessageRequest.display_settings` (new, repeated `DisplaySetting`): the
  display settings the client can change for the user when the run asks it
  to, each at most once, at most 8, never `SETTING_UNSPECIFIED`. Declare only
  those the client offers the user now. Omit them for a client without display
  settings: the run then changes none. They are part of the request the
  idempotency key covers.
- `DisplaySetting` (new enum): `APPEARANCE`, `LANGUAGE`, `CURRENCY`,
  `DATE_FORMAT`, `TIME_FORMAT`, `NUMBER_FORMAT`, `WEEK_START`, `SOUNDS`. Each
  value's comment lists the values the assistant may apply to it.
- `DisplaySettingAction` (new message), carried by the new `RunEvent` case
  `display_setting_action` (field 17): `tool_call_id`, `setting`, and an
  optional `value`. With a value, apply it; without one, the user did not name
  a value: show that setting's choices in the conversation and change nothing
  until the user picks. The event follows the `ToolFinished` event, with `ok`
  true, of the `set_display_preference` call that chose it.

Security, funds, API keys, permissions and notification channels are never
display settings: for those the assistant still offers a `DestinationsSuggested`
button.

## How clients use it

Declare the settings with each message:

```json
POST /ai.v1.AssistantService/SendMessage
{
  "text": "Switch to light mode",
  "idempotencyKey": "send-7a21c4",
  "displaySettings": ["APPEARANCE", "LANGUAGE", "CURRENCY", "DATE_FORMAT", "TIME_FORMAT", "SOUNDS"]
}
```

Then, from `WatchRun`:

```json
{"event": {"seq": "5", "toolFinished": {"toolCallId": "call_1", "name": "set_display_preference", "ok": true}}}
{"event": {"seq": "6", "displaySettingAction": {"toolCallId": "call_1", "setting": "APPEARANCE", "value": "light"}}}
```

and, for "change the language" with no language named:

```json
{"event": {"seq": "6", "displaySettingAction": {"toolCallId": "call_1", "setting": "LANGUAGE"}}}
```

Values, exactly as `value` carries them:

| Setting | Values |
| --- | --- |
| `APPEARANCE` | `light`, `dark`, `system` |
| `LANGUAGE` | `en`, `fr`, `zh-CN` |
| `CURRENCY` | a fiat code `GetCurrencyConversionConfig` lists, such as `EUR` |
| `DATE_FORMAT` | `MMM dd, yyyy`, `MM/dd/yyyy`, `dd/MM/yyyy`, `yyyy-MM-dd`, `yyyy/MM/dd`, `yyyy.MM.dd`, `dd-MM-yyyy`, `dd.MM.yyyy`, `dd MMM yyyy` |
| `TIME_FORMAT` | `12h`, `24h` |
| `NUMBER_FORMAT` | `US`, `EU`, `SPACE`, `CH`, `IN`, `NONE` |
| `WEEK_START` | `1` (Monday) to `6` (Saturday), `0` (Sunday) |
| `SOUNDS` | `on`, `off` |

Apply an action once, when it arrives in a run the client sent and follows;
replaying a run's events later, for example to show an earlier conversation,
applies none of them again. Offer the user an Undo back to the setting's
previous value. A client that no longer has the setting, or does not accept
the value, changes nothing. There is no call to report back: the assistant's
answer confirms the change in one short line.

## Migration

None: the field, enum, message and event case are new. A client that declares
no display settings gets no `display_setting_action` events, and a client that
does not know the event case skips it.
