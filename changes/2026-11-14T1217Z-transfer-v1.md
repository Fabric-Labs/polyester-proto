## What and why

Dust conversion: `transfer.v1.DustConversionService` turns dust, Trading
balances too small to trade, into one target asset (USDT to start) at index
prices less a disclosed fee (2% to start). One conversion moves every source
and credits the payout atomically, or moves nothing.

- A balance is dust when no open market accepts an order for it at the current
  index price and it is worth at most 10 USD. One conversion takes at most 20
  balances worth at most 200 USD together.
- An account converts once every 6 hours (refused conversions do not count),
  and each target has a daily conversion limit.
- RPCs: `ListDustBalances` previews, `QuoteDustConversion` prices for 30
  seconds, `CreateDustConversion` converts a quote under an idempotency key,
  `GetDustConversion` and `ListDustConversions` read conversions.

New `transfer.v1.ErrorCode` values 28–36 name the refusals:
`DUST_QUOTE_EXPIRED`, `DUST_PRICE_MOVED`, `DUST_NOT_ELIGIBLE`,
`DUST_WINDOW_ACTIVE`, `DUST_DAILY_LIMIT`, `DUST_BUSY`,
`DUST_TARGET_UNAVAILABLE`, `DUST_BALANCE_CHANGED` and
`DUST_CONVERSION_FAILED`. A refused conversion carries its code in
`refusal_code`.

A new policy action, `CONVERT_DUST` (`auth.v1.PolicyAction` value 39), and a
new subaccount permission, `SUBACCOUNT_PERMISSION_CONVERT_DUST`
(`auth.v1.SubaccountPermission` value 30), control quoting, converting and
reading conversions. Listing dust balances needs `READ_BALANCES`. The owner,
admin, trader and leveraged trader roles hold the permission; viewer and
treasury do not. It is opt-in: no existing API policy, subaccount policy or
the subaccount read-only floor includes it. No step-up is required, as the
value stays in the account.

## How clients use it

ConnectRPC, with a session token or a signed API key:

```http
POST /transfer.v1.DustConversionService/QuoteDustConversion
Content-Type: application/json

{"targetAssetId": 3}
```

```json
{
  "quoteId": "dq_6f1d2c3b4a5968778695a4b3c2d1e0f1",
  "expiresAt": "2026-11-14T12:00:30Z",
  "targetAssetId": 3,
  "feeBps": 200,
  "grossUsdE18": {"lo": "5500000000000000000"},
  "payoutE18": {"lo": "5390000000000000000"},
  "balances": [{"assetId": 10, "amountE18": {"lo": "5000000000000000000"}, "eligibility": "DUST_ASSET_ELIGIBILITY_ELIGIBLE", "usdValueE18": {"lo": "2500000000000000000"}}],
  "prices": [{"assetId": 10, "priceTicks": "500000000", "priceScale": 9, "asOf": "2026-11-14T11:59:58Z"}]
}
```

```http
POST /transfer.v1.DustConversionService/CreateDustConversion
Content-Type: application/json

{"idempotencyKey": "dust-2026-11-14-1", "quoteId": "dq_6f1d2c3b4a5968778695a4b3c2d1e0f1"}
```

- `subaccountId` (optional on every request) selects a subaccount, as for
  internal transfers.
- `ListDustBalances` with `targetAssetId` 0 previews the first target, lists
  every target in `targets`, and reports `targetAvailable` false when the
  target cannot be paid now. It reserves nothing.
- A quote has no `quoteId` when nothing converts. Create re-prices the quoted
  balances: a payout more than 1% below the quote is refused
  `DUST_PRICE_MOVED`, a source that is no longer its quoted whole balance
  `DUST_BALANCE_CHANGED`.
- Create answers `COMPLETED`, or `PROCESSING` when the outcome is not known
  yet; a processing conversion completes or is refused without another
  request. Poll `GetDustConversion` with its `conversionId`. Retrying Create
  with the same idempotency key returns the same conversion.
- `ListDustConversions` pages newest first: `limit` (0 means 20, at most 100)
  and `pageToken` from the previous `nextPageToken`.

REST: `GET /v1/trading/dust/balances`, `POST /v1/trading/dust/quotes`,
`POST /v1/trading/dust/conversions`,
`GET /v1/trading/dust/conversions/{conversionId}` and
`GET /v1/trading/dust/conversions`. Amounts are decimal strings in whole units
(`amount`, `usdValue`, `payout`, `fee`), enums drop their prefix (`ELIGIBLE`,
`COMPLETED`), and a refused conversion's `refusalCode` equals the REST problem
`code`, such as `DUST_BALANCE_CHANGED`.

## Migration

None: the service, the error codes, the policy action and the subaccount
permission are new. An API key converts dust only once its owner adds
`CONVERT_DUST` to the key's policy and, for a subaccount, to the subaccount's
policy.
