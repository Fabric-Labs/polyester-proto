## What and why

The assistant now has a daily allowance of AI usage for each main account,
set by the account's VIP tier and shared by every subaccount, and a daily
capacity across all accounts. Both reset at 00:00 UTC. A message sent past
either is not answered: its run ends at once with `RunFailed`, before any
model work, and two new `FailureCategory` values say which limit it met.

- `DAILY_LIMIT_REACHED` (7): the caller's main account used up today's
  free credits (see the later `GetUsage` note). `RunFailed.message` names
  them, when they reset and how to get more (a higher VIP tier, or the
  caller's own OpenAI API key).
- `ASSISTANT_PAUSED` (8): the assistant paused new answers for every account
  until 00:00 UTC. `RunFailed.message` says when it resumes.

A run that started below the limit always finishes; the next message is the
one refused.

## How clients use it

Nothing new to call. `SendMessage` records the message as before, and
`WatchRun` delivers the refusal as the run's only terminal event:

```json
POST /ai.v1.AssistantService/WatchRun
{"runId": "123", "afterSeq": "0"}

{"event": {"seq": "1", "runFailed": {
  "category": "DAILY_LIMIT_REACHED",
  "message": "You've used today's 250 free assistant credits for VIP 0. They reset at 00:00 UTC, in 3 h 12 min, and unused credits don't carry over. To get more, reach VIP 1 (500 free credits a day), or add your own OpenAI API key in the Polyester app (Settings → AI), which uses no credits. Buying credits is coming later.",
  "usage": {}
}}}
```

Show `RunFailed.message` to the user as written. Use the category to choose a
title or styling, for example "Daily limit reached" or "Assistant paused".

## Migration

None. Both values are new; a client that does not know them still receives
`RunFailed` with its `message` and should show it like any other failure.
