## What and why

`GetInternalTransferBatch` can now read a batch by the idempotency key the
caller sent to `BatchCreateInternalTransfers`, as well as by the request ID
that call returned. A client whose answer was lost, for example in a
timeout, can learn the batch's outcome without knowing its request ID.

Retrying `BatchCreateInternalTransfers` under the same key also returns the
stored outcome, but only while the caller may still move every source
account of the batch. The read needs only the permission to read the
transfers of every source account, so a caller who has since lost the right
to move a source, for example an API key whose policy no longer grants
`INTERNAL_TRANSFER`, or a member whose role was lowered to viewer, still
reads the answer it lost. The read never submits, retries or moves anything.

The key is scoped as `BatchCreateInternalTransfers` scoped it: to the
session's account, or to the API key that sent it. The answer is the
batch's stored outcome: `BATCH_ACCEPTED` with each leg's transfer ID,
`BATCH_PROCESSING`, or `BATCH_REFUSED` with each leg's reason.

Because the key is the caller's own, two answers differ from a read by
request ID, which answers `NOT_FOUND` for both:

- A batch its checks refused (refused before anything was admitted, so no
  request ID was ever returned) reads its stored refusal.
- A caller who may not read the transfers of one of the batch's source
  accounts is refused `PERMISSION_DENIED`, or `UNAVAILABLE` while that
  permission cannot be decided yet; retry the read.

`NOT_FOUND` by key means the caller submitted no batch under that key.

## How clients use it

Send exactly one of `request_id` and `idempotency_key`:

```http
POST /transfer.v1.InternalTransferService/GetInternalTransferBatch
Content-Type: application/json

{"idempotencyKey": "rebalance-2026-11-24-001"}
```

REST:
`GET /v1/trading/internal-transfers/batch?idempotencyKey=rebalance-2026-11-24-001`.
`requestId` remains available; a request with neither or both is refused
as invalid (ConnectRPC `INVALID_ARGUMENT`, REST 400). The response is unchanged. An API key needs
`READ_INTERNAL_TRANSFERS` in its own policy for either selector.

## Migration

None: reads by request ID behave as before, and `request_id` keeps its
field number and format.
