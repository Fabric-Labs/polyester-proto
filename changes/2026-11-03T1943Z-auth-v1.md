## What and why

Before the v1 launch, the public contract carries no `reserved`
declarations. A field or enum value that is withdrawn is deleted from the
contract, and one that comes back returns at its old number. Contract changes
before v1 that break source compatibility are announced in these notes instead
of being kept as reservations.

This publication removes every reservation the contract still carried:

- `auth.v1`: `WalletChallengePurpose`, `PolicyAction`,
  `SubaccountPolicyView`, `SubaccountPolicySpec`, `ApiPolicyView` and
  `ApiPolicySpec`.
- `chain.lifecycle.v1`: `AssetIds`, `FlowTxMatchView`, `FlowSummaryView`,
  `FlowStepView` and `FlowStepActivityView`.
- `orders.v1`: `ErrorCode`, `Order` and `UserTrade`.
- `privatews.v1`: `OrderEvent`.
- `swap.quickswap.v1`: `Screening`, `QuickSwapReason`, `Deposit`,
  `QuickSwapStatus`, `QuickSwap` and `ErrorCode`.

No field or enum value changes its number, name or type, and none is added or
removed. Messages encode and decode exactly as before, in binary and JSON.

## How clients use it

Nothing changes in the calls. Requests and responses are byte-for-byte the
same, for example:

```bash
curl -sS https://<api-host>/orders.v1.OrdersReadService/GetOrder \
  -H 'Content-Type: application/json' -d '{"orderId": "<order id>"}'
```

## Migration

None: the wire format is unchanged. Clients that regenerate from the new
contract get the same types and values. Code that read reserved ranges or
names from the contract's descriptors no longer finds any.
