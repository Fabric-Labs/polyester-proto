## What and why

**Availability:** devnet only. Not available on testnet yet; the service isn't deployed or routed there.

The assistant now places, shows and cancels every spot order type, not only
market and limit orders: stop-losses, take-profits, trailing stops, TWAPs,
ladders, good-till-date, immediate-or-cancel and fill-or-kill limit orders,
and orders with an attached take-profit, stop-loss or trailing stop. Two
additions let an app show them:

- New field `ApprovalRequested.parameters = 4`, a list of the new message
  `ApprovalParameter { string label = 1; string value = 2; }`: the key
  parameters of the action the user approves, such as the market, side,
  quantity, trigger price, a TWAP's duration, interval and slices, or a
  ladder's price range and levels. They are written from the same exact action
  as `summary`, never by the model.
- New `View` case `triggers_table` (field 7), message
  `TriggersTable { repeated triggers.v1.Trigger triggers = 1; bool truncated = 2; }`:
  the caller's triggers (standalone stop-losses, take-profits and trailing
  stops, those attached to an order, TWAPs and ladders) with their
  configuration, status, terminal reason and progress, as the Triggers API
  returns them.

## How clients use it

Watch a run as before. An approval for a TWAP looks like this:

```text
POST /ai.v1.AssistantService/WatchRun
{"runId": "6349022007070785130", "afterSeq": "0"}

{"event": {"seq": "4", "approvalRequested": {
  "approvalId": "4611686018427388100",
  "summary": "TWAP: buy 4 SOL on SOL-USDT over 5 min, one slice every 5 s (60 slices of about 0.066666 SOL), market slices, the market's default slippage cap per slice. ...",
  "expiresAt": "2026-11-09T11:30:00Z",
  "parameters": [
    {"label": "Type", "value": "TWAP"},
    {"label": "Market", "value": "SOL-USDT"},
    {"label": "Side", "value": "buy"},
    {"label": "Quantity", "value": "4 SOL"},
    {"label": "Duration", "value": "5 min"},
    {"label": "Slice interval", "value": "5 s"},
    {"label": "Slices", "value": "60 of about 0.066666 SOL"},
    {"label": "Execution", "value": "market"},
    {"label": "Trading account", "value": "<the trading account's public id>"}
  ]
}}}
```

- Show `parameters` in order, as label and value rows, under `summary`; decide
  with `DecideApproval` as before.
- Labels and values are plain words with units and assets; they are display
  text, not fields to parse.
- A `triggers_table` view arrives when the assistant lists or reads triggers.
  Render each `triggers.v1.Trigger` as the app renders the Triggers API's own
  list: the selected `configuration` case names the type, `runtime_details`
  carries progress (TWAP slices done, quantity filled, ladder levels filled).
  `subaccount_id`, `fee_asset`, `self_trade_prevention_mode`, `updated_at`,
  `armed_at` and `version` are not set in this view.

## Migration

None: the field, messages and view case are new. A client built on the
previous contract ignores `parameters` and skips the unknown view case, as the
contract already requires.
