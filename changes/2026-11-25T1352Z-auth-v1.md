## What and why

A sub-account a strategy bot holds or held keeps the bot's trading-only
policy. Before, ending the bot's access released the sub-account's policy to
the account to change. Now its funds come back only through the bot funds
return, so the policy can't be widened into a way out:

- `SetSubaccountPolicy` refuses to attach or apply another policy to it.
  Clearing its policy (no policy ID) stays allowed once the bot's access has
  ended, which is how the sub-account becomes reusable by a later bot.
- `UpdateSubaccountPolicy` refuses to edit the policy it holds.
- `CreateSubaccountPolicy` refuses to create a policy attached to it.

Each refusal is `FailedPrecondition` with `AUTH_STRATEGY_BOT_MANAGED`. This
applies to every caller: the owner's session, an admin member's and the
owner's admin API key. `EndStrategyBotAccess`'s description and the error
code's description say so.

## How clients use it

```json
// PATCH /v1/auth/subaccounts/{subaccount_id}/policy
// (POST /auth.v1.PolicyService/SetSubaccountPolicy)
{"subaccountId": "1234567890", "policyId": "9876543210"}
// -> failed_precondition, AUTH_STRATEGY_BOT_MANAGED, when a strategy bot
//    holds or held the sub-account; {"subaccountId": "1234567890"} with no
//    policyId clears its policy once the bot's access has ended
```

Show a bot sub-account's policy as fixed, and offer only "clear" after the
bot has stopped.

## Migration

None for a client that doesn't change policies on a strategy bot's
sub-account. One that did gets `AUTH_STRATEGY_BOT_MANAGED` and should clear
the policy instead, or leave it.
