## What and why

`GetSwap` and `ListSwaps` now read the Swaps of a sub-account that is not
active. Before, both answered `FAILED_PRECONDITION` `SUBACCOUNT_INACTIVE` for
such a sub-account, although `CancelSwap` already cancels its Swaps, so a
client could neither find the open Swaps to cancel nor follow a cancel to its
end. Reads still need the `SWAP` permission on the funding account, through
the caller's role or the API key's policy, and the sub-account's policy must
still grant it. Quoting and creating a Swap on a sub-account that is not
active still answer `SUBACCOUNT_INACTIVE`.

## How clients use it

List the open Swaps of a sub-account that is not active, then cancel each and
follow it with `GetSwap` until `isTerminal` is true:

```bash
curl -sS https://<api-host>/swap.v1.SwapService/ListSwaps \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer <session>' \
  -d '{"subaccountId": "1234567890123456789", "openOnly": true}'
```

```json
POST /swap.v1.SwapService/CancelSwap
{"swapId": "9876543210987654321"}
```

`ListSwaps` and `GetSwap` no longer return `SUBACCOUNT_INACTIVE`.

## Migration

None: a refusal is lifted. Clients that handled `SUBACCOUNT_INACTIVE` from
`GetSwap` or `ListSwaps` now receive the Swaps instead.
