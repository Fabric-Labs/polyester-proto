## What and why

`GetPortfolioEquityHistorySeries` now accepts a root-scoped API key as well as
a root-account session, exactly as `GetPortfolioEquitySnapshot` does.
Programmatic clients can read the same portfolio equity history the app
charts: the master account, the top owned subaccounts and the remaining owned
subaccounts combined, over the requested range.

The key's policy must grant `READ_BALANCES`. The history covers only
subaccounts the master account owns, never subaccounts it was only invited
to, and reads each one within that subaccount's policy. When the key may not
read one of them, the request fails instead of returning a partial history.
Subaccount-scoped API keys are refused.

## How clients use it

Sign the request with a root-scoped API key whose policy grants
`READ_BALANCES`.

```http
POST /ledger.read.v1.LedgerReadService/GetPortfolioEquityHistorySeries
Content-Type: application/json

{"range": "DAY_7"}
```

REST: `GET /v1/equity/portfolio/history/series?range=7d`.

The request and response are unchanged: `range` defaults to one day, and the
series list the master account first, then up to nine owned subaccounts by
current equity descending, then Remaining when other owned subaccounts exist.
Refusals, the same as the snapshot's:

- a key without `READ_BALANCES`: `PERMISSION_DENIED`, REST 403 with code
  `PERMISSION_DENIED` and the detail `API key policy does not grant
  READ_BALANCES`;
- a subaccount-scoped key: `PERMISSION_DENIED`, REST 403 with code
  `AUTH_API_KEY_ACCESS_DENIED` and the detail `READ_BALANCES requires an API
  key scoped to the main account`;
- an owned subaccount the key may not read: `PERMISSION_DENIED`, REST 403;
- account permissions temporarily unavailable: `UNAVAILABLE`, REST 503 with
  code `UPSTREAM_ERROR`; retry the request, after its `Retry-After` when
  present.

## Migration

None. Interactive sessions behave as before, and API keys were refused
before this change. A connected app granted the `account:read` scope now
reads the history over ConnectRPC with its delegated session, as it already
reads the snapshot; REST still refuses delegated sessions.
