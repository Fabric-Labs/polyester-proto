## What and why

A trigger that a halted market refuses after admission now reports why it
failed. The market-halt change that added the `MARKET_HALTED` cancel reasons
listed a known gap: such a trigger ended `STATUS_FAILED` but read
`failure_reason` as the unnamed value 212. That gap is closed. Its
`failure_reason` is now the existing `TRIGGER_FAILURE_REASON_MARKET_HALTED`
(8), on the trigger and on its `EVENT_FAILED` event, in reads and on the
private WebSocket alike. The attached legs of an order the halted market
refuses end the same way. No field, enum value or status is added.

## How clients use it

The reason appears wherever a trigger's or trigger event's `failure_reason`
already appears: `TriggersService.GetTrigger`, `ListTriggers` and
`ListTriggerEvents`, and the private WebSocket's trigger updates. No request
changes.

```bash
# Authenticate as for any private read (omitted here).
curl -sS https://<api-host>/triggers.v1.TriggersService/GetTrigger \
  -H 'Content-Type: application/json' -d '{"triggerId": "<trigger-id>"}'
# A trigger refused after the halt:
#   "status": "STATUS_FAILED",
#   "failureReason": "TRIGGER_FAILURE_REASON_MARKET_HALTED"
curl -sS 'https://<api-host>/v1/triggers/<base58-trigger-id>/events'
# REST drops the enum prefix: "failureReason": "MARKET_HALTED"
```

ConnectRPC JSON carries the trigger ID as the decimal string of its
`fixed64`; REST paths take the base58 public ID instead.

## Migration

None: the value already existed. A client that mapped the unnamed failure
reason 212 to "unknown", as that change advised, keeps working and now
shows "Market halted" for these triggers instead.
