## What and why

`orders.v1.ErrorCode` adds `ERROR_CODE_PATH_BODY_ID_MISMATCH` (95).
REST trigger modify, pause and resume now reject a non-empty body `triggerId`
that differs from the path ID with HTTP 400 and problem code
`PATH_BODY_ID_MISMATCH`. Neither trigger changes. An omitted or empty body ID
continues to use the path ID.

## How clients use it

Use the same public trigger ID in the path and body, or omit the body ID:

```http
PUT /v1/triggers/<trigger-id>
Content-Type: application/json

{"triggerPrice":"1"}
```

The same ID rule applies to `POST /v1/triggers/<trigger-id>/pause` and
`POST /v1/triggers/<trigger-id>/resume`. Both accept an empty body.
ConnectRPC requests such as
`/triggers.v1.TriggersService/PauseTrigger` with `{"triggerId":"99"}`
continue to identify their trigger only in the request message.

## Migration

Clients that send two different IDs must correct the body or omit its
`triggerId`. Previously the path ID silently replaced the body ID. Handle
`PATH_BODY_ID_MISMATCH` as a client input error; do not retry unchanged.
Clients already using matching, empty or omitted body IDs need no changes.
