## What and why

Comment-only. `AttachedExits.oco`, on an approval card's order preview, now
says exactly what linking an order's take-profit and stop-loss
one-cancels-the-other means, as `RiskPolicy.oco` does: it decides only what
canceling an exit's order ends. With `oco` set, canceling one exit's order
ends both exits; without it, only that exit ends. Canceling an exit itself
with `CancelTrigger` ends only that exit either way, and the other exit stays
active. The previous comment, "True when cancelling one exit ends the other",
read as if canceling one exit removed both.

## How clients use it

Nothing changes on the wire. `/ai.v1.AssistantService/WatchRun` streams an
approval card's order preview with its attached exits as before; a client
that shows `oco` should describe it as above and never tell the user that
canceling one exit removes the other:

```json
{
  "attached": {
    "takeProfit": { "triggerPrice": "67000" },
    "stopLoss": { "triggerPrice": "60500" },
    "oco": true
  }
}
```

## Migration

None for the wire. Clients that label `oco` as "canceling one exit cancels
the other" should change that copy to the meaning above.
