## What and why

A bot is a subaccount, so its money is read where every subaccount's money is
read, not through a second copy in the Strategies API. Three fields that
never carried data are removed:

- **`Bot.profit_and_loss`** (removed). A bot's profit and loss is read from
  `pnl.v1.ProfitAndLossService` by the bot's `subaccount_id`: realized and
  unrealized PnL in USD, daily PnL, and trading statistics.
- **`GetBotResponse.balances`** and the **`BotBalance`** message (removed). A
  bot's balances are its subaccount's, read with
  `ledger.read.v1.LedgerReadService.GetBalances` by `subaccount_id`.
- **`GetBotResponse.open_orders`** and the **`BotOrder`** message (removed).
  A bot's open orders are its subaccount's, read with
  `orders.v1.OrdersReadService.GetOpenOrders` by `subaccount_id`.

`StopBot`'s description also says what stopping a bot that is still being
deployed does: it ends the deploy before the bot starts.

## How clients use it

Read a bot with `GetBot`, then read its subaccount's money with the same calls
as any subaccount, naming `bot.subaccount_id`. For example, the profit and
loss of the bot's subaccount over its whole history, by ConnectRPC, whose JSON
carries the ID as a decimal string, as `GetBot`'s ConnectRPC JSON returns it:

```http
POST /pnl.v1.ProfitAndLossService/GetProfitAndLoss
Content-Type: application/json

{"subaccountId": "<subaccount ID, decimal>", "window": "PROFIT_AND_LOSS_WINDOW_LIFETIME"}
```

or by REST, which takes the same ID in base58, as every REST ID is written:

```http
GET /v1/pnl?subaccountId=<subaccount ID, base58>&window=LIFETIME
```

The two encodings are not interchangeable: a ConnectRPC decimal ID pasted into
a REST URL names another subaccount, or none. Convert between them, or read
the bot with the same protocol as its subaccount.

`ListDailyProfitAndLoss` gives the subaccount's PnL day by day, and
`GetTradingStatistics` its fills, fees, maximum drawdown and Sharpe ratio, with
the same `subaccountId`.

**A subaccount's history is not always one bot's.** Deploying a bot can reuse a
closed subaccount of an earlier bot of yours. The `LIFETIME` window then covers
the subaccount's whole history, the earlier bot's trades and transfers
included. A window that starts at the current bot's deployment is not available
yet. Until it is, read `LIFETIME` as the subaccount's profit and loss, not the
current bot's alone. A bot's own start is `Bot.created_at`, and the daily PnL
from that day on is the closest view.

## Migration

- Stop reading `Bot.profit_and_loss`; read the bot's subaccount with
  `pnl.v1.ProfitAndLossService.GetProfitAndLoss` instead.
- Stop reading `GetBotResponse.balances` and `open_orders`; read the bot's
  subaccount with `ledger.read.v1.LedgerReadService.GetBalances` and
  `orders.v1.OrdersReadService.GetOpenOrders`, naming its `subaccount_id`.

The removed fields were always empty, so no data is lost.
