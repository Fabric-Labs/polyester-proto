## What and why

An order control whose order ID names a trigger or an OCO list, not an
order, now returns ERROR_CODE_ORDER_UNKNOWN. It used to return
ERROR_CODE_ORDER_ALREADY_TERMINAL, which suggested that an order had ended
while the trigger or list was still live. This applies to `CancelOrder`,
each item of `BatchCancelOrders`, `ModifyOrder` and each item of
`BatchReplaceOrders`. It holds while the trigger or OCO list is live and
for one minute after it ends; later, such an ID may return
ERROR_CODE_ORDER_ALREADY_TERMINAL. No message, field or enum value changed.

## How clients use it

Cancel a trigger with `CancelTrigger` and an OCO list with `CancelOco`:

```bash
curl -sS https://<api-host>/triggers.v1.TriggersService/CancelTrigger \
  -H 'Content-Type: application/json' -d '{"triggerId": "<trigger id>"}'
curl -sS https://<api-host>/triggers.v1.TriggersService/CancelOco \
  -H 'Content-Type: application/json' -d '{"orderListId": "<list id>"}'
```

An order control naming a trigger or an OCO list changes nothing and
returns ERROR_CODE_ORDER_UNKNOWN:

```bash
curl -sS https://<api-host>/orders.v1.OrdersService/CancelOrder \
  -H 'Content-Type: application/json' -d '{"orderId": "<trigger id>"}'
```

## Migration

None: ERROR_CODE_ORDER_UNKNOWN already exists, and clients already handle it
as "no order of the account has that ID". A client that read
ERROR_CODE_ORDER_ALREADY_TERMINAL for a trigger's or OCO list's ID as "it
ended" should read the trigger or list instead.
