## What and why

An account read refused because the caller's API key policy, sub-account
policy or sub-account role does not grant the read's action now answers the
same way on every account read API, and names the action to grant. Before,
a client could not always tell which action was missing, and the ledger
reads answered their own codes for this refusal over REST.

Every such refusal is `403` with the code `PERMISSION_DENIED` and the `type`
`https://polyester.dev/problems/permission-denied`. Its detail ends with one
of these, where `<ACTION>` is the `auth.v1.PolicyAction` to grant:

- `API key policy does not grant <ACTION>`
- `Subaccount policy does not grant <ACTION>`
- `Your subaccount role does not grant <ACTION>`

| API | Before | Now |
| --- | --- | --- |
| Ledger reads (`/v1/balances`, `/v1/balances/history`, `/v1/equity/...`, `/v1/transfers`), REST | `403` with code `API_KEY_ACTION_DENY`, `ROLE_ACTION_DENY` or `SUBACCOUNT_POLICY_DENY`, the matching `type` (for example `.../api-key-action-deny`), and a detail naming no action | `403` `PERMISSION_DENIED`, `type` `.../permission-denied`, title `Permission Denied`, a detail naming the action, for example `api_key_action_deny: API key policy does not grant READ_BALANCES` |
| Ledger reads, ConnectRPC | `permission_denied` with `ErrorDetail` `ERROR_CODE_PERMISSION_DENIED`, and a message naming no action | unchanged, except that the message names the action |
| Statement exports (`/v1/statements/exports`), REST and ConnectRPC | `PERMISSION_DENIED`, detail `api_key_action_deny: API key policy does not allow exporting statements (READ_STATEMENTS).` | code and `type` unchanged; detail `api_key_action_deny: API key policy does not grant READ_STATEMENTS` |
| Funding flow account reads (`/v1/chain/account-flows`, `/v1/chain/account-flows/{flowId}`), REST and ConnectRPC | `PERMISSION_DENIED`, detail `API_KEY_ACTION_DENY` (or `ROLE_ACTION_DENY`, `SUBACCOUNT_POLICY_DENY`) | code and `type` unchanged; detail `PERMISSION_DENIED: API key policy does not grant READ_FUNDING_FLOWS` |

This replaces the REST code an earlier ledger note gave for a
`GetPortfolioEquitySnapshot` call by a key without `READ_BALANCES`: that call
now answers `403` `PERMISSION_DENIED`, not `API_KEY_ACTION_DENY`.

Other refusals, such as a key scoped to another sub-account or an unknown
key, are unchanged.

## How clients use it

Branch on the code, and read the action to grant from the detail:

```text
GET /v1/balances

403 application/problem+json
{"type":"https://polyester.dev/problems/permission-denied","title":"Permission Denied",
 "status":403,"detail":"api_key_action_deny: API key policy does not grant READ_BALANCES",
 "code":"PERMISSION_DENIED"}
```

Over ConnectRPC the code stays `permission_denied` and the ledger
`ErrorDetail` stays `ERROR_CODE_PERMISSION_DENIED`; the message names the
action the same way.

## Migration

A client that matched the ledger REST code `API_KEY_ACTION_DENY`,
`ROLE_ACTION_DENY` or `SUBACCOUNT_POLICY_DENY`, or their `type` URIs, must
match `PERMISSION_DENIED` and `.../permission-denied` instead. A client that
matched the old detail texts must match the new ones.
