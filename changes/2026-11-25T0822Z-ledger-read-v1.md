## What and why

A statement export now has a type, so the Statements page and API clients can
choose which file to produce:

- `ACCOUNT_STATEMENT`: the existing account statement, one row per entry,
  account bucket and asset, with the entry's net amount, the fees paid and the
  balance after it. Its columns are unchanged.
- `LEDGER`: new. One row per ledger movement, each transfer leg on its own, as
  `LedgerReadService.ListTransfers` returns it. A trade's settlement is several
  rows: its base and quote legs and each fee.

`CreateStatementExportRequest.type` is required. `StatementExport.type` echoes
it on create, get, cancel and list. Both types have the same period limit (366
days), asset filter, limits on exports in progress, 4,000,000-movement cap,
7-day retention and lifecycle.

The downloaded file is now named after its type:
`account-statement-<exportId>.csv` or `ledger-<exportId>.csv`, where it was
`statement-<exportId>.csv`. The download URL response's `filename` says the
same.

LEDGER columns, in order: `time`, `transfer_id`, `account` (`funding` or
`trading`), `asset`, `type` (the transfer reason, such as `trade_base`,
`trade_quote`, `taker_fee` or `deposit`), `side` (`debit` or `credit`),
`amount` (signed: negative for a debit), `counterparty` (`funding_account`,
`trading_account`, `external_address`, `private_counterparty`, `fee_account`
or `system_account`; empty when unknown), `balance` (after the movement),
`link_id` and `flow_id`. For consecutive rows of the same bucket and asset,
each balance equals the previous balance plus `amount`.

In both types, `flow_id` is now the lifecycle flow linked to the movement
before the export was created. A flow linked later is left out of the file,
even when the export is still being produced, so one export's file never
mixes two moments; `ListTransfers` and a new export show it.

## How clients use it

Create a ledger export over ConnectRPC:

```http
POST /ledger.read.v1.StatementExportService/CreateStatementExport
Content-Type: application/json

{"type": "LEDGER", "startTime": "2026-10-01T00:00:00Z", "endTime": "2026-11-01T00:00:00Z", "idempotencyKey": "ledger-2026-10"}
```

REST: `POST /v1/statements/exports` with the same body.

Then poll `GetStatementExport` until `status` is READY, and download the file
as before. A request without `type`, or with a value outside the enum, is
`INVALID_ARGUMENT` (REST `400`). Repeating an idempotency key with another
type is `FAILED_PRECONDITION` with `IDEMPOTENCY_KEY_REUSED` (REST `409`), as
for any other changed field.

## Migration

1. Send `type` on every `CreateStatementExport`: `ACCOUNT_STATEMENT` for the
   file you received before. A request without it is now refused.
2. If you save downloads under the server's name, expect
   `account-statement-<exportId>.csv` or `ledger-<exportId>.csv` instead of
   `statement-<exportId>.csv`.

Exports created before this change are account statements and are returned
with `type` ACCOUNT_STATEMENT.
