## What and why

The changelog can now name one more product area:

- `Surface` gains `TRADING_BOTS`, trading bots: strategies you build, backtest
  and share, and bots running them live. Changes to trading bots carry it in
  `Change.surfaces`, and a post section that covers trading bots carries it in
  `Section.surface`.
- `ListChangesRequest.surfaces` accepts up to 12 values, one per surface.

Clients can label trading bot changes and sections, and filter changes to
trading bots.

## How clients use it

```bash
curl -sS https://<api-host>/changelog.v1.ChangelogService/ListChanges \
  -H 'Content-Type: application/json' -d '{"surfaces": ["TRADING_BOTS"]}'
# {"changes": [{"title": "...", "surfaces": ["TRADING_BOTS"], ...}], ...}

curl -sS https://<api-host>/changelog.v1.ChangelogService/GetPost \
  -H 'Content-Type: application/json' -d '{"slug": "2026-11-25"}'
# {"post": {"summary": {...}, "sections": [
#   {"heading": "Trading Bots", "surface": "TRADING_BOTS", "changes": [...]}]}}
```

REST:

```bash
curl -sS 'https://<api-host>/v1/changelog/changes?surfaces=TRADING_BOTS'
curl -sS 'https://<api-host>/v1/changelog/posts/2026-11-25'
```

## Migration

None: the value is additive. Clients must keep tolerating enum values they do
not know, in `Change.surfaces` and in `Section.surface`: decode them as
unknown and show them without a product-area label rather than failing.
