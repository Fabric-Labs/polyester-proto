## What and why

**Availability:** devnet only. Not available on testnet yet; the service isn't deployed or routed there.

`ai.v1.AssistantService` is the API of the Polyester trading assistant. A
user sends a message, which starts a run: the assistant's answer, with the
tools, skills and subagents it uses. A run continues on the server when no
client watches it; its events are recorded before they are sent, so a client
can replay a run from the start or resume it after a disconnect without gaps
or repeats. Actions that change the account, such as placing an order, run
only after the user approves them.

The service has eight methods:

- `SendMessage`: send a message, to a new or an existing conversation, and
  start the run that answers it. Idempotent per caller and `idempotency_key`.
- `WatchRun`: a server stream of a run's events from `after_seq`: answer text
  (`TextDelta`, and `DiscardPartial` for text the assistant writes again after
  an interruption), tool calls, loaded skills, subagents, approval requests
  and their outcome, structured views (orders and balances tables, a price
  chart, a price alert card, a generic table) and the run's end
  (`RunCompleted` with usage, or `RunFailed` with a category).
- `CancelRun`: stop an active run.
- `DecideApproval`: approve or reject an action the assistant asked to take.
- `ListConversations` and `ListMessages`: the caller's conversations and
  their messages.
- `ListMemories` and `DeleteMemory`: what the assistant remembers about the
  caller, and forgetting one fact.

Every method needs a session token; API keys are not accepted. Another user's
conversation, run, approval or memory is reported exactly as a missing one.

## How clients use it

ConnectRPC, JSON over POST. Public IDs are `fixed64`, decimal strings in
JSON.

```bash
# Start a new conversation.
curl -sS https://<api-host>/ai.v1.AssistantService/SendMessage \
  -H 'Authorization: Bearer <session-token>' -H 'Content-Type: application/json' \
  -d '{"text": "What is BTC doing today?", "idempotencyKey": "msg-7f3a"}'
# {"runId": "18364758544493064720", "conversationId": "1290345521"}
```

`WatchRun` is a server-streaming method: use a ConnectRPC client (the
streaming protocol frames each message), not a plain JSON POST.

```ts
for await (const { event } of client.watchRun({ runId, afterSeq: lastSeq })) {
  lastSeq = event.seq;
  switch (event.event.case) {
    case "textDelta": /* append event.event.value.text */ break;
    case "discardPartial": /* drop text of TextDelta events with seq >= fromSeq */ break;
    case "runCompleted": case "runFailed": /* the run ended */ break;
    default: /* render or skip; skip kinds this client does not know */
  }
}
```

- Each event has a `seq`: 1 for the first, then increasing by exactly one.
  Reconnect with the last `seq` received as `after_seq`; 0 replays the run.
  The stream ends after `RunCompleted` or `RunFailed`; the server may also
  end it earlier, and the client then reconnects.
- A conversation runs one run at a time: `SendMessage` during an active run
  fails with `FAILED_PRECONDITION` and `RUN_ACTIVE`.
- Repeat `SendMessage` unchanged, with the same `idempotency_key`, after a
  timeout or `UNAVAILABLE`: it returns the same run and conversation.
- `ListConversations` (default 20, max 100), `ListMessages` (default 50,
  max 200) and `ListMemories` (default 50, max 200) are newest first and
  return `next_page_token`, empty on the last page; pass it back as
  `page_token` with the same filters.
- Errors carry an `ai.v1.ErrorDetail` with an `ErrorCode`.
