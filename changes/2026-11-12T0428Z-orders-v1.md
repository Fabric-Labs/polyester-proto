## What and why

`Order.batch_request_id` identifies the batch replacement that admitted the
order. It remains populated after cancellation or fill, including for
batch-replaced trigger-generated orders. A later batch that replaces this order
does not change its admission identity. Orders not admitted by batch replacement
return zero.

## How clients use it

Read the order with the same flags before and after it ends:

```http
POST /orders.v1.OrdersReadService/GetOrder
Content-Type: application/json

{"orderId":"<public-order-id>","includeExecutionHistory":false}
```

On REST, use `GET /v1/orders/<public-order-id>`. Compare `batchRequestId` with
the batch receipt's public ID to correlate the order with its admission batch.
The association is independent of receipt expiry and order version.

## Migration

No client changes are required. Previously completed orders may still return
zero because their batch association was not retained. This change does not
restore missing historical associations.
