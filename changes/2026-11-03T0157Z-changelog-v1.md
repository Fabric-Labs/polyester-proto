## What and why

The changelog can now name three more product areas, and it says which product
area each post section covers:

- `Surface` gains `MARKET_DATA` (prices, candles, order book, heatmaps and
  market overviews), `QUICKSWAP` (the QuickSwap swap app) and `REWARDS` (daily
  claims, campaigns, VIP tiers and fee discounts). `TRADING` now covers orders,
  triggers and protective orders, and order outcomes only.
- `Section.surface` is the product area of a section. It is
  `SURFACE_UNSPECIFIED` for a section not tied to one area, for example the
  changes that need your attention, or general changes.
- `ListChangesRequest.surfaces` accepts up to 10 values, one per surface.

Clients can group or label sections by product area, and filter changes by the
new areas.

## How clients use it

`GetPost` returns `surface` on each section. ConnectRPC JSON omits it when it
is `SURFACE_UNSPECIFIED`; the REST view also omits it then.

```bash
curl -sS https://<api-host>/changelog.v1.ChangelogService/GetPost \
  -H 'Content-Type: application/json' -d '{"slug": "2026-11-04"}'
# {"post": {"summary": {...}, "sections": [
#   {"heading": "Market data", "surface": "MARKET_DATA", "changes": [...]},
#   {"heading": "Changes that need your attention", "changes": [...]}]}}

curl -sS https://<api-host>/changelog.v1.ChangelogService/ListChanges \
  -H 'Content-Type: application/json' -d '{"surfaces": ["QUICKSWAP", "REWARDS"]}'
```

REST:

```bash
curl -sS 'https://<api-host>/v1/changelog/posts/2026-11-04'
curl -sS 'https://<api-host>/v1/changelog/changes?surfaces=QUICKSWAP&surfaces=REWARDS'
```

A change keeps its own `surfaces`, which `ListChanges` filters on; a section's
`surface` does not change which changes match.

## Migration

None: the values and the field are additive. Clients must keep tolerating enum
values they do not know, in `Change.surfaces` and in `Section.surface`, so
that later additions do not break them: decode them as unknown and show them
without a product-area label rather than failing.
