## What and why

Transfer history now links a failed withdrawal's debit to its withdrawal.
The `WITHDRAW_FAILED` (1075) debit of a withdrawal from the Funding account
to an external chain carries the withdrawal's `flow_id` in
`LedgerReadService.ListTransfers`, both when the withdrawal was rejected and
refunded and when it failed in execution. Clients can now show that debit
next to the withdrawal it belongs to. The contract does not change: `flow_id`
was already a field of every transfer row and was empty on these debits.

The flow itself is unchanged: it stays refunded (`STATE_REFUNDED`) or failed
(`STATE_FAILED`). The debit does not settle it, and the flow never shows a
ledger-settled step.

The realtime transfer stream does not carry the link yet: it publishes the
`WITHDRAW_FAILED` debit once, with an empty `flow_id`, and does not publish it
again with one.

## How clients use it

Transfer history returns the link in `flowId`, over ConnectRPC and REST:

```json
POST /ledger.read.v1.LedgerReadService/ListTransfers
{ "transferCode": "WITHDRAW_FAILED", "reversed": true, "limit": 50 }
```

`GET /v1/transfers?reversed=true` returns the same rows, with
`"transferCode": "withdraw_failed"`. Each `WITHDRAW_FAILED` debit
(`isDebit` true, from the Funding account to a system account) carries the
withdrawal's `flowId`, the ID `GET /v1/chain/flows/{flow_id}` accepts. The
amount, balance and count of these debits are unchanged: one debit per failed
withdrawal.

- The link is joined when transfer history is read. A read made before the
  withdrawal's refunded or failed outcome is recorded can return the debit
  with an empty `flowId`; a later read returns the link.
- Withdrawals that ended before this change reached an environment keep an
  empty `flowId` on their debit.
- On the realtime transfer stream, the `WITHDRAW_FAILED` leg arrives without
  `flowId` (JSON omits it, protobuf leaves `flow_id` empty), and no later
  publication adds it. Reload recent transfers over `ListTransfers` to get the
  link.

## Migration

None: the field and the code already exist, and no request changes. Clients
that group transfers by `flowId` now show the `WITHDRAW_FAILED` debit with its
withdrawal. Clients that keep transfer history from the realtime stream must
reload it over `ListTransfers` to see the link.
