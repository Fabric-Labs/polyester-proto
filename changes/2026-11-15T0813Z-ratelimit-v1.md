## What and why

`GetTradingRateLimits` documentation now states the limits that are actually
enforced. Placement and cancellation limits apply per trading account: the root
account and each subaccount have their own limits, and every API key and
session that trades for an account shares them. The previous text said the
API-key rules were enforced as well; they are not.

- `GetTradingRateLimitsResponse.rules`: the enforced placement and cancellation
  rules for the selected account.
- `GetTradingRateLimitsResponse.api_key_rules`: the rules resolved for the
  calling API key, now documented as informational. Trading requests are not
  limited per API key.

No field, type, number, path or enum value changed.

## How clients use it

Read the account rules to size a trading client's request budget:

```http
GET /v1/trading/rate-limits?subaccountId=<public subaccount ID>
```

```json
POST /ratelimit.v1.RateLimitService/GetTradingRateLimits
{"subaccountId": "<public subaccount ID>"}
```

Budget against `rules` (placement first, cancellation second). Several API keys
or sessions trading for one account draw on the same budget, so adding a key
does not add capacity.

## Migration

None for code: the wire contract is unchanged. A client that budgeted per API
key from `api_key_rules` should budget per account from `rules` instead.
