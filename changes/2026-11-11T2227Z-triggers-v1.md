## What and why

`ModifyTrigger` refuses a new or different nonzero activation price once a
trailing stop has started tracking. The whole patch is refused with
`ERROR_CODE_TRIGGER_ACTIVATION_PRICE_NOT_MODIFIABLE` (315), ConnectRPC
`failed_precondition`, REST HTTP 400. The existing peak or trough, trigger
price, settings and reserved funds remain unchanged.

Activation edits before tracking, clearing activation with zero, repeating
the current activation price, and distance or slippage edits remain accepted.
Pausing does not make an already activated trailing stop wait for activation
again.

## How clients use it

ConnectRPC: `POST /triggers.v1.TriggersService/ModifyTrigger`:

```json
{"triggerId":"9155001234567","activationPriceTicks":"25000000000"}
```

Prices use quote units scaled by 1e9. If this trailing stop already tracks,
this example is refused with code 315. A zero activation clears it; omit the
field to keep it.

REST: `PUT /v1/triggers/{triggerId}` uses the public trigger ID in the path
and a decimal price in the body, for example `{"activationPrice":"25"}`.
A refusal changes none of the other fields in the same patch.

## Migration

Handle `TRIGGER_ACTIVATION_PRICE_NOT_MODIFIABLE` as a refused edit and retain
the existing trigger in the UI. Stop offering a different nonzero activation
price once tracking has begun, including while paused. Omit unchanged fields
from edits. To wait for a new activation price, cancel the existing trigger
and create a new one. Existing clients that relied on the previously accepted
edit must change that behavior; it no longer succeeds.
