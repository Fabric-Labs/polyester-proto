## What and why

Adds `AuthErrorCode.AUTH_PATH_BODY_ID_MISMATCH = 58`. REST requests with a non-empty body resource identifier that differs from the path identifier return HTTP 400 with problem code `AUTH_PATH_BODY_ID_MISMATCH` and title `Path and Body ID Mismatch` before any action is performed. This applies to MFA challenge verification and factor updates, subaccount member MFA and role changes, invites, policy assignment, and copying address-book entries.

## How clients use it

For REST calls, omit the body resource identifier or send the same identifier as the path. For example:

```http
POST /v1/auth/mfa/challenges/mfa_aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa:verify-totp
Content-Type: application/json

{"code":"123456"}
```

A conflicting `challengeId` returns HTTP 400. ConnectRPC calls have no path resource identifier and retain their existing request behavior:

```http
POST /auth.v1.MFAService/VerifyTOTPChallenge
Content-Type: application/json

{"challengeId":"mfa_aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","code":"123456"}
```

## Migration

Clients that send conflicting resource identifiers must remove the redundant body identifier or make it match the path. Matching identifiers and omitted or empty identifiers continue to use the path resource. Numeric identifier fields use their normal encoded zero value when unset.
