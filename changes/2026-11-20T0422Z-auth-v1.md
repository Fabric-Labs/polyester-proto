## What and why

A strategy bot trades with an API key of its own, on a sub-account of its
own. The account gives the bot that key when it deploys the bot, and the key
stays under the bot's control until the bot's access ends: no other call
changes, revokes or re-binds it. Listing keys now shows which keys belong to
a strategy bot.

- `ApiKeyPurpose` gains `STRATEGY_BOT`. A `STRATEGY_BOT` key's policy allows
  spot trading only, within the trading limits of the bot's sub-account, and
  never an action that moves value out of the account.
- `ApiKey.strategy_bot_id` is a new optional field: the strategy bot the key
  trades for (an opaque ID). It is present only on a `STRATEGY_BOT` key.
- `CreateApiKey` and `UpdateApiKey` refuse `purpose: STRATEGY_BOT` with
  InvalidArgument, as they refuse `ASSISTANT`. No key becomes or stops being
  a `STRATEGY_BOT` key.
- `AuthErrorCode` gains three codes:
  - `AUTH_STRATEGY_BOT_MANAGED` (FailedPrecondition, HTTP 412): a strategy bot
    manages the key, policy or sub-account the call would change.
  - `AUTH_STRATEGY_BOT_SUBACCOUNT_INELIGIBLE` (FailedPrecondition, HTTP 412)
    and `AUTH_STRATEGY_BOT_OPERATION_CONFLICT` (AlreadyExists, HTTP 409): only
    the deploy flow meets them.

While a strategy bot holds its key, these calls answer
`AUTH_STRATEGY_BOT_MANAGED`: any `UpdateApiKey` of the key (its label
included), `DeleteApiKey` of the key, `SetApiKeyPolicy` on it, and
`UpdateApiPolicy`, `DeleteApiPolicy` and `CreateApiPolicy` with
`assign_to_key_id` on its policy; on the bot's sub-account, `CreateApiKey`,
`SetAssistantKeys` for it, `SetSubaccountPolicy`, `CreateSubaccountPolicy`
attached to it, `UpdateSubaccountPolicy` and `DeleteSubaccountPolicy` of its
policy, `InviteSubaccountMember`, accepting an invite to it,
`UpdateSubaccountMemberRole`, and `UpdateSubaccount` enabling it again.

These stay available: disabling the sub-account with `UpdateSubaccount`,
which disables the bot's key at once and is how the account cuts a bot off
besides stopping it, renaming the sub-account, `RemoveSubaccountMember` and
`SetSubaccountMemberMFARequirement`. A strategy bot's sub-account cannot be
enabled again. `DeleteAssistantKeys` revokes the assistant's keys only: a
bot's `STRATEGY_BOT` key is not an assistant key and stays as it is.

`SetStrategyBotAccess` and `EndStrategyBotAccess` now declare their typed
errors in the `polyester.api.error_codes` method option.

## How clients use it

`ListApiKeys` (`POST /auth.v1.ApiKeyService/ListApiKeys`) returns a strategy
bot's key like any other, for example:

```json
{"keyId": "ak_3f2a9c1b8e7d6f5a4c3b2a1f0e9d8c7b", "label": "Strategy bot",
 "purpose": "STRATEGY_BOT", "strategyBotId": "9223372036854775808",
 "status": "ACTIVE"}
```

The REST key list (`GET /v1/auth/api-keys`) carries the same fields, with
`strategyBotId` as a base58 string like its other IDs. Show a
`STRATEGY_BOT` key as belonging to its bot, and offer no edit, policy change
or delete for it. On `AUTH_STRATEGY_BOT_MANAGED`, tell the user the strategy
bot manages the key or sub-account and point to stopping the bot.

## Migration

None: the enum value, field and error codes are additive. A client that maps
every `ApiKeyPurpose` or `AuthErrorCode` value should map the new ones, and a
client that offers key edits should hide them for a `STRATEGY_BOT` key.

How a client built on the previous contract sees a `STRATEGY_BOT` key, which
`ListApiKeys` returns only to an account that deployed a strategy bot:

- Binary (protobuf over ConnectRPC): `purpose` decodes as the unrecognized
  value `4`, kept as a number; `strategy_bot_id` is an unknown field and is
  ignored.
- JSON (ConnectRPC JSON and REST): `purpose` is the string `"STRATEGY_BOT"`.
  A strict JSON parser rejects an enum name it doesn't know; one set to
  ignore unknown values leaves `purpose` unset. `strategyBotId` is an unknown
  field. Regenerate the client to read both.
- The new error codes reach older clients as their numeric `AuthErrorCode`
  values in the error details; the HTTP status (412 or 409) and the message
  are as documented.
