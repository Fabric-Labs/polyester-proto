## What and why

API-key request signing uses a five-second default receive window and allows timestamps at most one second ahead of the server clock. An optional signed `X-API-RECV-WINDOW` remains a whole number of milliseconds from 1 to 60000. HTTP requests no longer use `X-API-NONCE`. Signed trading and market-data WebSocket upgrades require a random, signed, single-use nonce.

## How clients use it

REST example: `POST https://<api-host>/v1/orders` with the normal order JSON body. ConnectRPC example: `POST https://<api-host>/orders.v1.OrdersService/CreateOrder` with the same request message encoded as ConnectRPC JSON. Send `X-API-KEY-ID`, `X-API-TIMESTAMP` (Unix milliseconds) and `X-API-SIGNATURE`; send `X-API-RECV-WINDOW` only when overriding the 5000 ms default.

The HTTP canonical payload is unchanged:

```text
TIMESTAMP_MS
[RECV_WINDOW_MS
]METHOD
PATH
CANONICAL_QUERY
SHA256_BODY_HEX
```

For HTTP, `PATH` retains the existing percent-decoded public request path (Go `URL.Path`). Square brackets denote an optional complete receive-window line, not literal characters. Join the lines with LF, without a trailing LF. For WebSocket upgrades use `GET`, the public escaped upgrade path, canonical query and the SHA-256 of an empty body. Append `\nws-nonce:` followed by exactly 32 lowercase hex characters encoding 16 cryptographically random bytes. Send that same nonce as `X-API-NONCE` and sign the entire resulting string with Ed25519.

## Migration

1. Remove nonce generation and `X-API-NONCE` from every REST and ConnectRPC signer. Keep the existing HTTP canonical string and signature encoding.
2. Synchronize the client clock. Timestamps more than 1000 ms ahead are rejected with `TIMESTAMP_SKEW`; requests older than 5000 ms are rejected by default. If needed, explicitly send and sign a receive window from 1 to 60000 ms; the one-second future allowance still applies.
3. For each trading or market-data WebSocket connection attempt, generate a fresh 16-byte cryptographically random nonce and encode it as 32 lowercase hex characters. Append the exact `\nws-nonce:<nonce>` suffix to the upgrade canonical string, sign it and send `X-API-NONCE`. Unsigned, absent, malformed or modified nonces are refused.
4. Never reuse a login nonce, including after a failed upgrade, disconnect or reconnect. Trading WebSocket login replays are rejected across replicas and edges with HTTP 401 `REPLAY_DETECTED` (`AUTH_REPLAY_DETECTED` in the auth error catalogue). Market-data WebSockets check single use within each server process.
5. A login authority outage refuses the trading session with HTTP 503 `AUTH_TEMPORARILY_UNAVAILABLE`; retry with a newly signed login and fresh nonce. HTTP 429 `REPLAY_CAPACITY_EXHAUSTED` also requires waiting and a fresh login. HTTP write requests retain their existing process-local signature replay protection; generate a fresh timestamp and signature when retrying an operation that permits retries.
