## What and why

A refused Triggers API field now answers the code the trading engine
answers for the same mistake, instead of the generic
`ERROR_CODE_VALIDATION_ERROR`, on REST and ConnectRPC alike, whether the
request is refused at the API or by the engine. The transport status is
unchanged: ConnectRPC answers `INVALID_ARGUMENT` and REST answers HTTP 400,
with the same field violation as before.

`CreateTrigger`:

| Field | Refused when | Code |
| --- | --- | --- |
| `client_trigger_id` | empty or longer than 36 bytes | `ERROR_CODE_CLIENT_TRIGGER_ID_INVALID` |
| `qty_scaled` | not positive | `ERROR_CODE_TRIGGER_QTY_INVALID` |
| `trigger_price_ticks` | missing or not positive | `ERROR_CODE_TRIGGER_PRICE_INVALID` |
| child `price_ticks`, trailing `limit_price_ticks` | not positive | `ERROR_CODE_BAD_PRICE` |
| trailing distance | missing, not positive, or basis points above 10000 | `ERROR_CODE_TRAILING_DISTANCE_INVALID` |
| `activation_price_ticks` | negative | `ERROR_CODE_TRIGGER_ACTIVATION_PRICE_INVALID` |
| `max_slippage_ticks` | not positive | `ERROR_CODE_SLIPPAGE_TICKS_INVALID` |
| `max_slippage_bps` | outside 1 to 10000 | `ERROR_CODE_SLIPPAGE_BPS_INVALID` |
| `max_slippage_bps` | 10000 on a SELL child or any trailing stop, which leaves no price | `ERROR_CODE_MAX_SLIPPAGE_INVALID` |
| TWAP `duration_ms`, `slice_interval_ms` | out of range | `ERROR_CODE_TWAP_DURATION_INVALID`, `ERROR_CODE_TWAP_INTERVAL_INVALID` |
| ladder `levels` | outside 2 to 100 | `ERROR_CODE_LADDER_LEVELS_INVALID` |
| ladder `price_min_ticks`, `price_max_ticks` | not positive, or the maximum not above the minimum | `ERROR_CODE_TRIGGER_PRICE_INVALID` |
| ladder price range | too narrow to place its levels a price tick apart | `ERROR_CODE_LADDER_RANGE_TOO_NARROW` |

`ModifyTrigger` answers the same codes for `trigger_price_ticks`, the
trailing distance and `activation_price_ticks`; its cap may be 0, which
clears it, so a negative `max_slippage_ticks` answers
`ERROR_CODE_SLIPPAGE_TICKS_INVALID` and `max_slippage_bps` outside 0 to
10000 `ERROR_CODE_SLIPPAGE_BPS_INVALID`. A modify's invalid
`activation_price_ticks` answered `ERROR_CODE_TRIGGER_PRICE_INVALID` before.

`CreateOco` answers `ERROR_CODE_BAD_QTY` for a non-positive `qty_scaled`,
`ERROR_CODE_TRIGGER_PRICE_INVALID` for a leg's non-positive
`trigger_price_ticks` and `ERROR_CODE_BAD_PRICE` for a leg's non-positive
limit price, as the trading WebSocket's `CreateOco` already did.

On REST, a malformed decimal answers the same code as the value on
ConnectRPC: a trigger's `qty` `TRIGGER_QTY_INVALID`, a ladder's `priceMin`
and `priceMax` `TRIGGER_PRICE_INVALID`, a trigger's `trailingDistance`
`TRAILING_DISTANCE_INVALID`, and a trigger's or modify's `activationPrice`
`TRIGGER_ACTIVATION_PRICE_INVALID`.

A request without a strategy, a conditional trigger without a child, or a
TWAP without an execution still answers `ERROR_CODE_VALIDATION_ERROR`: those
refuse the request's shape, not a field's value. The Orders API, including
attached take-profit, stop-loss and trailing legs, is unchanged.

## How clients use it

A client trigger ID longer than 36 bytes:

```http
POST /triggers.v1.TriggersService/CreateTrigger
Content-Type: application/json

{"trigger":{"symbolId":1,"qtyScaled":"1000000","clientTriggerId":"an-id-that-is-much-longer-than-36-bytes","trailingStop":{"side":"SELL","trailingDistanceBps":100}}}
```

answers `invalid_argument` with an `orders.v1.ErrorDetail` whose `code` is
`ERROR_CODE_CLIENT_TRIGGER_ID_INVALID` and whose violation names
`trigger.client_trigger_id`. REST answers the same request on
`POST /v1/triggers` with HTTP 400, `"code":"CLIENT_TRIGGER_ID_INVALID"` and a
violation on `trigger.clientTriggerId`.

A trailing stop without a distance answers
`ERROR_CODE_TRAILING_DISTANCE_INVALID` (REST `TRAILING_DISTANCE_INVALID`),
and a stop-loss whose market child is capped at 0 ticks
`ERROR_CODE_SLIPPAGE_TICKS_INVALID`.

## Migration

1. A client that matched `ERROR_CODE_VALIDATION_ERROR` (REST
   `VALIDATION_ERROR`) for any refusal above, on a trigger or an OCO, must
   match the field's code instead.
2. A client that matched `ERROR_CODE_TRIGGER_PRICE_INVALID` for a modify's
   invalid activation price must match
   `ERROR_CODE_TRIGGER_ACTIVATION_PRICE_INVALID`.
3. A REST client that matched `BAD_QTY` or `BAD_PRICE` for a malformed
   trigger `qty`, ladder `priceMin` or `priceMax`, trigger
   `trailingDistance` or `activationPrice` must match the codes above.

Field violations, HTTP statuses and ConnectRPC status codes are unchanged.
