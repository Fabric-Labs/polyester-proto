## What and why

`AssetConfig`, returned for each asset by `GetSpotConfig`, gains `optional bool included_in_equity`
(field 7). It says whether the asset counts in an account's total equity. The server always sets
it; an absent value means unknown (for example a server that predates the field), never false. An asset outside equity can still have a
market and a live index price, so a client that totals holdings itself must read this flag to
match the total equity Polyester reports.

## How clients use it

```http
POST /marketdata.v1.MarketDataService/GetSpotConfig
{}
```

REST: `GET /v1/spot/config`. Each entry of `assets` now carries `includedInEquity`:

```json
{ "asset": "BTC", "ledgerId": 3, "quantityDisplayDecimals": 8, "includedInEquity": true }
```

Value only the assets where it is `true`; list the `false` ones by amount with no value. Treat an
asset without the field as unknown: show no value for it, and never call it outside equity. REST
omits the property only when it is absent; `false` is sent as `false`.

## Migration

None: the field is new. Clients that ignore it decode responses as before.
