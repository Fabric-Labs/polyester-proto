## What and why

A stop-loss or take-profit created with a trigger price the market has already reached is now always refused, including on the index price. Before, a few creates on the index price (about 3 in 100) armed and fired a few milliseconds after they were submitted, placing an order the user did not intend, because a new index price arrived in the moments between submission and the trigger taking effect. The check now uses the same price that arms the trigger. A trigger whose price the market reaches in those few milliseconds is refused as well, in the same way a modify onto a reached price is; before, it fired. A trailing stop whose activation price is already reached is refused the same way. No message, field or enum value is added; only `TRIGGER_FAILURE_REASON_TRIGGER_WOULD_TRIGGER_IMMEDIATELY`'s documentation changes.

## How clients use it

The calls are unchanged. When the BTC-USDT index is 74,436.85, a sell
stop-loss on the index price with a trigger price of 74,936.85 is already
reached. ConnectRPC: `POST /triggers.v1.TriggersService/CreateTrigger`, prices
in ticks scaled by 1e9 and the quantity scaled by the pair's
`base_quantity_scale`:

```json
{"trigger":{"symbolId":1,"qtyScaled":"10000","clientTriggerId":"sl-1","stopLoss":{"side":"SELL","triggerPriceTicks":"74936850000000","triggerPriceSource":"INDEX_PRICE","child":{"marketIoc":{}}}}}
```

REST: `POST /v1/triggers` with decimal prices:

```json
{"trigger":{"symbol":"BTC-USDT","qty":"0.0001","clientTriggerId":"sl-1","stopLoss":{"side":"SELL","triggerPrice":"74936.85","triggerPriceSource":"INDEX_PRICE","child":{"marketIoc":{}}}}}
```

`CreateTrigger` returns the trigger ID, which acknowledges the request only. The trigger then ends `STATUS_FAILED` with
`failure_reason` `TRIGGER_FAILURE_REASON_TRIGGER_WOULD_TRIGGER_IMMEDIATELY`
and no child order: read it with `POST /triggers.v1.TriggersService/GetTrigger`
(`{"triggerId":"<trigger_id from CreateTrigger>"}`) or
`GET /v1/triggers/{trigger_id}`. A trigger price the market has not reached
arms as before, on the last price and on the index price alike.

## Migration

None: no client code changes. A client that expected a trigger to fire on a price reached a few milliseconds after submission gets the refusal and can place the order directly.
