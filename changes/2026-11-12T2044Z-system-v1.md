## What and why

`SystemService` gains `ListStatusEvents`, the environment's feed of scheduled
maintenance and incidents. Clients, bots and the web app can show upcoming
maintenance windows and ongoing incidents without scraping announcements.

Each `StatusEvent` carries:

- an opaque `id`, a `kind` (`MAINTENANCE` or `INCIDENT`) and a `state`
  (`SCHEDULED`, `IN_PROGRESS`, `COMPLETED` or `CANCELLED`);
- a `title`, a plain-text `message` (the summary), and the `start_time` and
  `end_time` window;
- the affected `services`, plus optional `markets` (pair symbols) and
  `assets` (asset codes);
- an optional `impact` for incidents (`DEGRADED`, `PARTIAL_OUTAGE` or
  `MAJOR_OUTAGE`);
- append-only progress notes in `updates`, oldest first;
- an optional `details_url`: an https link to a long-form announcement about
  the event, for example a planned upgrade;
- `cancelled_at` once cancelled, and `updated_at`.

`state` follows the window at the time of the response. An event is
`SCHEDULED` before `start_time`, `IN_PROGRESS` until `end_time` and
`COMPLETED` from `end_time` on. A maintenance always has an `end_time`. An
incident without an expected end has none and stays `IN_PROGRESS` until one
is set. `start_time` no longer changes once the window has started.

New types: `StatusEvent`, `StatusEventUpdate`, and the enums
`StatusEventKind`, `StatusEventState`, `StatusEventImpact` and
`AffectedService`. `AffectedService` has the values `TRADING`,
`MARKET_DATA`, `DEPOSITS`, `WITHDRAWALS`, `TRANSFERS`, `ACCOUNTS`, `API`,
`QUICKSWAP` and `APP`.

## How clients use it

The call is public, needs no authentication, and supports cacheable GET.
Answers can be up to 10 seconds old.

With no `states`, it returns current and upcoming events (`SCHEDULED` and
`IN_PROGRESS`), latest start first. `limit` defaults to 50 (maximum 200). Pass
`next_page_token` back as `page_token`, with the same `states` and `kinds`.

ConnectRPC:

```http
POST /system.v1.SystemService/ListStatusEvents
Content-Type: application/json

{"states": ["SCHEDULED", "IN_PROGRESS"], "kinds": ["MAINTENANCE"], "limit": 20}
```

REST, with repeated or comma-separated enum names; REST ids are base58:

```http
GET /v1/system/status-events?states=SCHEDULED,IN_PROGRESS&kinds=MAINTENANCE&limit=20&pageToken=...
```

```json
{
  "events": [
    {
      "id": "6k9TH7CDDXt",
      "kind": "INCIDENT",
      "state": "IN_PROGRESS",
      "title": "SOL deposits delayed",
      "message": "SOL deposits are taking longer than usual to be credited.",
      "startTime": "2026-11-12T19:30:00Z",
      "services": ["DEPOSITS"],
      "assets": ["SOL"],
      "impact": "DEGRADED",
      "detailsUrl": "https://example.com/announcements/sol-deposits",
      "updates": [
        {"id": 1, "message": "The cause is identified; credits are resuming.", "createdAt": "2026-11-12T19:45:00Z"}
      ],
      "updatedAt": "2026-11-12T19:45:00Z"
    }
  ]
}
```

To keep a banner current, poll at most every 10 seconds and compare
`updated_at` per `id`. A state change caused only by time passing doesn't
change `updated_at`.

## Migration

None: the RPC and its types are new.
