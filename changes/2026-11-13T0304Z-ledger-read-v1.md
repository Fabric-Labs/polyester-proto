## What and why

A statement now says how far it is complete. `ExportStatementResponse` gains
`complete_through`, and `GET /v1/statements` returns the same time in a
`Statement-Complete-Through` header. The statement covers movements from
`start_time` up to `complete_through`, exclusive. That time is the earliest
of `end_time`, the time of the first page's request, and the time through
which account history was complete when that page was requested. It is
never before `start_time`, and every page of one statement carries the same
value. Movements recorded just before a request can take a moment to reach
account history; a statement no longer includes some of them and silently
misses others.

## How clients use it

```http
GET /v1/statements?startTime=2026-11-01T00:00:00Z&endTime=2026-12-01T00:00:00Z
```

```http
HTTP/1.1 200 OK
Content-Type: text/csv; charset=utf-8
Statement-Complete-Through: 2026-11-13T03:04:05.123456789Z
Next-Page-Token: <opaque token>
```

- When `complete_through` is before `end_time`, request the rest, from
  `complete_through` to `end_time`, later.
- While account history is not available at all, the export fails with
  `UPSTREAM_ERROR` (ConnectRPC `unavailable`, HTTP 502); retry later.

## Migration

None for new requests. A page token issued before this change is refused as
invalid: restart that statement from its first page.
