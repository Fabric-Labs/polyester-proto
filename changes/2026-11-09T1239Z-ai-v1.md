## What and why

**Availability:** devnet only. Not available on testnet yet; the service isn't deployed or routed there.

The assistant can now show the user's deposit addresses. When a user asks
"what's my deposit address for BTC?", the run shows the address as a card the
user can copy, next to the assistant's answer.

- New `View` case `deposit_address` (field 8), message
  `DepositAddressCard { chain.deposit.v1.DepositAddress deposit_address = 1; optional uint32 asset_id = 2; }`.
- `deposit_address` carries the address and the chain it is assigned on, as
  `chain.deposit.v1.DepositAddressService` returns them.
- `asset_id` is the public unified asset ID (`AssetConfig.ledger_id` in
  `GetDepositWithdrawConfig`) the user asked to deposit. It is omitted when
  the card shows an address without one asset, for example when the user
  lists all their addresses.

An address takes deposits only on its own chain. Sending another asset, or
using another chain, can lose the funds, so a client shows the chain's name
next to the address and the same warning the deposit page shows.

## How clients use it

Watch a run as before; a card arrives as a `view` event after the tool call
that produced it:

```text
POST /ai.v1.AssistantService/WatchRun
{"runId": "6349022007070785130", "afterSeq": "0"}

{"event": {"seq": "1", "toolStarted": {"toolCallId": "call-1", "name": "get_deposit_address", "input": {"asset": "BTC"}}}}
{"event": {"seq": "2", "toolFinished": {"toolCallId": "call-1", "name": "get_deposit_address", "ok": true}}}
{"event": {"seq": "3", "view": {"depositAddress": {"depositAddress": {"chainId": 1, "depositAddress": "tb1q…"}, "assetId": 3}}}}
```

- Resolve `chainId` to the chain's name, and `assetId` to the asset's code,
  with `POST /chain.zipper.v1.ZipperService/GetDepositWithdrawConfig`
  (`GET /v1/chain/deposit-withdraw/config`).
- Show the address in full with a copy action, the chain's name, and the
  warning: "Send only BTC on Bitcoin Testnet to this address. Sending another
  asset, or BTC on another network, can lose the funds." Without `assetId`,
  name the assets the chain carries instead.
- A run that lists the user's addresses has one card per address, in the
  order of `ListDepositAddresses` (ascending chain ID).
- A card is never sent while the assistant is still asking which network to
  use.

## Migration

None: the view case and message are new. A client built on the previous
contract skips the unknown `View` case, as the contract already requires.
