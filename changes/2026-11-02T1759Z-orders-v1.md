## What and why

Order errors now name the field a client must fix, and REST answers the codes
ConnectRPC answers.

- The REST problem body of `orders.v1.OrdersService` methods gains an
  optional `violations` array: the field violations ConnectRPC returns in
  `orders.v1.ErrorDetail.violations` (or, for request validation failures, in
  `buf.validate.Violations`). Each item has `fieldPath`, `ruleId` and
  `message`. Before, a REST `VALIDATION_ERROR` said only "Request validation
  failed." and named no field.
- REST `fieldPath` values are REST request field paths: the field the client
  sent, such as `order.baseQty`, `order.limitGtc.price` or
  `items[2].limitGtc.price` for a batch item. This applies to the problem body
  and to the violations in batch and preview results, which used ConnectRPC's
  field names before.
- ConnectRPC `fieldPath` values name real request fields too. An order
  quantity off the pair's step or below its minimum now names
  `order.base_qty_scaled` (was `order.qty_scaled`). A limit price off the tick
  or not positive now names its execution's field, such as
  `order.limit_gtc.price_ticks` (was `order.execution.price_ticks`). A batch
  replace refused for one item's attached risk names that item, such as
  `items[1].new_attached_risk.take_profit.trigger_price_ticks` (was
  `items.new_attached_risk...`).
- A REST `POST /v1/orders` decimal finer than its scale answers the typed code
  an off-grid value answers: a `baseQty` with a nonzero digit beyond the
  pair's base scale answers `QTY_STEP_SIZE`, and a limit price or a
  tick-checked attached take-profit, stop-loss or trailing-stop price with a
  nonzero digit beyond 9 fractional digits answers `PRICE_TICK_SIZE`. Before,
  both answered `INVALID_ARGUMENT` "too many fractional digits". Excess digits
  that are all zeros, such as `"0.000100000"` at base scale 8, still answer
  `INVALID_ARGUMENT` "too many fractional digits".
- A REST batch over its item limit (`BATCH_TOO_LARGE`) carries the `items`
  violation ConnectRPC returns.

## How clients use it

```bash
curl -sS -X POST https://<api-host>/v1/orders \
  -H 'Authorization: Bearer <token>' -H 'Content-Type: application/json' \
  -d '{"order":{"symbol":"BTC-USDT","side":"SELL","maxQuoteDebit":"10","marketIoc":{}}}'
```

```json
{
  "type": "https://polyester.dev/problems/validation-error",
  "title": "Validation Error",
  "status": 400,
  "detail": "Request validation failed.",
  "code": "VALIDATION_ERROR",
  "violations": [
    {
      "fieldPath": "order.maxQuoteDebit",
      "ruleId": "buy_only",
      "message": "max quote debit sizing is only valid for BUY orders"
    }
  ]
}
```

A `baseQty` of `"0.000100001"` on a pair with base scale 8 answers (excerpt):

```json
{
  "status": 400,
  "code": "QTY_STEP_SIZE",
  "detail": "Quantity must align with the step size.",
  "violations": [
    {
      "fieldPath": "order.baseQty",
      "ruleId": "step_size",
      "message": "quantity does not align with the pair step size"
    }
  ]
}
```

ConnectRPC returns the same violation as
`{"fieldPath": "order.base_qty_scaled", "ruleId": "step_size", ...}` in
`orders.v1.ErrorDetail`.

`violations` is omitted when there are none. When no choice of a one-of group
was sent, `fieldPath` names the group, for example `order.execution` when an
order sets no execution. Branch on `code`, and on `ruleId` within it; `detail`
and `message` are human-readable only.

## Migration

1. A REST client that branched on `INVALID_ARGUMENT` for a `POST /v1/orders`
   quantity or price with a nonzero digit beyond its scale must branch on
   `QTY_STEP_SIZE` or `PRICE_TICK_SIZE` instead, the codes an off-step
   quantity or off-tick price already answered. A value whose excess digits
   are all zeros still answers `INVALID_ARGUMENT`.
2. A REST client that read batch or preview result violations must expect
   REST field paths (`items[2].limitGtc.price`) where it saw ConnectRPC names
   (`order.limit_gtc.price_ticks`).
3. A ConnectRPC client that matched `order.qty_scaled` or
   `order.execution.price_ticks` must match `order.base_qty_scaled` or the
   execution's own price field, such as `order.limit_gtc.price_ticks`; one
   that matched a batch replace's `items.new_attached_risk...` must expect the
   item index, `items[1].new_attached_risk...`.

A client that step 1 does not affect and that does not inspect `fieldPath`
needs no further change: `violations` stays optional.
