## What and why

**Availability:** devnet only.

The assistant reads images. A user can attach screenshots of an order, an
error or a chart to a message, and the assistant answers from the text and the
images together. The images stay with the message, so later answers in the
conversation can refer to them, and the conversation history shows them.

- `SendMessageRequest.images` (new, `repeated ImageAttachment`): at most 4
  images, in the order the user attached them. Each `ImageAttachment` has
  `data` (the file's bytes) and `mime_type` (`image/png`, `image/jpeg` or
  `image/webp`). Each image is at most 10 MiB, 8000 pixels on a side and 32
  megapixels in all. They are part of the request the idempotency key covers.
- `SendMessageRequest.text` may now be empty when the message has images; a
  message with neither is `INVALID_ARGUMENT`. With images, the text is the
  question about them.
- `Message.images` (new, `repeated MessageImage`): the images of a user
  message, each with `image_id`, `mime_type`, `width`, `height` and
  `size_bytes`, as the assistant stored them. An image larger than 2000 pixels
  on a side is scaled down to fit and may be stored in another of the three
  formats.
- `GetMessageImage` (new RPC, session token, no side effects): returns one
  image's `data` and `mime_type` by `image_id`, only to the user whose
  message it is.
- `ErrorCode` (new values): `IMAGE_TOO_LARGE`, `IMAGE_TYPE_UNSUPPORTED`,
  `TOO_MANY_IMAGES` (each with `INVALID_ARGUMENT` on SendMessage; nothing is
  recorded) and `IMAGE_NOT_FOUND` (`NOT_FOUND` on GetMessageImage).

Text in an image is read as part of the picture, never as instructions to the
assistant.

## How clients use it

Send a screenshot with a question:

```json
POST /ai.v1.AssistantService/SendMessage
{
  "text": "Why was this order rejected?",
  "idempotencyKey": "msg-0b6f2c9e",
  "images": [{ "mimeType": "image/png", "data": "iVBORw0KGgoAAAANSUhEUgAA…" }]
}
```

Show a conversation's images: ListMessages returns each user message's
`images` without their bytes; read each one with GetMessageImage.

```json
POST /ai.v1.AssistantService/GetMessageImage
{ "imageId": "5000000000123" }
```

Check the limits before sending to give the user an immediate answer; the
service enforces them all the same. On `INVALID_ARGUMENT`, read the
`ai.v1.ErrorDetail` code: `IMAGE_TOO_LARGE`, `IMAGE_TYPE_UNSUPPORTED` or
`TOO_MANY_IMAGES` name what to fix, and nothing was recorded, so the user can
send again.

## Migration

None. Every new field is optional and the new RPC is additive. A client that
sends no images behaves as before; only `text` may now also be empty when
images are attached.
