## What and why

A trigger's event history now records every fire that was refused while the
trigger stayed live. Before, such a refusal left no event: the next
`EVENT_FIRED` carried a later `child_seq`, and the attempts in between were
invisible. Users could not see why a take-profit or stop-loss placed no order
when its trigger price was crossed.

`TriggerEventType` gains `EVENT_FIRE_REFUSED = 7` (REST and WebSocket JSON
name `FIRE_REFUSED`). It is published once per refused attempt when:

- an attached take-profit, stop-loss or trailing stop's order is refused for
  the market's or the system's state, for example `MARKET_HALTED`, or
  `PAIR_POST_ONLY` for an order that would take liquidity. The trigger waits
  for the next price through its trigger price;
- an attached take-profit, stop-loss or trailing stop's order is refused
  because the remaining position is below the market's minimums
  (`MIN_NOTIONAL`, `MIN_QUANTITY`, `STEP_SIZE`). The trigger stays live and
  fires again once the position changes;
- a stop-loss, take-profit, trailing stop, TWAP slice or attached leg is
  refused for a rate limit (`RATE_LIMITED`) or because the account is under an
  automatic repair (`ACCOUNT_REPAIRING`). It fires again shortly.

`EVENT_FIRE_REFUSED` is not terminal: the trigger keeps its status,
`STATUS_ARMED` or `STATUS_RUNNING`. A refusal that ends the trigger is still
`EVENT_FAILED` with `failure_reason`, never also `EVENT_FIRE_REFUSED`. That
includes an attached leg refused below the minimums after its parent order
has ended.

`TriggerEvent` gains `optional TriggerFailureReason fire_refusal_reason = 22`,
the reason for the refusal, and `TriggerFailureReason` gains
`TRIGGER_FAILURE_REASON_ACCOUNT_REPAIRING = 239`.

## How clients use it

`ListTriggerEvents` returns the new events like any other, newest first. On
`EVENT_FIRE_REFUSED`:

- `child_seq` is the refused attempt. The next attempt takes the next one, so
  a later `EVENT_FIRED` names a higher `child_seq`.
- `child_order_id` is unset: no order was placed.
- `fire_price_ticks` is the price the attempt fired at, in quote units scaled
  by 1e9, set as on `EVENT_FIRED` (absent for time-scheduled triggers such as
  TWAP).
- `fire_refusal_reason` says why. It is set only on `EVENT_FIRE_REFUSED` and
  sits outside the `terminal_reason` oneof, so `cancel_reason` and
  `failure_reason` stay unset.

ConnectRPC, JSON over POST, authenticated with a session token or an API key.
`trigger_id` is the trigger's `fixed64` as a decimal string; `event_type`
filters to one event type:

```bash
curl -sS https://<api-host>/triggers.v1.TriggersService/ListTriggerEvents \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer <session-token>' \
  -d '{"triggerId": "<trigger-id>", "eventType": "EVENT_FIRE_REFUSED", "limit": 20}'
```

```json
{"events": [{"triggerId": "<trigger-id>", "eventType": "EVENT_FIRE_REFUSED",
  "childSeq": 1, "firePriceTicks": "104000000000", "tsNs": "<ns>",
  "fireRefusalReason": "TRIGGER_FAILURE_REASON_RATE_LIMITED"}]}
```

REST, with the trigger's base58 public ID; enum values drop their prefix:

```bash
curl -sS 'https://<api-host>/v1/triggers/<trigger-public-id>/events?eventType=FIRE_REFUSED&limit=20' \
  -H 'Authorization: Bearer <session-token>'
```

```json
{"events": [{"triggerId": "<trigger-public-id>", "eventType": "FIRE_REFUSED",
  "childSeq": 1, "firePx": "104", "tsNs": "<ns>",
  "fireRefusalReason": "RATE_LIMITED"}], "nextPageToken": ""}
```

The private WebSocket trigger-events channel carries the same event:
`eventType`, `childSeq`, `firePx` and `fireRefusalReason` in JSON, and
`triggers.v1.TriggerEvent` in protobuf.

Paging is unchanged: `limit` defaults to 100, maximum 1000; pass
`next_page_token` back as `page_token` with the same filter until it is empty.
An event is identified by `(trigger_id, event_type, child_seq, ts_ns)`.

## Migration

No change is required to keep working: no field or value was removed or
renumbered. Existing clients must still tolerate an event type and a
failure reason they do not know:

1. Do not treat an unknown event type as an error or as a terminal event.
2. Do not infer the trigger's status from its last event:
   `EVENT_FIRE_REFUSED` leaves it armed or running. Read the trigger's
   `status`.
3. Code that counts fires by `child_seq` should expect each refused attempt to
   use a `child_seq` of its own, recorded by an `EVENT_FIRE_REFUSED`.
