## What and why

Account statements: `ledger.read.v1.LedgerReadService/ExportStatement` exports
an account's balance movements for a period as CSV, for reconciliation and tax
reporting. It covers one account (the main account or one subaccount),
optionally one asset, for a period of up to 366 days.

Each CSV row is the effect of one entry on one account bucket (`funding` or
`trading`) in one asset. An entry is one ledger operation: a trade with its
fees, a deposit, a withdrawal step, an internal transfer, a move between the
account's buckets, or an adjustment. Every row carries the signed amount, the
fee the account paid, and the bucket balance after the entry, so that for
consecutive rows of the same bucket and asset, balance = previous balance +
amount - fee.

A new policy action, `READ_STATEMENTS` (`auth.v1.PolicyAction` value 38), and
a new subaccount permission, `SUBACCOUNT_PERMISSION_READ_STATEMENTS`
(`auth.v1.SubaccountPermission` value 29), control statement exports. Every
subaccount role has the permission, and every subaccount policy includes the
action as part of its read-only floor. An API key needs `READ_STATEMENTS` in
its policy: `READ_BALANCES` and `READ_INTERNAL_TRANSFERS` do not grant it.

## How clients use it

ConnectRPC, with a session token or a signed API key:

```http
POST /ledger.read.v1.LedgerReadService/ExportStatement
Content-Type: application/json

{"startTime": "2026-10-01T00:00:00Z", "endTime": "2026-11-01T00:00:00Z"}
```

```json
{
  "csv": "time,entry_id,type,account,asset,amount,fee,balance,link_id\r\n2026-10-03T08:12:45.123456Z,27419385013475392811,trade,trading,BTC,0.1,0,1.1,77\r\n2026-10-03T08:12:45.123456Z,27419385013475392811,trade,trading,USDT,-5000,2.5,4997.5,77\r\n",
  "nextPageToken": "..."
}
```

- `startTime` is inclusive and `endTime` exclusive, both required; the period
  must be non-empty and at most 366 days long.
- `subaccountId` selects a subaccount: the main account's session or API key
  may name any subaccount the main account owns, a subaccount-scoped key only
  its own subaccount, and a member's session any subaccount it holds a role
  on. `assetId` (optional) keeps one asset.
- Rows are oldest first. A page holds at most 2000 ledger movements and never
  splits an entry. Only the first page starts with the header row, so
  concatenating the `csv` of every page in order yields the whole statement.
  Repeat the request with the same fields and `pageToken` set to the previous
  `nextPageToken` until it is empty.
- Columns: `time` (RFC 3339 UTC, microseconds), `entry_id`, `type`, `account`,
  `asset`, `amount`, `fee`, `balance`, `link_id`. Amounts are exact decimal
  strings in whole asset units with up to 18 fractional digits.

There is no REST route yet.

## Migration

None: the RPC, the policy action and the subaccount permission are new.
Existing API keys cannot export statements until their owner adds
`READ_STATEMENTS` to the key's policy.
