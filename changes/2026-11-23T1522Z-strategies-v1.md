## What and why

A backtest of a bot on minute candles can now run without a start. An unset
`StartBacktestRequest.start_time` still means the most recent 365 days of
data for a bot on one hourly or daily candle series, or without candle calls.
When the calls the backtest can predict wouldn't fit in 365 days, it now
means the most whole days that fit, at least one day.

A backtest runs three cost scenarios and holds at most 30,000 calls of the
bot. The calls it predicts are a call for each close of each candle series
the bot declares, when its code handles candles, and one start call in each
scenario. A year of a single minute series is far more than that, so before
this change a backtest of a minute bot without a start failed as over its
budget. Now that bot gets its most recent 6 days, and a bot on two minute
series gets 3. More series, or finer ones, can shorten the window too.

Only those calls are sized. Calls the bot gets from its orders, its price
levels and its schedule can still take a backtest past its budget, and so
can a bot too busy for even one day.

A finished minute bot's report warning now also says that each candle the
bot is called on counts against the backtest's call budget, that its other
calls can still exceed it, and that a start gives a different window. It
still names the window the backtest covered. Only comments and that warning
text change; no field or value changes.

## How clients use it

```http
POST /strategies.v1.StrategiesService/StartBacktest
{"versionId": "sha256:...", "idempotencyKey": "..."}
```

The answer carries the backtest's ID. Read the window it resolved to from
the backtest:

```http
POST /strategies.v1.StrategiesService/GetBacktest
{"backtestId": "..."}
```

`backtest.window` holds its start and end. A request that gives `startTime`
keeps it, and a backtest of a window longer than its calls fit still fails
over budget.

## Migration

None for a request with `startTime`, or for a bot on one hourly or daily
series: it resolves to the same window and the same backtest as before. The
365-day default was never guaranteed either: short or gappy data could
already shorten it. A client that assumed an unset start is 365 days should
read the window from `GetBacktest`.
