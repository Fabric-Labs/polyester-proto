## What and why

Returning a stopped bot's funds: the owner moves every spendable balance of
a stopped bot's subaccount back to their main account in one call, without
naming assets, amounts or a destination. The main account is the only
destination, so the call needs no fresh MFA.

- `ReturnBotFunds(bot_id, idempotency_key)` returns the bot's funds and
  answers the return, a `BotFundsReturn`. The bot must be stopped.
- `GetBotFundsReturn(return_id)` reads a return as it stands.
- `BotFundsReturn` carries its `return_id`, `bot_id`, `status`, the `assets`
  moved so far (confirmed only: an amount still being moved counts once its
  move is confirmed), `held` (what the bot's open orders still hold), `requested_at`
  and `finished_at`.
- `BotFundsReturnStatus`: `RETURN_PROCESSING`, `RETURN_COMPLETED`,
  `RETURN_NOTHING_MOVED`.
- `ErrorCode` gains `BOT_NOT_STOPPED` (45) and `NOTHING_TO_RETURN` (46).
- `auth.v1.PolicyAction` gains `RETURN_STRATEGY_BOT_FUNDS` (52), the API-key
  permission for `ReturnBotFunds`. `GetBotFundsReturn` takes
  `READ_STRATEGIES`.

## How clients use it

```http
POST /strategies.v1.StrategiesService/ReturnBotFunds
{"botId": "...", "idempotencyKey": "..."}

POST /strategies.v1.StrategiesService/GetBotFundsReturn
{"returnId": "..."}
```

- **A return completes on its own.** It reads `RETURN_PROCESSING` while
  anything stays on the bot's subaccount, and returns each amount as it
  becomes spendable.
- **Kept orders.** After a `KEEP_ORDERS` stop, the bot's open orders can stay
  for days. Their holds show in `held`, per asset, and the return takes them
  once the orders fill or end.
- **Never taken:** what an open order's hold reserves.
- **Finishing.** It reads `RETURN_COMPLETED` once nothing stays, with `assets`
  the total it moved, or `RETURN_NOTHING_MOVED` when nothing was left to move.
- **Errors:**
  - `BOT_NOT_STOPPED` while the bot may still trade (deploying, running,
    paused, stopping). Retry once it reads `STOPPED`. If the bot reads
    `STOPPED` but an API-key call gets `BOT_NOT_STOPPED` because the bot's
    access is still live, its owner must first call `ReturnBotFunds` from
    their own interactive session to end that access. Retrying only with the
    API key cannot do this. Afterwards root-scoped API keys with
    `RETURN_STRATEGY_BOT_FUNDS` can return funds. Retry any recorded return
    with the same idempotency key.
  - `NOTHING_TO_RETURN` when nothing spendable is on the subaccount, or the
    return under the key ended with nothing moved.
  - `IDEMPOTENCY_CONFLICT` (`ALREADY_EXISTS`) for a key reused for another
    bot.
  - `BOT_NOT_FOUND` for another account's bot.
  - `SERVICE_UNAVAILABLE`: retry with the same key.
- **Who may call.** The call is open to the owner's own session, and to API
  keys scoped to the main account whose policy grants
  `RETURN_STRATEGY_BOT_FUNDS`. Connected apps can't return funds:
  `AUTH_SESSION_KIND_NOT_ALLOWED`. An invited member of the bot's subaccount
  gets `BOT_NOT_FOUND`.

## Migration

None: the RPCs, messages, error codes and action are new.
