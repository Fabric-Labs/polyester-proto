## What and why

Remove the unsupported public LedgerReadService.ListHolds RPC and the
ListHoldsRequest, HoldRow, and ListHoldsResponse messages. The RPC previously
returned UNIMPLEMENTED. The public /v1/holds route is removed as well.
Individual hold records are not exposed through the public account API.

## How clients use it

Use GetBalances `reserved` for held amounts. For ConnectRPC JSON, send
POST /ledger.read.v1.LedgerReadService/GetBalances with the account's normal
authentication and this body:

```json
{}
```

The equivalent REST request is GET /v1/balances. Select a subaccount with
subaccountId when needed and authorized.

Read reserved for each returned asset. In ConnectRPC, it is a U128 amount at
fixed 18-decimal scale. REST returns reserved as a decimal string in asset
units. The value is the aggregate amount held in the trading bucket, not a
list of individual holds.

## Migration

Use GetBalances `reserved` for held amounts. Remove ListHolds calls and
references to ListHoldsRequest, HoldRow, and ListHoldsResponse when updating
the SDK. Use each asset's reserved balance for aggregate held trading funds;
individual hold identifiers and expiry times have no public replacement.
