## What and why

The documentation of `CancelTriggerResponse.status` now states the guarantee
plainly: the status after a successful cancel is always canceled. It used to
say the status "should be" the prefixed enum name, which did not match the
REST value. Nothing else changes: the field, its type and the returned value
are the same.

## How clients use it

Cancel a trigger as before. ConnectRPC returns the prefixed enum name, REST
returns the value without the prefix:

```text
POST /triggers.v1.TriggersService/CancelTrigger
{"triggerId": "3458764513820540929"}
-> {"triggerId": "3458764513820540929", "status": "STATUS_CANCELED", ...}

DELETE /v1/triggers/92fHfkJgBqr
-> {"triggerId": "92fHfkJgBqr", "status": "CANCELED", ...}
```

## Migration

None: only documentation text changes.
