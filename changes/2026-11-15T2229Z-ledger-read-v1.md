## What and why

Devnet only for now: testnet keeps the previous behavior until its next
update.

`GetPortfolioEquitySnapshot` now accepts a root-scoped API key as well as a
root-account session. Programmatic clients, such as an assistant acting with a
master account's API key, can read the same portfolio equity snapshot the app
shows: the master account and every subaccount that master account owns, with
per-account and per-asset equity and the portfolio total.

The key's policy must grant `READ_BALANCES`. The snapshot covers only
subaccounts the master account owns, never subaccounts it was only invited
to, and reads each one within that subaccount's policy. When the key may not
read one of them, the request fails instead of returning a partial total.
Subaccount-scoped API keys are still refused.

## How clients use it

Sign the request with a root-scoped API key whose policy grants
`READ_BALANCES`. The request has no fields.

```http
POST /ledger.read.v1.LedgerReadService/GetPortfolioEquitySnapshot
Content-Type: application/json

{}
```

REST: `GET /v1/equity/portfolio/snapshot`.

The response is unchanged: the master account first, then each owned
subaccount by current equity descending. Refusals:

- a key without `READ_BALANCES`: `PERMISSION_DENIED`, REST 403 with code
  `API_KEY_ACTION_DENY`;
- a subaccount-scoped key: `PERMISSION_DENIED`, REST 403 with code
  `AUTH_SESSION_KIND_NOT_ALLOWED`;
- account permissions temporarily unavailable: `UNAVAILABLE`, REST 503 with
  code `UPSTREAM_ERROR`; retry the request, after its `Retry-After` when
  present.

## Migration

None: sessions behave as before, and API keys were refused before this
change.
