## What and why

Order request failures now return the existing specific public error codes for invalid side, self-trade prevention mode, fee asset, client order ID (including `newClientOrderId`), modify behavior, trigger price source, and cancel-all-after timeout. Undefined trigger price sources return `TRIGGER_PRICE_SOURCE_UNSUPPORTED` for attached-risk orders and standalone triggers on both surfaces. REST conversion failures include a field violation with the public request field path. The HTTP status remains 400, and no error enum values are added.

## How clients use it

For example, `POST /v1/orders` with an invalid side returns `INVALID_SIDE` and a violation naming `order.side`:

```json
{"order":{"symbol":"BTC-USDT","side":"HOLD","baseQty":"0.0001","limitGtc":{"price":"70000"}}}
```

The corresponding semantic failure at `/orders.v1.OrdersService/CreateOrder` uses an undefined numeric enum value:

```json
{"order":{"symbolId":1,"side":99,"baseQtyScaled":"10000","limitGtc":{"priceTicks":"70000000000000"}}}
```

Connect returns the same public code in `orders.v1.ErrorDetail`, with the canonical protobuf field path. Nested REST fields retain their full path, including batch indexes. Orders and triggers express execution with objects such as `limitGtc` and `marketIoc`; there are no separate type or time-in-force request fields.

## Migration

Update code that branches only on `INVALID_ARGUMENT` or `VALIDATION_ERROR` to handle the more specific codes. Use REST `violations[].fieldPath` or Connect `ErrorDetail.violations` to locate the field. Existing protobuf messages and enum values remain wire compatible.

Malformed REST order decimals keep `INVALID_ARGUMENT`; malformed REST trigger decimals change from `BAD_REQUEST` to `INVALID_ARGUMENT`. Both now include a field violation. Malformed Connect integer JSON and unrecognized enum strings fail during decoding, before domain validation: they retain transport `invalid_argument`, with the field named in the message and without a domain ErrorDetail. Numeric enum values reach domain validation and receive the specific public code.
