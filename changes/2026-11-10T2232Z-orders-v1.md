## What and why

The API reference for Cancel All Orders and Cancel All After (the dead-man
switch) now states, on the REST and ConnectRPC operations and on the SBE
trading WebSocket's CancelAllOrders and CancelAllAfter messages, what they
cancel and what they leave running:

- They cancel open orders, including those that triggers placed (TWAP
  slices, ladder levels and exit orders), but not triggers.
- Standalone stop-loss, take-profit and trailing triggers and TWAPs keep
  running and can place new orders. A ladder stops once its levels are
  canceled.
- An attached stop-loss, take-profit or trailing leg whose exit order is
  canceled ends, and so do the parent's other legs when `oco` is set, so the
  position loses that protection. Other attached legs keep protecting the
  parent's filled quantity; those of a parent canceled before any fill end
  with it.

A client that wants to stop all automated trading must cancel its triggers
separately. Behavior, messages and fields are unchanged; only descriptions
change.

## How clients use it

To stop all automated trading, cancel each live trigger first, then cancel
the orders, so that a trigger firing before its cancel places no order that
outlives the cancel-all.

ConnectRPC:

```bash
# 1. List live triggers.
curl -sS https://<api-host>/triggers.v1.TriggersService/ListTriggers \
  -H 'Content-Type: application/json' \
  -d '{"status": ["STATUS_CREATED", "STATUS_ARMED", "STATUS_RUNNING", "STATUS_PAUSED"]}'
# 2. Cancel each one.
curl -sS https://<api-host>/triggers.v1.TriggersService/CancelTrigger \
  -H 'Content-Type: application/json' -d '{"triggerId": "<trigger-id>"}'
# 3. Cancel the open orders.
curl -sS https://<api-host>/orders.v1.OrdersService/CancelAllOrders \
  -H 'Content-Type: application/json' -d '{"requestId": "<request-id>"}'
```

REST: `POST /v1/orders/cancel-all` and `POST /v1/orders/cancel-all-after`
behave the same way; cancel triggers through the triggers endpoints first.

## Migration

None: no request, response or behavior changes. Clients that relied on
Cancel All Orders or the dead-man switch to stop TWAP, stop-loss,
take-profit or trailing triggers must cancel those triggers explicitly.
Clients that keep attached legs as position protection must not expect them
to survive a cancel-all that cancels their working exit order.
