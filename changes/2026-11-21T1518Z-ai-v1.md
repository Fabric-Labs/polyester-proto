## What and why

A subagent's end now says which strategy revision it saved, so a client that
shows the strategy beside the assistant, such as Strategy Studio, knows when to
read it again.

- **`SubagentFinished.draft_version`** (new field 6, message `DraftVersion`) is
  set whenever one of the subagent's saves of one of the caller's strategies is
  known to have landed, valid or not, whatever its outcome: completed, stopped
  at its credit cap, stopped by a draft conflict, or ended with a cancelled or
  failed run. It names the last revision known to have landed: `strategy_id`,
  `revision` and `version_id`.
- It is absent when no save is known to have landed, including when the
  outcome of the subagent's last save is unknown (its reply never arrived).
  Then read the strategy's revisions (`ListStrategyRevisions`): an absent value
  never means nothing changed.
- It is a hint to refresh and carries no capability: read the strategy itself
  (`strategies.v1.StrategiesService/GetStrategy` or `GetStrategyVersion`) for
  what it shows.
- `SubagentFinished` is a stored run event, so `WatchRun` from `after_seq` 0
  replays it for a client that reopens the conversation.

## How clients use it

Nothing new to call. Watch the run as before and read the new field on the
`subagent_finished` event:

```http
POST /ai.v1.AssistantService/WatchRun
Content-Type: application/json
Connect-Protocol-Version: 1

{"runId": "1234"}
```

One event of the stream:

```json
{
  "seq": "42",
  "subagentFinished": {
    "subagentId": "7Hq2",
    "name": "strategy-coder",
    "ok": true,
    "summary": "Answered: see the assistant's reply.",
    "draftVersion": {
      "strategyId": "5678",
      "revision": "3",
      "versionId": "v-0f00"
    }
  }
}
```

On it, re-read the strategy (`GetStrategy` with `strategyId`) and refresh what
shows its code and flow.

## Migration

None: the field is new and optional. Clients that ignore it keep working.
