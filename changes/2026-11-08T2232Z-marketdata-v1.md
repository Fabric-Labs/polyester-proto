## What and why

Historical heatmap pages reconstruct their own starting book, including quiet
windows. Best bid, best ask and mid retain raw prices when available; older
historical buckets without recorded raw prices use reconstructed price bins.
Replayable history begins at the oldest available snapshot, so older update
buckets without an anchor are omitted.

## How clients use it

Apply `chain.deltas` oldest-first over `chain.base_keyframe`. Continue older
pages with `next_page_token` and the same filters; stop when the token is empty.
A window entirely before replayable history returns an empty chain.

```http
POST /marketdata.v1.HeatmapService/GetOrderbookHeatmap
Content-Type: application/json

{
  "symbolId": 1,
  "interval": "INTERVAL_1S",
  "depth": "DEPTH_50",
  "quantityMode": "CLOSE",
  "limit": 30,
  "timeRange": {
    "startTime": "2026-11-06T15:58:00Z",
    "endTime": "2026-11-06T16:00:00Z"
  }
}
```

## Migration

None: request and response fields are unchanged. Historical pages gain complete
starting state and pagination stops at the end of replayable history.
