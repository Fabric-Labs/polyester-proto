## What and why

`ExplainStrategy` is now implemented. It used to answer `UNIMPLEMENTED`. It
returns a version's review summary: what a user approves when deploying it.
The summary is computed from the version's check, its behaviour examples
and its backtests each time it is called, and nothing is stored.

- `money_card` and `settings` are the version's money rules and settings
  form.
- `scenarios` lists each behaviour example in manifest order with its last
  result. Each example is `NOT_RUN` until the examples have been run.
- `backtest` is the latest eligible completed backtest with the default
  settings: the caller's own, finished and within retention. Its comment in
  the contract now says so. At the same moment, `ExplainStrategy` and a new
  deploy proposal for the same version and settings agree. A stored proposal
  keeps the summary it was made with.
- When there is no backtest, `backtest_absent_reason` says why, in this
  order:
  - The bot can't be backtested on candles. This uses the words of its
    `NotBacktestableReason`, for example "It reacts to trades or to quotes,
    which candles do not carry." It applies even when an older backtest
    completed.
  - "not backtested with the default settings": the version has completed
    backtests, but only with other settings, or a setting has no default.
  - "no completed backtest available": none is available, including one
    past retention.
- Without a backtest, `warnings` states the same text as
  `backtest_absent_reason`. With one, `warnings` has "the backtest ran N
  times" when more than one completed backtest of this version with the
  default settings is available. Queued and failed requests don't count.
- `limitations` lists "stopping the bot does not sell its holdings".

## How clients use it

Call it with one of the caller's versions. An API key needs
`READ_STRATEGIES` and must be scoped to the main account. There is no REST
route; it's a ConnectRPC call.

```http
POST https://<api-host>/strategies.v1.StrategiesService/ExplainStrategy
Content-Type: application/json

{"versionId": "sha256:2669df62…"}
```

```json
{
  "versionId": "sha256:2669df62…",
  "moneyCard": {"maxOrder": {"asset": "USDT", "amount": "100"}, "markets": ["BTC-USDT"]},
  "settings": [{"name": "budget", "kind": "quote", "asset": "USDT", "defaultValue": "100"}],
  "scenarios": [{"name": "Buys every Monday", "outcome": "PASSED"}],
  "backtestAbsentReason": "no completed backtest available",
  "warnings": ["no completed backtest available"],
  "limitations": ["stopping the bot does not sell its holdings"]
}
```

Errors:
- `NOT_FOUND` with `VERSION_NOT_FOUND` for a version the caller doesn't
  hold, or one past its expiry that no strategy, proposal or bot keeps.
- `FAILED_PRECONDITION` with `VERSION_INVALID` for a version that didn't
  validate.
- `UNAVAILABLE` with `SERVICE_UNAVAILABLE`: retry.
- `INVALID_ARGUMENT` for a malformed request.
- `PERMISSION_DENIED` with `AUTH_API_KEY_ACCESS_DENIED` for an API key
  without `READ_STRATEGIES`, or one scoped to a subaccount.

## Migration

None. The call existed in the contract and answered `UNIMPLEMENTED`; no
message or field changed.
