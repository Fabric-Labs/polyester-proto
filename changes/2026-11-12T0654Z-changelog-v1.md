## What and why

The changelog is moving to one post per backend release, for example
`v0.92.9`. A release post has the same slug and content in every
environment. Each environment's changelog also groups releases by the
deployment that brought them, and each group has a stable, shareable slug,
for example `testnet-v0.92.9`.

Additions:

- Enums `Environment` (`DEVNET`, `TESTNET`, `MAINNET`) and
  `ChangeAvailability` (`AHEAD`, `PENDING`, `UNAVAILABLE`).
- `PostSummary.release_version` (14), `PostSummary.environments` (15,
  `EnvironmentStatus` per environment) and
  `PostSummary.deployment_group_slug` (16). They are set on release posts
  only.
- `Change.environment_exceptions` (10, `ChangeException`): the environments
  where a change differs from its release, for example a change that is
  already available on Testnet before its release reaches Testnet.
- RPCs `ListDeploymentGroups` and `GetDeploymentGroup`, with
  `DeploymentGroupSummary`, `DeploymentGroup`, `DeploymentGroupPost`,
  `DeploymentGroupAttention` and `DeploymentGroupHighlight`.

Until release posts are switched on, no post carries the new fields, the
group list is empty, and every group answers not found.

## How clients use it

List the deployment groups of this environment, newest first, then read
one:

```bash
curl -sS 'https://<api-host>/v1/changelog/deployment-groups?limit=20'
curl -sS 'https://<api-host>/v1/changelog/deployment-groups/testnet-v0.92.9'
```

The same calls over ConnectRPC are
`/changelog.v1.ChangelogService/ListDeploymentGroups` with
`{"limit": 20}` and `/changelog.v1.ChangelogService/GetDeploymentGroup`
with `{"slug": "testnet-v0.92.9"}`.

`limit` defaults to 20, and the maximum is 100. `page_token` is an
opaque, exclusive, keyset-backed cursor bound to deployment time and slug.
`next_page_token` is empty on the last page. A group lists every release it
brought (`versions`, ascending) and the published release posts among them
(`posts`). The detail adds the changes that need attention (breaking or
action required) and the highlights of those posts.

A release post's `environments` changes when its release goes live
somewhere, and `revision` does not change when that happens. Compare the
whole summary, or the response entity tag, to notice it.

## Migration

None. Every addition is optional, and posts that do not announce a
release are unchanged.
