## What and why

A trigger that a halted market refuses now reads its failure reason as
`TRIGGER_FAILURE_REASON_MARKET_HALTED` (8). Before, such a trigger ended
`STATUS_FAILED` with the unnamed `failure_reason` 212, which no client could
label, so users saw a failed take-profit or stop-loss with no reason.

The reason is the same on the trigger, on its `EVENT_FAILED` event, and on a
refused fire's `EVENT_FIRE_REFUSED` event, in `GetTrigger`, `ListTriggers` and
`ListTriggerEvents` and on the private WebSocket trigger channels alike. The
attached take-profit, stop-loss and trailing-stop legs of an order refused
this way end the same way. No message, field or enum value changes: 8 is an
existing value.

## How clients use it

Read the trigger or its events as before; no request changes.

```bash
# Authenticate as for any private read (omitted here).
curl -sS https://<api-host>/triggers.v1.TriggersService/GetTrigger \
  -H 'Content-Type: application/json' -d '{"trigger_id": "1234567890123456789"}'
# A trigger the halted market refused:
#   "status": "STATUS_FAILED",
#   "failureReason": "TRIGGER_FAILURE_REASON_MARKET_HALTED"
curl -sS 'https://<api-host>/v1/triggers/<base58-trigger-id>/events'
# REST drops the enum prefix: "failureReason": "MARKET_HALTED"
```

ConnectRPC JSON carries the trigger ID as the decimal string of its `fixed64`;
REST paths take the base58 public ID instead.

## Migration

None for clients that already label `TRIGGER_FAILURE_REASON_MARKET_HALTED`.
A client that mapped the unnamed failure reason 212 to "market halted" can
drop that mapping: no trigger reads 212 for a halt any more.
