## What and why

A stored strategy version now says why it is invalid. Until now, reading it
back gave only `valid: false`; the errors and warnings were in the save's
answer and nowhere else.

- **`GetStrategyVersionResponse.validation`** (new field, 10) is the version's
  `VersionValidation`, as it was stored, the same message `SaveDraftVersion`
  answers:
  - the errors and warnings, each with its place in the code or manifest, its
    rule, message and hint, at most 50 of each;
  - for a valid version, the money card, the settings form and the flow.
- **`GetStrategyResponse.head`** is a `GetStrategyVersionResponse`, so the
  current draft carries it too.
- Reading never checks the version again: a version never changes, so neither
  does its result. The existing `valid`, `settings_form` and `flow` fields stay
  as they are.
- `validation` is absent for a version stored without its check result; read
  `valid` for such a version.
- An API key reads `validation` with `READ_STRATEGIES`, like the rest of the
  version.

## How clients use it

Read a draft and show why it is invalid:

```http
POST /strategies.v1.StrategiesService/GetStrategy
Content-Type: application/json
Connect-Protocol-Version: 1

{"strategyId": "1234"}
```

```json
{
  "strategy": {"strategyId": "1234", "name": "Weekly DCA", "revision": "2", "valid": false},
  "head": {
    "versionId": "sha256:79b6…",
    "valid": false,
    "validation": {
      "versionId": "sha256:79b6…",
      "runtimeVersion": "2026-12",
      "errors": [
        {"line": 4, "column": 5, "rule": "UNKNOWN_CALL", "message": "…", "hint": "…"}
      ]
    }
  }
}
```

`GetStrategyVersion` with `{"versionId": "sha256:79b6…"}` answers the same
`validation` for any stored version of the caller.

## Migration

None: the field is new, and every existing field is unchanged.
