## What and why

`GetInternalTransfer` reads an accepted internal transfer by its request ID or transfer ID and returns both identifiers plus the authoritative `flowId`. `CreateInternalTransfer` also returns `flowId`. Clients can reconcile transfers without matching amounts or timestamps or resubmitting a transfer.

## How clients use it

Use a JWT session for this read; API keys are not supported. Select exactly one identifier. Omit `subaccountId` for the authenticated root account, or supply an accessible source subaccount. Unknown, pending, and inaccessible transfers return NotFound. This read does not move money or require fresh MFA.

A newly granted delegate may briefly receive NotFound until the access mirror catches up.

```http
POST /transfer.v1.InternalTransferService/GetInternalTransfer
Content-Type: application/json
Authorization: Bearer <session>

{"transferId":"254811058965469215576143367742519946794"}
```

REST: `GET /v1/trading/internal-transfers?transferId=254811058965469215576143367742519946794`. Alternatively supply `requestId` in either request. REST uses encoded public IDs for `subaccountId`; ConnectRPC uses fixed64. `acceptedAtTsNs` is a decimal string of nanoseconds since epoch in REST and Connect JSON. This is one receipt, with no pagination.

Use the returned `flowId` with `chain.lifecycle.v1.LifecycleReadService.GetFlowById` (`GET /v1/chain/flows/{flowId}`). Its `observedSteps` entry with `step: SETTLEMENT` and `lifecycleSource: LEDGER` carries the same transfer ID in `milestoneTxRef`, linking back to both debit and credit ledger entries. The flow projection may become readable after the accepted receipt.

`idempotencyKey` deduplicates submissions within the source account; `requestId` identifies the intake receipt; `transferId` identifies the settled debit and credit pair; `flowId` identifies the lifecycle view. Optional ledger `linkId` is separate correlation data and is not an internal-transfer lookup key.

## Migration

None: the read and response field are additive. Regenerate SDKs to use the new method and field. Availability begins with the release containing this change.
