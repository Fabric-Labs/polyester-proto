## What and why

Internal transfer REST refusals now answer the uppercase codes of the
internal transfer error catalog, the codes ConnectRPC already carries in
`transfer.v1.ErrorDetail`. Some answered lowercase names that are not
catalog codes.

| Refusal | Before | Now |
| --- | --- | --- |
| A lookup without exactly one of `requestId` or `transferId`, a body that is not JSON, or another malformed request | `400` `invalid_request` | `400` `INVALID_REQUEST` |
| A request body that cannot be read, on REST or on an API-key ConnectRPC call | `503` `upstream_error` | `503` `SERVICE_UNAVAILABLE` |
| An unexpected server error writing the response | `500` `internal_error` | `500` `INTERNAL_ERROR` |

The statuses are unchanged, and the `title` now follows the code (for
example `Invalid Request`). The `type` URI follows the code too, so it changes
for the unreadable request body only:

- Internal transfer `type` upstream-error → service-unavailable:
  `https://polyester.dev/problems/upstream-error` →
  `https://polyester.dev/problems/service-unavailable`.

The `invalid-request` and `internal-error` types are unchanged.

## How clients use it

Branch on the uppercase `code`:

```text
GET /v1/trading/internal-transfers

400 application/problem+json
{"type":"https://polyester.dev/problems/invalid-request","title":"Invalid Request",
 "status":400,"detail":"validation error: identifier: exactly one field is required in oneof",
 "code":"INVALID_REQUEST"}
```

An API-key ConnectRPC call whose request body cannot be read, for example
`/transfer.v1.InternalTransferService/CreateInternalTransfer`, is refused
before its method runs, with the same answer as REST: still `503`, code
`upstream_error` → `SERVICE_UNAVAILABLE`, `type` upstream-error →
service-unavailable. Every other ConnectRPC error, and the
`transfer.v1.ErrorDetail` it carries, is unchanged.

## Migration

A client that matched `invalid_request`, `upstream_error` or `internal_error`
on these REST routes must match `INVALID_REQUEST`, `SERVICE_UNAVAILABLE` or
`INTERNAL_ERROR` instead. A client that matched the
`https://polyester.dev/problems/upstream-error` type must match
`https://polyester.dev/problems/service-unavailable`. Clients that branch on the catalog's codes need no
change.
