## What and why

`ledger.v1.TransferCode` gains `WITHDRAW_FAILED = 1075`. REST and the transfer
stream name it `withdraw_failed`.

It is the debit of a withdrawal that Zipper rejected or that failed to
execute: the funds that left the account for that withdrawal. A rejected
withdrawal refunds its net amount to the user's own wallet; the withdrawal
fee is not refunded. The account's balance drops by what left with the
withdrawal, and its transfer history shows that debit with this code.

A `WITHDRAW_FAILED` transfer is a debit (`is_debit` true) of the account the
withdrawal left. Its destination is a system account, and it carries no
`flow_id`: the withdrawal's flow stays failed. Track the withdrawal itself
through its flow.

## How clients use it

Transfer history and transfer streams can now return rows with this code.
`ListTransfers` accepts it as a filter:

```json
POST /ledger.read.v1.LedgerReadService/ListTransfers
{ "transferCode": "WITHDRAW_FAILED", "limit": 50 }
```

`GET /v1/transfers` returns such rows with `"transferCode": "withdraw_failed"`.
Show it as a failed withdrawal in transfer history, for example "Withdrawal
failed", next to the account's other debits.

## Migration

None: the enum value is new. Clients that map transfer codes to labels should
add it. Until they do, generated enums show the numeric value 1075, or
`unspecified` where a client maps unknown codes to a default.
