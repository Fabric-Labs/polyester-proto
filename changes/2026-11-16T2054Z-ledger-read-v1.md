## What and why

`StatementExportService` gains `GetStatementExportDownloadUrl`, REST
`GET /v1/statements/exports/{exportId}/download-url`. It returns a URL of a
`READY` statement file that is valid for 60 seconds from signing and needs no credentials,
so a browser can save the file straight to disk instead of a web app reading
it into memory first. The download saves the file as
`statement-<exportId>.csv`.

The file download's `?redirect=true` is removed:
`GET /v1/statements/exports/{exportId}/file` now always returns the file. A
client that cannot send credentials with the download uses the new method
instead.

The service's documentation now also states the file download's answers
before the file is ready and after a failure, the error body, who may
download an export, and the 366-day period limit of `CreateStatementExport`.

## How clients use it

When an export is `READY`, ask for a URL right before downloading, then hand
it to the browser:

```http
GET https://<api-host>/v1/statements/exports/{exportId}/download-url
```

```json
{"url": "https://…", "expiresAt": "2026-11-16T21:00:00Z", "filename": "statement-<exportId>.csv"}
```

- ConnectRPC: `POST /ledger.read.v1.StatementExportService/GetStatementExportDownloadUrl`
  with `{"exportId": "<exportId>"}`. Session tokens and API keys with the
  `READ_STATEMENTS` policy action may call it, with the same access as the
  file download.
- `url` works until `expiresAt`, the exact end of its signature: 60 seconds
  measured from signing, which happens while the call is answered, or the
  file's own expiry if sooner. Each call returns a new URL. Anyone holding it
  can download the file until then, so do not log, store or share it.
- Before the file is `READY` the method answers `FAILED_PRECONDITION` with
  `STATEMENT_EXPORT_NOT_READY` (REST `409`); after a failure,
  `STATEMENT_EXPORT_FAILED` (`409`); once expired, or with less than 5 seconds
  left on the file, `STATEMENT_EXPORT_EXPIRED` (`410`).

## Migration

1. Replace `GET /v1/statements/exports/{exportId}/file?redirect=true` with a
   call to `GetStatementExportDownloadUrl`, and download from its `url`.
2. Clients that download with credentials keep using
   `GET /v1/statements/exports/{exportId}/file`, without `redirect`.
