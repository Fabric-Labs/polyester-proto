## What and why

Bots can now read each market's trading rules, so they can size and price
orders the exchange accepts instead of learning from a refusal.

- **The bot API** (`GetStrategyReference`, the reference text) documents
  **`bot.market(market)`**: the market's `tick_size`, `step_size`, `min_qty`
  and `min_notional` as exact decimals, with `base` and `quote`, and
  `round_price(price, side)` and `round_qty(qty)`, which round exactly as
  every order is rounded (a buy's price down to the tick, a sell's up, a
  quantity down to the step). `base` and `quote` are asset codes, such as
  `BTC` and `USDT`. Live trading, behaviour examples and backtests read the
  rules from the same source, at different times: a running bot keeps the
  rules read when it started, and a backtest or behaviour-example run reads
  the current ones when it runs.
- **The manifest schema** (`GetStrategyReferenceResponse.manifest_schema`)
  accepts **`observe.markets`** in a behaviour example: a market's trading
  rules, each key optional, replacing the exchange's for that example and
  the examples continuing it.
- **`RunScenarios`** runs a version's examples on each market's trading rules
  as the exchange sets them when the version first runs, and the stored
  result keeps them: a version always gets the same result, and a new
  version runs on the rules current then. A version with a market the
  exchange doesn't list is `FAILED_PRECONDITION` `VERSION_INVALID`.

## How clients use it

A behaviour example that tests a bot against a coarser tick and a higher
minimum, in the version's manifest:

```json
{"name": "coarse market", "at": "2026-11-23T09:00:00Z",
 "event": {"type": "timer"},
 "observe": {"markets": {"BTC/USDT": {"tick_size": "5", "min_notional": "100"}}},
 "expect": [{"buy": "BTC/USDT", "qty": "0.12345", "limit": "80000"}]}
```

```http
POST /strategies.v1.StrategiesService/RunScenarios
{"versionId": "sha256:..."}
```

- `tick_size` and `step_size` are positive decimal strings; `min_qty` and
  `min_notional` are decimal strings of zero or more. A key left out keeps
  the exchange's value.
- In bot code, `bot.market("BTC/USDT").round_qty(qty)` returns 0 when the
  quantity rounds to nothing, and an order below `min_qty` or `min_notional`
  is refused.

## Migration

None: no message or field changes. Existing manifests, bots and stored
behaviour-example results keep working unchanged.
