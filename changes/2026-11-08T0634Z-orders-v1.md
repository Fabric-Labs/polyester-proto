## What and why

`ERROR_CODE_ATTACHED_RISK_NOT_SUPPORTED` (value 82) now has one more cause.
The exchange already returns it, and its documented description now names
it: a modify that adds take-profit, stop-loss or trailing-stop legs to an
order that a triggered take-profit, stop-loss or trailing-stop leg placed.
Such an order can't carry legs of its own. Nothing changes on the order.

Only the description changes. The value, the name, the transport mapping
(ConnectRPC `unimplemented`, REST status 501) and the trading WebSocket's
`RejectCode` `ATTACHED_RISK_NOT_SUPPORTED` (82) stay the same. The
WebSocket's SBE schema keeps version 36; only the value's description text
changes.

## How clients use it

A modify whose `newAttachedRisk` names a leg, sent for an order whose
`origin` scope is `ATTACHED_RISK`, is refused. Over ConnectRPC:

```http
POST https://<api-host>/orders.v1.OrdersService/ModifyOrder
Content-Type: application/json

{"orderId":"<exit order id>","symbolId":1,"requestId":"legs-1","newAttachedRisk":{"takeProfit":{"triggerPriceTicks":"500000000","child":{"marketIoc":{}}}}}
```

`symbolId` is the market the exit order trades on, `1` in this example; it is
required on every modify. The answer is ConnectRPC `unimplemented` with
`ERROR_CODE_ATTACHED_RISK_NOT_SUPPORTED`.

Over REST, the same modify is:

```http
POST https://<api-host>/v1/orders/modify
Content-Type: application/json

{"symbol":"BTC-USDT","orderId":"<exit order id>","requestId":"legs-1","newAttachedRisk":{"oco":false,"takeProfit":{"triggerPrice":"50000","child":{"marketIoc":{}}}}}
```

`symbol` is the exit order's market. The answer is HTTP 501 with an
`application/problem+json` body whose `code` is `ATTACHED_RISK_NOT_SUPPORTED`
and whose `detail` gives the reason.

A batch replace sends the same patch per item, in REST
`POST /v1/orders/replace-batch` or ConnectRPC
`/orders.v1.OrdersService/BatchReplaceOrders`:

```http
POST https://<api-host>/v1/orders/replace-batch
Content-Type: application/json

{"symbol":"BTC-USDT","requestId":"legs-batch-1","items":[{"orderId":"<exit order id>","newAttachedRisk":{"oco":false,"takeProfit":{"triggerPrice":"50000","child":{"marketIoc":{}}}}}]}
```

The batch itself is answered with HTTP 200. That item is counted in
`rejectedCount`, and its result has `code` `ATTACHED_RISK_NOT_SUPPORTED`.
The other items are judged on their own.

On the trading WebSocket's protobuf protocol, a `modifyOrder` frame with the
same request is answered by a `CommandReject` whose `code` is
`ATTACHED_RISK_NOT_SUPPORTED`, with the same `detail`. The SBE protocol's
`ModifyOrder` carries no attached legs, so it never meets this case. Its
`RejectCode` `ATTACHED_RISK_NOT_SUPPORTED` (82) has the updated description.

In every case the order and its funds are unchanged. A modify that only
changes the order's price or quantity is still accepted.

## Migration

None: no field, value or shape changes. A client that shows the error's
description, or lets users add legs to any open order, should not offer
legs on an order whose `origin` scope is `ATTACHED_RISK`.
