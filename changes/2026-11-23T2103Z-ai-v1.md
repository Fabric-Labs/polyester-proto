## What and why

`ListMessagesResponse` gains `subject` (field 4): what the conversation is
about, the same value as `Conversation.subject`. A conversation's subject is
fixed when it starts, so every page of `ListMessages` carries the same value,
and it is omitted for a general conversation.

A client that opens a conversation by its ID calls `ListMessages` anyway. It
now learns from that call whether the conversation is about one of the
caller's strategies, for example to hide an account picker, without paging
through `ListConversations` to find the conversation.

## How clients use it

ConnectRPC, JSON over POST:

```bash
curl -sS https://<api-host>/ai.v1.AssistantService/ListMessages \
  -H 'Authorization: Bearer <session-token>' \
  -H 'Content-Type: application/json' \
  -d '{"conversationId": "1535956427583482916", "limit": 50}'
```

A strategy-bound conversation answers with its subject on every page,
alongside `lastAccount`:

```json
{
  "messages": [],
  "nextPageToken": "",
  "subject": { "strategy": { "strategyId": "4223" } }
}
```

A general conversation's response has no `subject`. Paging is unchanged:
newest first, default 50, maximum 200, `next_page_token` empty on the last
page.

## Migration

None: the field is new and optional. A client that read the subject from
`ListConversations` may read it from `ListMessages` instead.
