## What and why

The documentation of `ModifyTriggerRequest.max_slippage` said a max-slippage
cap can be changed for any stop-loss or take-profit with a market child. That
holds only for a standalone stop-loss or take-profit created with
`CreateTrigger`, and for any trailing stop.

A take-profit or stop-loss attached to an order (`TakeProfitPolicy` or
`StopLossPolicy` with a `RiskMarketIoc` child), and either leg of an OCO
created with `CreateOco`, takes no cap: `RiskMarketIoc` has no cap field, and
its market child always uses the pair's default market slippage for its side,
or 200 basis points if no positive default is configured. `ModifyTrigger` with
`max_slippage_ticks` or `max_slippage_bps` on such a leg is rejected with
`ERROR_CODE_TRIGGER_NOT_MODIFIABLE` and leaves the leg unchanged, also when
the same request changes the trigger price. Its trigger price alone remains
modifiable.

The comments on `ModifyTriggerRequest.max_slippage` and `RiskMarketIoc` now
say so. Behavior, messages and wire format are unchanged.

## How clients use it

Change an attached or OCO leg's trigger price without a cap. Both calls are
authenticated with a session token or an API key.

ConnectRPC: `triggerId` is the trigger's numeric ID as a decimal string,
`symbolId` the pair's numeric ID, and `triggerPriceTicks` the price in quote
units scaled by 1e9 (79000 here):

```bash
curl -sS https://<api-host>/triggers.v1.TriggersService/ModifyTrigger \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer <token>' \
  -d '{"triggerId": "<trigger-id>", "symbolId": 1, "triggerPriceTicks": "79000000000000"}'
```

REST: the base58 trigger ID goes in the path, the pair as `symbol`, and the
price as a decimal string `triggerPrice`:

```bash
curl -sS -X PUT https://<api-host>/v1/triggers/<base58-trigger-id> \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer <token>' \
  -d '{"symbol": "BTC-USDT", "triggerPrice": "79000"}'
```

Adding a cap to either request for an attached or OCO leg
(`"maxSlippageBps": 100`, or `maxSlippageTicks`, in either API) is rejected:
ConnectRPC answers InvalidArgument with `ERROR_CODE_TRIGGER_NOT_MODIFIABLE`,
REST answers HTTP 400 with code `TRIGGER_NOT_MODIFIABLE`. On a standalone stop-loss or take-profit with a market child, and
on a trailing stop, the cap stays modifiable as before.

## Migration

None: documentation only. A client that sends a cap patch to an attached or
OCO leg already receives `ERROR_CODE_TRIGGER_NOT_MODIFIABLE`; send the trigger
price alone instead.
