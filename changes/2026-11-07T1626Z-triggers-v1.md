## What and why

No message, field, enum value or RPC changes. Two documented behaviours
change.

- **Cancel Trigger of an ended trigger.** A trigger that has ended
  (completed, canceled or failed) answers a cancel with
  `ERROR_CODE_TRIGGER_STATUS_INVALID` (HTTP 400) for at least 60 s after it
  ends; after that it may answer `ERROR_CODE_TRIGGER_NOT_FOUND` (404). That
  includes a repeat of a cancel that succeeded. Before, a repeat cancel of
  a canceled trigger returned the canceled trigger again (200) for about a
  minute. Pause, Resume and Modify of an ended trigger answer the same
  way. That
  includes an ended ladder or TWAP, which used to answer
  `ERROR_CODE_TRIGGER_NOT_MODIFIABLE`; a running ladder or TWAP still
  answers `ERROR_CODE_TRIGGER_NOT_MODIFIABLE`, since it supports only
  cancel.
  Within that minute, `ERROR_CODE_TRIGGER_NOT_FOUND` means only that the
  ID names none of the caller's triggers; after it, it can also name a
  trigger that has ended, which Get Trigger still returns. The cancel's
  error message says the trigger has already ended.
- **Ladder trigger events.** A ladder level that the order book rejects
  when it arrives (for example a post-only level that would cross,
  `TRIGGER_FAILURE_REASON_POST_ONLY_CROSS`) is now reported as
  `EVENT_FIRE_REFUSED`, while the ladder keeps working its other levels.
  The event's `child_seq` names the level, `fire_refusal_reason` says why
  and `fire_price_ticks` is the level's price. It follows that level's
  `EVENT_FIRED`, which carries the rejected child order, while other
  levels are still open. A ladder fails (`EVENT_FAILED`) only when every
  level was rejected; the SDK hints say how a ladder ends when its last
  open level is rejected.

## How clients use it

Cancel a trigger, and treat `TRIGGER_STATUS_INVALID` as already done:

```http
DELETE https://<api-host>/v1/triggers/59VD7Lar
```

```http
POST https://<api-host>/triggers.v1.TriggersService/CancelTrigger
Content-Type: application/json

{"triggerId":"9155001234567"}
```

A cancel of an ended trigger answers:

```json
{"code":"TRIGGER_STATUS_INVALID","detail":"Trigger has already ended (completed, canceled or failed); there is nothing left to cancel."}
```

Read the trigger (`GET /v1/triggers/{trigger_id}`) to see how it ended.
List a ladder's events (`GET /v1/triggers/{trigger_id}/events`) to see
each rejected level as `EVENT_FIRE_REFUSED` with `fireRefusalReason`.

## Migration

- A client that retries a cancel must accept `TRIGGER_STATUS_INVALID` as
  success-equivalent, where it used to see 200 with the canceled trigger.
- A client that treated `TRIGGER_NOT_FOUND` after a cancel as "already
  gone" should treat `TRIGGER_STATUS_INVALID` the same way, and keep
  treating `TRIGGER_NOT_FOUND` so for a trigger it knows it created: more
  than 60 s after the end it may still get that.
- A client that reads `TRIGGER_NOT_MODIFIABLE` from Modify, Pause or
  Resume of a ladder or TWAP sees `TRIGGER_STATUS_INVALID` once the
  ladder or TWAP has ended.
- A client that counts a ladder's placed levels from its events should
  not count a level whose `EVENT_FIRED` is followed by an
  `EVENT_FIRE_REFUSED` of the same `child_seq`.
