## What and why

Comment-only change: the descriptions of `TriggerIntent.fee_asset`,
`OrderIntent.fee_asset`, `FeeAsset.BASE` and
`ERROR_CODE_FEE_ASSET_NOT_ALLOWED` now state the fee-asset rule the API
already enforces. No field, type, default or behavior changed.

The rule, for orders and for every trigger strategy (stop-loss, take-profit,
trailing stop, TWAP and ladder):

- The fee asset defaults to QUOTE when it is not set.
- A SELL must use QUOTE.
- A BUY may select BASE only on a pair whose `allow_buy_fee_from_base` is
  true in `marketdata.v1.MarketDataService/GetSpotConfig`.

Any other combination is refused with `ERROR_CODE_FEE_ASSET_NOT_ALLOWED`
(`INVALID_ARGUMENT`). A trigger is refused at create, so it is never
created. An OCO carries no fee asset: both of its legs always pay in quote.

## How clients use it

Read the pair's `allow_buy_fee_from_base` from `GetSpotConfig` before
selecting BASE on a BUY:

```http
POST /marketdata.v1.MarketDataService/GetSpotConfig
Content-Type: application/json

{}
```

Then send `"feeAsset": "BASE"` only on a BUY trigger or order for a pair
whose `allowBuyFeeFromBase` is `true`; otherwise omit `feeAsset` or send
`"QUOTE"`. A refused request answers `INVALID_ARGUMENT` with an
`ErrorDetail` of code `ERROR_CODE_FEE_ASSET_NOT_ALLOWED`. A SELL trigger
refused for it also carries a violation with `field_path`
`trigger.fee_asset` and `rule_id` `sell_quote_only`.

## Migration

None: the contract is unchanged; only its descriptions are more complete.
