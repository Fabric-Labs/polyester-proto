## What and why

The realtime token endpoints now refuse a request the same way every other
auth REST endpoint does. `GET /v1/rt/subscribe` answers a missing,
unsupported or `:json` channel with `400 application/problem+json` and
`code` `AUTH_INVALID_REQUEST`. Both `GET /v1/rt/token` and
`GET /v1/rt/subscribe` answer a token that cannot be issued with `500`
`AUTH_INTERNAL_ERROR`. Before, these answered `text/plain` with no `code`. A signed request whose body cannot be read is answered
`502 application/problem+json` `AUTH_UPSTREAM_ERROR` instead of plain text.

The policy endpoints' refusals of a malformed `policy_id`, `subaccount_id` or
`subaccountId` now name the parameter alone, for example `invalid policy_id`.

## How clients use it

Nothing changes for well-formed requests. A malformed one returns:

```http
GET /v1/rt/subscribe

HTTP/1.1 400 Bad Request
Content-Type: application/problem+json

{"type":"https://polyester.dev/problems/auth-invalid-request","title":"Bad Request","status":400,"detail":"missing channel","code":"AUTH_INVALID_REQUEST"}
```

## Migration

None: every status stays the same. Clients that read these refusals as plain
text can now read `code` and `detail` from the problem body.
