## What and why

The trading WebSocket can now arm, refresh and disarm the account's
cancel-all-after timer (dead-man switch), so a market maker keeps the timer
alive on its order-entry connection instead of a separate HTTP call. It is
the same timer as the Orders API's `CancelAllAfter`, with the same symbol and
side scope and the same timeout rule: 0 disarms, 10 to 120 seconds arms or
refreshes, and any other value is refused with
`CANCEL_ALL_AFTER_TIMEOUT_INVALID` (222). On expiry it cancels the account's
open orders in scope, including orders that triggers placed, which end
`CANCELED` with cancel reason `CANCEL_ALL_AFTER`; it cancels no trigger. The
timer belongs to the account, not to the connection: closing the connection
neither disarms nor fires it.

- **Protobuf** (`tradews.v1`): `ClientFrame.cancel_all_after = 18` carries
  `orders.v1.CancelAllAfterRequest`, and `AckResponse.cancel_all_after = 8`
  carries `orders.v1.CancelAllAfterResponse`. `request_id` is required, as on
  the Orders API, and `subaccount_id` must be omitted.
- **SBE** (`tradews.xml`, schema 7): the new request `CancelAllAfter`
  (template 10) and its answer `CancelAllAfterAck` (template 30), the enum
  `CancelAllAfterStatus`, `CommandType` `CANCEL_ALL_AFTER = 10` and
  `RateLimitOperation` `CANCEL_ALL_AFTER = 8`. The schema version stays 36:
  no existing message changed, so every client built on version 36 keeps
  working. `semanticVersion` moves from 1.0.0 to 1.1.0 to mark the additions.

## How clients use it

Protobuf client frame, arming a 60-second timer on one pair's sells; send it
again every 15 to 30 seconds to refresh it, and with `timeout_sec` 0 to
disarm it:

```json
{
  "seq": "42",
  "correlationId": "caa-42",
  "cancelAllAfter": {
    "timeoutSec": 60,
    "symbolId": 1,
    "side": "SELL",
    "requestId": "caa-42"
  }
}
```

The answer is `ServerFrame.ack.cancel_all_after`: `status` `ARMED` or
`DISABLED`, `effective_timeout_sec`, `expires_at_ts_ns`, `ts_ns` (when the
request applied) and `effective_scope`, absent when disabled.

SBE `CancelAllAfter` (template 10): `seq` (uint64), `correlationId` (uint64),
`timeoutSec` (uint32), `symbolId` (uint32, 0 for every pair), `side` (uint8,
0 for both sides). It is answered by `CancelAllAfterAck` (template 30) with
`seq`, `correlationId`, `status`, `timeoutSec`, `expiresAtTsNs`, `symbolId`,
`side` and `tsNs`, or by a `CommandReject`. Each request counts against the
cancellation rate limit.

## Migration

None: the command is new, and existing protobuf and SBE version 36 clients
are unaffected.
