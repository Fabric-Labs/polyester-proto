## What and why

The changelog can now name one more product area:

- `Surface` gains `ASSISTANT`, the AI assistant: chats, approvals, memories and
  preferences. Changes to the assistant carry it in `Change.surfaces`, and a
  post section that covers the assistant carries it in `Section.surface`.
- `ListChangesRequest.surfaces` accepts up to 11 values, one per surface.

Clients can label assistant changes and sections, and filter changes to the
assistant.

## How clients use it

```bash
curl -sS https://<api-host>/changelog.v1.ChangelogService/ListChanges \
  -H 'Content-Type: application/json' -d '{"surfaces": ["ASSISTANT"]}'
# {"changes": [{"title": "...", "surfaces": ["ASSISTANT"], ...}], ...}

curl -sS https://<api-host>/changelog.v1.ChangelogService/GetPost \
  -H 'Content-Type: application/json' -d '{"slug": "2026-11-18"}'
# {"post": {"summary": {...}, "sections": [
#   {"heading": "AI assistant", "surface": "ASSISTANT", "changes": [...]}]}}
```

REST:

```bash
curl -sS 'https://<api-host>/v1/changelog/changes?surfaces=ASSISTANT'
curl -sS 'https://<api-host>/v1/changelog/posts/2026-11-18'
```

## Migration

None: the value is additive. Clients must keep tolerating enum values they do
not know, in `Change.surfaces` and in `Section.surface`: decode them as
unknown and show them without a product-area label rather than failing.
