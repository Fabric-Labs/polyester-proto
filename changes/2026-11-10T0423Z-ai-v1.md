## What and why

**Availability:** devnet only. Not available on testnet yet; the service isn't deployed or routed there.

Approval cards and account views now carry, as typed fields, the facts that
until now appeared only in the approval's summary text. A client draws them
from the fields and no longer reads them out of the text. Each field is set
from the same exact action as the summary, so the two always agree.

- `ApprovalRequested.account_id` (`fixed64`): the trading account
  (subaccount) the action acts on, the one `SendMessageRequest.subaccount_id`
  named. A replayed run carries it too.
- `account_id` (`fixed64`) on every account view: `OrdersTable`,
  `TriggersTable`, `BalancesTable`, `DepositAddressCard`,
  `BalanceHistoryChart`, `EquityHistoryChart` and `TransfersTable`. A client
  can load live data for that exact account, also for a reloaded conversation.
- `TwapPreview.unfilled_slice_policy` (new enum `UnfilledSlicePolicy`,
  `CANCEL_BEFORE_NEXT` for limit slices) and
  `TwapPreview.first_slice_immediate`.
- `LadderPreview.time_in_force` (`orders.v1.TimeInForce`, `GTC`) and
  `LadderPreview.all_levels_at_once`.
- `StopOrderPreview.funds_reserved` and `TrailingStopPreview.funds_reserved`:
  the funds are reserved when the order is created, also when
  `OrderPreview.reserved_amount` is omitted.
- `PlaceOrdersPreview.total_values` (new message `QuoteValue`): the set's
  estimated value, one per quote asset.
- `TriggerChangePreview.direction` (`TriggerDirection`), the `reserve_change`
  oneof (`reserve_increase` or `reserve_release`) and `fires_on_resume`.
- `RelativePrice.rounding` (new enum `PriceRounding`: `DOWN`, `UP`) and
  `RelativePrice.tick_size`.
- `CancelOrdersPreview.live_triggers_kept_lower_bound`: `live_triggers_kept`
  counts only the triggers read, and more may stay active.
- `CancelTriggerPreview`, a new `ApprovalRequested.preview` member
  `cancel_trigger`: the trigger a single-trigger cancellation cancels, its
  progress, and `cancels_open_orders` for a TWAP or ladder, whose open orders
  are cancelled with it.

## How clients use it

Watch a run as before. The new fields arrive on the same `approvalRequested`
and `view` events:

```text
POST /ai.v1.AssistantService/WatchRun
{"runId": "6349022007070785130", "afterSeq": "0"}

{"event": {"seq": "4", "approvalRequested": {
  "approvalId": "8812301928372615",
  "accountId": "4105301236839741",
  "summary": "Cancel twap 7Kq…: buy 0.01 BTC on BTC-USDT, 1 of 60 slices done, 0 BTC filled so far; its open orders are cancelled with it, on trading account …",
  "cancelTrigger": {
    "triggerId": "4471983620157",
    "symbolId": 1,
    "symbol": "BTC-USDT",
    "type": "TWAP",
    "side": "BUY",
    "quantity": "0.01",
    "filledQuantity": "0",
    "slicesDone": 1,
    "sliceCount": 60,
    "cancelsOpenOrders": true
  }
}}}
```

- `account_id` is a public ID: a `fixed64`, a decimal string in JSON.
- A `false` boolean, a zero and an unspecified enum are omitted in JSON. In
  `CancelTriggerPreview`, the progress fields are `optional`: an explicit `0`
  (no slice done yet) is present.
- `reserve_increase` and `reserve_release` are exact decimal strings in the
  quote asset, fee reserve included. Neither is set when the change leaves
  the reserve as it is.
- `total_values` lists one value per quote asset in the order the assets first
  appear in `orders`, rounded to at most 2 decimals.

## Migration

None: every field, message, enum and oneof member is new. A client that ignores
them keeps working, and a client that does not recognize `cancel_trigger` shows
the summary and parameters only, as before.
