## What and why

The assistant's daily allowance is now counted in credits, and callers can
read it. A credit is a fixed amount of AI usage. Each VIP tier gives a number
of free credits per UTC day, shared by the main account and every subaccount;
they reset at 00:00 UTC and unused credits never carry over to the next day.
Messages answered on the caller's own OpenAI API key use no credits.

- New RPC `GetUsage`: today's free credits (by the caller's VIP tier), how
  many are used and left, when they reset, what pays for the caller's next
  messages (`FundingMode`: `CREDITS` or `OWN_KEY`) and the next VIP tier's
  free credits. Session tokens only; API keys are refused.
- New enum `FundingMode` and message `TierCredits`.
- `DAILY_LIMIT_REACHED` (unchanged value 7) now means the day's free credits
  are used up. `RunFailed.message` names the tier's free credits, when they
  reset, that they don't carry over, and how to get more: the next VIP tier
  and its free credits, the caller's own OpenAI API key, and buying credits
  later. `GetUsage` returns the same figures as fields.

## How clients use it

Read the credits, for example in the assistant's settings or next to the
chat box, and again after a `RunFailed` with `DAILY_LIMIT_REACHED`:

```json
POST /ai.v1.AssistantService/GetUsage
Authorization: Bearer <session token>
{}

{
  "fundingMode": "CREDITS",
  "vipTier": 2,
  "freeCredits": "750",
  "freeCreditsUsed": "120",
  "freeCreditsLeft": "630",
  "resetsAt": "2026-11-18T00:00:00Z",
  "nextTier": {"vipTier": 3, "dailyFreeCredits": "1000"}
}
```

- Whole credits. `freeCreditsUsed` is rounded down and may exceed
  `freeCredits`: an answer started with credits left always finishes.
- A message is answered while `freeCreditsLeft` is above 0, or on the
  caller's own OpenAI API key (`fundingMode` `OWN_KEY`), which uses none.
- `vipTier` is absent when the tier could not be read; VIP 0's free credits
  then apply. `nextTier` is absent at VIP 10 and when the tier is unknown.
- `resetsAt` is the next 00:00 UTC.
- Errors: `UNAUTHENTICATED`, `PERMISSION_DENIED` for an API key,
  `RESOURCE_EXHAUSTED` (`USAGE_LIMIT_REACHED`) and `UNAVAILABLE`.

## Migration

None. `GetUsage`, `FundingMode` and `TierCredits` are new, and
`DAILY_LIMIT_REACHED` keeps its value; only its message now speaks in
credits. Keep showing `RunFailed.message` as written.
