## What and why

Account statements now carry the lifecycle flow of each entry: the
`ledger.read.v1.LedgerReadService/ExportStatement` CSV, on ConnectRPC and on
`GET /v1/statements`, gains a last column `flow_id`. It holds the public flow
ID of a deposit, withdrawal or internal transfer, the same value ListTransfers
returns as `flowId` for the entry's legs, so a statement row can be matched to
the flow it belongs to. It is empty for entries outside a chain lifecycle
flow, such as trades.

## How clients use it

```http
GET /v1/statements?startTime=2026-10-01T00:00:00Z&endTime=2026-11-01T00:00:00Z
```

```csv
time,entry_id,type,account,asset,amount,fee,balance,link_id,flow_id
2026-10-02T14:03:11.000000Z,27419385013475392777,deposit,funding,USDT,100,0,100,,flow_8d1f2c
2026-10-03T08:12:45.123456Z,27419385013475392811,trade,trading,BTC,0.1,0,1.1,77,
```

- Every row of one entry carries the same `flow_id`.
- Paging, limits and permissions are unchanged.

## Migration

None: the column is appended after `link_id`, and the header row names every
column. Clients that read columns by header name need no change; clients that
require exactly nine columns per row must accept the tenth.
