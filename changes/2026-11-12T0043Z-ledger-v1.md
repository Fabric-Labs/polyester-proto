## What and why

The descriptions of two `ledger.v1.TransferCode` values now say what each
one records. Codes, names and labels are unchanged.

- `TRADING_WITHDRAW_REQUEST_FEE` (1065, REST `trading_withdraw_request_fee`)
  is the debit of a withdrawal from the Trading account that was rejected or
  failed to execute: the whole amount sent for the withdrawal, its request fee
  included. The withdrawal's other fees are not charged. It used to say it
  was only the request fee.
- `WITHDRAW_FAILED` (1075, REST `withdraw_failed`) is the same debit for a
  withdrawal from the Funding account. It used to read as covering every
  failed withdrawal.

For both, a rejected withdrawal refunds that amount less the request fee to
the account's own wallet, and its flow ends `STATE_REFUNDED`; a withdrawal
that failed to execute is not refunded, and its flow ends `STATE_FAILED`.

## How clients use it

Transfer history returns these rows as before:

```json
POST /ledger.read.v1.LedgerReadService/ListTransfers
{ "transferCode": "TRADING_WITHDRAW_REQUEST_FEE", "limit": 50 }
```

`GET /v1/transfers` returns them with `"transferCode":
"trading_withdraw_request_fee"` or `"withdraw_failed"`. Show either as the
debit of a failed withdrawal, for its whole amount, not as a fee.

## Migration

None: no value, name or label changes. Clients that label 1065 as a fee
should label it as a failed Trading withdrawal.
