## What and why

An attached trailing stop's refused slippage cap or activation price now
answers the code a standalone trailing stop answers for the same mistake,
and an OCO's refused quantity the code a standalone trigger's quantity
answers, on REST and ConnectRPC alike. The transport status and the field
violation are unchanged: ConnectRPC answers `INVALID_ARGUMENT` and REST
answers HTTP 400, or the refused preview or batch item carries the code.

`CreateOrder`, `PreviewOrder`, `BatchCreateOrders`, `ModifyOrder` and
`BatchReplaceOrders`, for `attached_risk.trailing_stop` and
`new_attached_risk.trailing_stop`:

| Field | Refused when | Code | Before |
| --- | --- | --- | --- |
| `max_slippage_ticks` | not positive | `ERROR_CODE_SLIPPAGE_TICKS_INVALID` | `ERROR_CODE_MAX_SLIPPAGE_INVALID` or `ERROR_CODE_VALIDATION_ERROR` |
| `max_slippage_bps` | not positive | `ERROR_CODE_SLIPPAGE_BPS_INVALID` | `ERROR_CODE_MAX_SLIPPAGE_INVALID` or `ERROR_CODE_VALIDATION_ERROR` |
| `max_slippage_bps` | above 10000 | `ERROR_CODE_MAX_SLIPPAGE_INVALID` | `ERROR_CODE_VALIDATION_ERROR` on preview, modify and batch replace |
| `activation_price_ticks` | negative | `ERROR_CODE_TRIGGER_ACTIVATION_PRICE_INVALID` | `ERROR_CODE_VALIDATION_ERROR` |

A cap of exactly 10000 basis points still answers
`ERROR_CODE_MAX_SLIPPAGE_INVALID`. On REST, a malformed or negative
`activationPrice` decimal of an attached trailing stop answers
`TRIGGER_ACTIVATION_PRICE_INVALID` instead of `BAD_PRICE`. The trading
WebSocket's protobuf `CreateOrder`, `ModifyOrder`, `BatchCreateOrders` and
`BatchReplaceOrders` frames refuse these values with the same codes.

`CreateOco` answers `ERROR_CODE_TRIGGER_QTY_INVALID` for a `qty_scaled`
that is not positive, instead of `ERROR_CODE_BAD_QTY`, and REST answers
`TRIGGER_QTY_INVALID` for a malformed or negative `qty` decimal. The trading
WebSocket's `CreateOco` answers the same code. An order's quantity keeps its
codes.

## How clients use it

An order whose attached trailing stop caps its exit at 0 ticks:

```http
POST /orders.v1.OrdersService/CreateOrder
Content-Type: application/json

{"order":{"symbolId":1,"side":"BUY","baseQtyScaled":"1000000","limitGtc":{"priceTicks":"70000000000000"},"attachedRisk":{"trailingStop":{"trailingDistanceBps":100,"maxSlippageTicks":"0"}}}}
```

answers `invalid_argument` with an `orders.v1.ErrorDetail` whose `code` is
`ERROR_CODE_SLIPPAGE_TICKS_INVALID` and whose violation names
`order.attached_risk.trailing_stop.max_slippage_ticks`. REST answers the
same request on `POST /v1/orders` with HTTP 400,
`"code":"SLIPPAGE_TICKS_INVALID"` and a violation on
`order.attachedRisk.trailingStop.maxSlippageTicks`.

An OCO of quantity 0:

```http
POST /triggers.v1.TriggersService/CreateOco
Content-Type: application/json

{"oco":{"symbolId":1,"side":"SELL","clientListId":"oco-1","qtyScaled":"0","takeProfit":{"triggerPriceTicks":"80000000000000","child":{"marketIoc":{}}},"stopLoss":{"triggerPriceTicks":"60000000000000","child":{"marketIoc":{}}}}}
```

answers `ERROR_CODE_TRIGGER_QTY_INVALID` with a violation on
`oco.qty_scaled`; REST `POST /v1/triggers/oco` answers
`"code":"TRIGGER_QTY_INVALID"` with a violation on `oco.qty`.

## Migration

1. A client that matched `ERROR_CODE_MAX_SLIPPAGE_INVALID` or
   `ERROR_CODE_VALIDATION_ERROR` for an attached trailing stop's cap that is
   not positive must match `ERROR_CODE_SLIPPAGE_TICKS_INVALID` or
   `ERROR_CODE_SLIPPAGE_BPS_INVALID`.
2. A client that matched `ERROR_CODE_VALIDATION_ERROR` (REST `BAD_PRICE`)
   for an attached trailing stop's negative activation price must match
   `ERROR_CODE_TRIGGER_ACTIVATION_PRICE_INVALID`.
3. A client that matched `ERROR_CODE_BAD_QTY` for an OCO's quantity must
   match `ERROR_CODE_TRIGGER_QTY_INVALID`.

Field violations, HTTP statuses and ConnectRPC status codes are unchanged.
