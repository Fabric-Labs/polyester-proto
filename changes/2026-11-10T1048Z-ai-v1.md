## What and why

Two RPCs on `ai.v1.AssistantService` let a signed-in user set optional limits on what they may approve from Telegram, and read them back:

- `GetTelegramApprovalLimits` returns the caller's `TelegramApprovalLimits`, plus the notional value approved from Telegram in the last 24 hours while a limit was set.
- `SetTelegramApprovalLimits` replaces the caller's limits.

`TelegramApprovalLimits` holds two optional limits, both in US dollars of notional value and both off unless set:

- `per_approval_usd`: the most one approval from Telegram may be worth;
- `daily_usd`: the most approvals from Telegram may total in any rolling 24 hours.

An approval from Telegram that would exceed a limit is refused, and the user can approve it in the Polyester app instead. Cancelling orders, pausing a trigger and rejecting are never limited.

**Availability:** devnet only. Not available on testnet yet; the service isn't deployed or routed there.

## How clients use it

Read the limits:

```http
POST /ai.v1.AssistantService/GetTelegramApprovalLimits
{}
```

```json
{ "limits": { "perApprovalUsd": "5000.00" }, "approvedLast24hUsd": "120.00" }
```

Set them. Each limit is a decimal string with at most 2 decimal places, and `"0"` allows none. A limit left out is turned off, so `{ "limits": {} }` turns both off.

```http
POST /ai.v1.AssistantService/SetTelegramApprovalLimits
{ "limits": { "perApprovalUsd": "5000", "dailyUsd": "20000" } }
```

```json
{ "limits": { "perApprovalUsd": "5000.00", "dailyUsd": "20000.00" } }
```

- Both RPCs require a session token.
- Both are rate limited like the other assistant reads and controls.
- A malformed amount is `INVALID_ARGUMENT`.

## Migration

None: the RPCs and messages are new.
