## What and why

The assistant can now cancel several triggers with one approval, for example
"cancel all my stop-losses on SOL-USDT". Before, it asked for one approval per
trigger. Its approval card now carries the whole set as typed values.

- **`CancelTriggersPreview`** (new message) is the exact set of live triggers an
  approval cancels together, in the order the user named them. Its `triggers`
  field repeats `CancelTriggerPreview`, the message a single-trigger cancel
  already uses: id, market, type, side, quantity, and trigger price or progress.
  Approving cancels exactly these triggers and no other. A trigger created after
  the approval is not cancelled under it.
- **`ApprovalRequested.preview.cancel_triggers`** (new oneof member 13) carries
  it. The other members are unchanged, and a single trigger still uses
  `cancel_trigger` (12).

## How clients use it

The approval arrives on the run's event stream as before. Draw the new member
when it is set:

```json
{
  "approvalRequested": {
    "approvalId": "4242",
    "summary": "Cancel 3 triggers on subaccount 5678: …",
    "parameters": [{ "label": "Cancel", "value": "3 triggers" }],
    "accountId": "5678",
    "cancelTriggers": {
      "triggers": [
        {
          "triggerId": "1001",
          "symbolId": 4,
          "symbol": "SOL-USDT",
          "type": "STOP_LOSS",
          "side": "SELL",
          "quantity": "0.15",
          "triggerPrice": "40"
        },
        {
          "triggerId": "1002",
          "symbolId": 4,
          "symbol": "SOL-USDT",
          "type": "STOP_LOSS",
          "side": "SELL",
          "quantity": "0.15",
          "triggerPrice": "41"
        }
      ]
    }
  }
}
```

Approve or reject it with `DecideApproval`, as for every other approval:

```http
POST /ai.v1.AssistantService/DecideApproval
Content-Type: application/json
Connect-Protocol-Version: 1

{"approvalId": "4242", "decision": "APPROVE"}
```

The run then reports each trigger's result in its answer: cancelled, already
ended before the cancel, or not cancelled, with the reason.

## Migration

None: the message and the oneof member are new. A client that does not
recognize the member shows the approval's `summary` and `parameters`, which
list every trigger, as `ApprovalRequested.preview` already documents.
