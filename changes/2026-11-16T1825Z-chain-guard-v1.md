## What and why

A signed API-key request to the guard signer whose body cannot be read now
answers the uppercase code `UPSTREAM_ERROR`, not `upstream_error`. The status,
title, detail and `type` URI are unchanged.

| Error | Before | Now |
| --- | --- | --- |
| A signed request whose body cannot be read | `503` `upstream_error` | `503` `UPSTREAM_ERROR` |

## How clients use it

Branch on the uppercase `code`:

```text
POST /chain.guard.v1.GuardSignerService/GetGuardSignerStatus

503 application/problem+json
{"type":"https://polyester.dev/problems/upstream-error","title":"Service Unavailable",
 "status":503,"detail":"request body could not be read","code":"UPSTREAM_ERROR"}
```

This refusal is answered on the ConnectRPC routes, by every `GuardSignerService`
method an API key calls. Every other ConnectRPC error is unchanged.

## Migration

A client that matched `upstream_error` must match `UPSTREAM_ERROR`
instead.
