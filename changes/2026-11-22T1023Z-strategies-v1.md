## What and why

The bot pages get a bot's recent activity and the time it last decided.

- **`ListBotLogs`** now answers. It reads a bot's recent activity, oldest
  first: the last 20 decisions of its current deployment, each with the
  lines its call wrote, and its last 20 errors. That window is what is kept:
  older entries are not kept anywhere, and an entry that left the window
  before it was read is not returned.
- **`ListBotLogsResponse.follow_token`** (new): set on the last page, it
  reads the entries written after the last one read, by sequence, in the
  same deployment's log.
- **`ListBotLogsResponse.deployed_again`** (new): the bot was deployed again
  after the deployment whose log the response read, so a new run started.
  Its new log is read by listing again without `pageToken`. It doesn't end
  the old log: late entries of the old deployment can still arrive, with no
  set time limit, and its `followToken` keeps reading them for as long as
  they are kept.
- **`BotLogEntry.sequence`** increases within the bot's current deployment.
  A bot deployed again starts a new log, whose sequences start low again. A
  decision comes first, then the lines its call wrote, then its error if the
  call failed. A decision line names the handler and the orders the call
  asked for, or that it asked for none; a failed call's line says so, and
  its error entry carries why.
- **`BotLogEntry.time`** is when the event behind the entry was observed. A
  decision's lines and its error have the decision's time, and two
  decisions can have the same time, for example two markets' candles of one
  minute: order entries by `sequence`, never by `time`.
- **`Bot.last_decision_at`** is now set on `ListBots` and `GetBot`: the time
  of the event behind the bot's latest decision, over all its deployments.
  It is omitted before the bot's first decision and lags the bot by up to
  about a minute.

## How clients use it

Read a bot's recent activity, then follow it:

```http
POST /strategies.v1.StrategiesService/ListBotLogs
{"botId": "1234", "limit": 100}

POST /strategies.v1.StrategiesService/ListBotLogs
{"botId": "1234", "startTime": "2026-11-22T09:30:00Z"}
```

- `limit` is 100 by default and at most 200; `pageToken` comes from the
  previous response's `nextPageToken`. The token is bound to the caller,
  `botId`, `startTime` and the deployment whose log the first page read:
  its pages keep reading that log even after the bot is deployed again.
- To see newer entries, call again with `pageToken` set to the last
  response's `followToken`: it returns only the entries after the last one
  read. Never follow with a later `startTime`: it filters by event time, and
  an entry written later can carry an earlier time.
- When a response has `deployedAgain`, start a new listing without
  `pageToken` for the new log. The old `followToken` stays usable for the old
  deployment's late entries; follow both if they matter.
- `startTime` is inclusive; unset reads from the oldest entry kept.
- The call needs `READ_STRATEGIES` (API keys) or `account:read` (connected
  apps), main account only, as the other bot reads.

## Migration

None: `follow_token` and `deployed_again` are new, and the RPC and every
other field already existed. `ListBotLogs` answered `UNIMPLEMENTED` and `Bot.last_decision_at` was
never set; clients that call them now get data.
