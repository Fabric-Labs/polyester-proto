## What and why

New transfers from Trading to Funding retain their lifecycle flow identifier in the first realtime transfer update. The identifier matches the same transfer returned by ListTransfers. Trading withdrawals also retain the correlation at settlement.

## How clients use it

Subscribe to `private:ledger:transfers:{accountId}` for JSON updates or `private:ledger:transfers:{accountId}:proto` for `ledger.read.v1.TransferRowBatch` protobuf updates. Use the subscribed account's public ID for `{accountId}`. No RPC or REST call is involved, and the subscription has no paging.

Read `flow_id` from each protobuf `TransferRow`, or `flowId` from each JSON event, to link to the transfer's lifecycle flow. Apply events in publication order and array order; an event with the same transfer ID, account and debit side replaces the earlier copy. Amounts are decimal strings in JSON and integer E18 quantities in protobuf; timestamps are microseconds. For example, a JSON publication includes:

```json
{"events":[{"transferId":"211655085759659829926748472328402807297","flowId":"flow_byAvWMBW5WG"}]}
```

## Migration

None. Existing clients already decode the flow identifier. The field is now populated for newly committed transfers without a refetch.
