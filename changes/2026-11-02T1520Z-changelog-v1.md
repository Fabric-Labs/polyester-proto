## What and why

`changelog.v1.ChangelogService` serves the public changelog of each
environment: the posts published for it and the changes each post announces.
Clients can show what changed in a release, and integrators can find every
breaking change or action they must take since a date without reading the
posts. The service is public and caller-independent: it needs no
authentication, and its responses can be cached (ConnectRPC GET).

It has three read-only methods:

- `ListPosts`: post summaries, newest first, with exact counts per category.
- `GetPost`: one complete post, its sections and their changes, by slug.
- `ListChanges`: changes across posts, filtered by category, surface,
  audience, `action_required`, a publication time window or one post.

## How clients use it

A post's slug is the date its coverage ends, `YYYY-MM-DD`, with `-2` (then
`-3`, and so on) appended when two posts end on the same day:
`2026-11-04`, `2026-11-04-2`.

ConnectRPC, JSON over POST (GET also works, as for every side-effect-free
method):

```bash
curl -sS https://<api-host>/changelog.v1.ChangelogService/ListPosts \
  -H 'Content-Type: application/json' -d '{"limit": 1}'
curl -sS https://<api-host>/changelog.v1.ChangelogService/GetPost \
  -H 'Content-Type: application/json' -d '{"slug": "2026-11-04"}'
# Every breaking change published since 2026-09-24, oldest first.
curl -sS https://<api-host>/changelog.v1.ChangelogService/ListChanges \
  -H 'Content-Type: application/json' \
  -d '{"categories": ["BREAKING_CHANGE"], "startTime": "2026-09-24T00:00:00Z", "sort": "SORT_ASC"}'
```

REST:

```bash
curl -sS 'https://<api-host>/v1/changelog/posts?limit=1'
curl -sS 'https://<api-host>/v1/changelog/posts/2026-11-04'
curl -sS 'https://<api-host>/v1/changelog/changes?categories=BREAKING_CHANGE&startTime=2026-09-24T00:00:00Z&sort=ASC'
```

Paging: `ListPosts` (default 20, max 100) and `ListChanges` (default 100,
max 500) return `next_page_token`, empty on the last page. Pass it back as
`page_token` with the same filters, time bounds and sort. `GetPost` returns the
whole post; for a post with hundreds of changes, page through
`ListChanges` with `post_slug` instead.

## Migration

None: the service is new.
