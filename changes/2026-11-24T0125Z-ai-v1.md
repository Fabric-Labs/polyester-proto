## What and why

The assistant now places two more kinds of spot order behind an approval card,
and its typed `OrderPreview` carries them:

- A sell sized by what it brings in ("sell enough BTC to get 500 USDT"): a
  sell market order, or sell immediate-or-cancel limit order, that sells whole
  quantity steps until its proceeds before fees reach an amount of quote
  asset, never more. `OrderPreview.quote_proceeds` (field 20) states that
  amount, an exact decimal string in the quote asset. Such an order has no
  `quantity` and no `quote_amount`; `estimated_value` is the proceeds target.
- A limit order with a static peg ("buy 0.1 BTC at the best bid", "sell 1 ETH
  two ticks above the best ask"): the exchange takes its price once, when it
  accepts the order, from the best bid or ask moved by a number of the pair's
  ticks, and never moves it after. It is a new `OrderPreview` kind,
  `pegged_limit` (field 21, `PeggedLimitOrderPreview`), never the `limit`
  kind, so a client that does not know it never draws the order's bound as
  its price. It has:
  - `reference`: `BEST_BID` or `BEST_ASK`, the book side the price is taken
    from.
  - `offset_ticks`: the signed number of the pair's ticks added to it (2 is
    two ticks above, -1 one tick below); zero, the best price itself, is
    omitted in JSON.
  - `tick_size`: the pair's tick size, an exact decimal string.
  - `current_price`: the price the peg gives at the book the preview read. The
    exchange takes it again when it accepts the order, so the order's price
    can differ.
  - `bound_price`: the most a buy pays or the least a sell takes. The exchange
    checks the order's minimums, maximums and funds at it, and refuses the
    order when the pegged price passes it. It is not the order's price.
  - `time_in_force`, `expire_at` and `post_only`, as on a limit order. A
    pegged order carries no attached exits.

  `OrderPreview.reference_price` is the book side it is pegged to, and
  `estimated_value` the quantity at `current_price`.

The assistant's orders can also set the fee asset (a buy may pay its fee in
the base asset where the market allows it) and the self-trade prevention mode.
Neither has a typed field: the approval's `summary` and `parameters` state
them ("Fee asset", "Self-trade prevention").

## How clients use it

Nothing new to call: the preview arrives on the run's `ApprovalRequested`
event, from the server-streaming `WatchRun` RPC, as `orderPreview`. Read the
stream with a ConnectRPC client. In TypeScript, with code generated from
`ai/v1/assistant.proto`:

```ts
for await (const { event } of assistant.watchRun({ runId })) {
  if (event?.event.case !== "approvalRequested") continue;
  const { preview } = event.event.value;
  if (preview.case !== "orderPreview") continue;
  const order = preview.value;
  if (order.quoteProceeds !== undefined) {
    console.log(`sells until ${order.quoteProceeds} ${order.quoteAsset} before fees`);
  }
  if (order.kind.case === "peggedLimit") {
    const { reference, offsetTicks, tickSize, currentPrice, boundPrice } = order.kind.value;
    console.log(reference, offsetTicks, tickSize, currentPrice, "bound", boundPrice);
  }
}
```

A buy of 0.001 BTC pegged two ticks below the best bid, paying at most 76000
USDT, arrives as this `orderPreview`, shown in ProtoJSON:

```json
{
  "symbolId": 1,
  "symbol": "BTC-USDT",
  "baseAsset": "BTC",
  "quoteAsset": "USDT",
  "side": "BUY",
  "quantity": "0.001",
  "estimatedValue": "75.93",
  "referencePrice": {
    "price": "75939.39",
    "source": "BEST_BID",
    "observedAt": "2026-11-24T12:00:00Z"
  },
  "peggedLimit": {
    "reference": "BEST_BID",
    "offsetTicks": "-2",
    "tickSize": "0.01",
    "currentPrice": "75939.37",
    "boundPrice": "76000",
    "timeInForce": "GTC"
  }
}
```

A market sell sized by 500 USDT of proceeds carries `"side": "SELL"`,
`"quoteProceeds": "500"`, `"estimatedValue": "500"` and `"market": {}`, and
no `quantity`. Approving the card places exactly this order;
`DecideApproval` is unchanged.

## Migration

None required: every change is a new field or message. Update to an SDK
generated from this contract to draw them. How an older client handles such
an approval depends on how it decodes events:

- A client decoding binary protobuf, or ProtoJSON with unknown fields
  ignored, keeps the event. A pegged order's `pegged_limit` kind is unknown
  to it, so it shows the approval's summary and parameters, which state the
  peg and the bound. A sell sized by proceeds keeps its `market` or `limit`
  kind with neither `quantity` nor `quote_amount`: a client that assumes one
  of them is set must show the summary and parameters for it, which state
  the proceeds target.
- A client decoding ProtoJSON strictly with an older descriptor rejects the
  whole event (`key "quoteProceeds" is unknown`, `key "peggedLimit" is
  unknown`). Update the SDK, or decode with unknown fields ignored.
