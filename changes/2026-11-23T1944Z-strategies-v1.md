## What and why

`RunScenarios` records a version's behaviour-example results and answers later
calls from that record, so a version's recorded results stay the same. There is
now one exception. When a call takes longer than allowed, or the runtime fails
on a run, the outcome depends on that run rather than on the version. Such a
run's results are returned but not recorded. The affected example fails with an
error that says to run the examples again, and the next call runs them again.

Before, such a run was recorded like any other, so one slow or failed run could
leave a version's examples failing until a new version was saved. Only the
comments of `RunScenarios` and `ScenarioResult.error` change; messages, fields
and the wire are unchanged.

## How clients use it

```http
POST /strategies.v1.StrategiesService/RunScenarios
{"versionId": "sha256:..."}
```

An example the run couldn't finish for these reasons reads, for example:

```json
{"name": "buys on Monday", "passed": false,
 "error": "a call took longer than allowed on this run; run the examples again"}
```

or `"the runtime failed on this run; run the examples again"`. Calling
`RunScenarios` again runs the examples again. Each new run counts toward the
per-minute limit (`SCENARIO_RUN_LIMIT_REACHED` with `retry_after`); a recorded
run answers without counting.

## Migration

None: the contract's shape is unchanged. A client that treated every failed
example as final for the version may offer to run the examples again when the
error says so.
