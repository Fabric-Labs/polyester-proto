## What and why

`RunScenarios` now runs a version's behaviour examples against its code.
The contract is unchanged; one comment now states exactly when an example
passes:

- `ScenarioResult.passed` is true when the handler ran without an error,
  made exactly the expected orders and cancels, in order, and watches every
  expected level.

## How clients use it

```json
POST /strategies.v1.StrategiesService/RunScenarios
{"versionId": "sha256:…"}

{"versionId": "sha256:…", "passed": 2,
 "results": [
   {"name": "Buys on Monday when RSI is normal", "passed": true,
    "expected": [{"buy": "BTC/USDT", "quote": "50"}],
    "actual": [{"buy": "BTC/USDT", "quote": "50"}]},
   {"name": "Skips an overheated week", "passed": true,
    "logs": ["Skipped this week: daily RSI is 80"]}]}
```

- A version runs once: the result is deterministic, and every later call
  returns the same one.
- At most 10 new runs per minute per account; past that the call is
  `SCENARIO_RUN_LIMIT_REACHED` with `retry_after`. A version that already ran
  answers without counting. A new run counts even when it fails or the call
  is cancelled.
- `actual` lists the orders and cancels the code made, in the shape of
  `expected`, so a failing example shows the difference. `error` holds the
  handler's error when it raised.
- The scenario format is the reference's Scenarios section.
