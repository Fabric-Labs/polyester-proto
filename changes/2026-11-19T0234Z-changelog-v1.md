## What and why

The documentation of `published_at` now describes what the changelog returns
for release posts. Only comments change: no message, field, RPC or wire
encoding changes, and the values returned are the same as before this note.

The comments said `published_at` is the time of first publication. For a
release post (a post with `release_version`), `published_at` is the
publication time in the environment you read:

- the time the release went live there, the same value as that environment's
  `live_at` in `environments`, so releases that went live together share it;
- the time the post was first published, while the release is still pending
  there.

So the same release post's `published_at` can differ between environments. It
follows that environment's `live_at`: it changes when the release goes live
there, and again whenever that `live_at` changes later, for example when the
release is dated by an earlier deployment, all without a new `revision`.
Republishing never changes it. Other posts keep the time of first publication.
Post lists are ordered by `published_at`, newest first, then by release
version descending at equal times.

The same applies to `ChangeEntry.published_at` (`ListChanges`) and
`DeploymentGroupPost.published_at` (deployment groups). `PostSummary.updated_at`
is still when the current revision was published. For a release post it is
independent of `published_at` and can be earlier or later.

## How clients use it

Nothing new to call. Read `published_at` as the post's date in the
environment you query:

```bash
curl -sS https://<api-host>/changelog.v1.ChangelogService/ListPosts \
  -H 'Content-Type: application/json' -d '{"limit": 20}'
curl -sS 'https://<api-host>/v1/changelog/posts?limit=20'
```

## Migration

None. Clients that treated `published_at` as a fixed time of first publication
should not treat a release post's `published_at` as fixed, whether the release
is pending or already live in the environment: read it again with the post
instead of keeping a copy. Use `revision` and `updated_at` to follow edits to
the post itself; a change of `published_at` alone does not change them.
