## What and why

`GetIndexPriceCandles` is new. It returns one continuous price series per
spot market, in columns: the market's composite reference candles before the
bucket containing its listing time, and its index price candles from that
bucket on. Each candle is marked with its source, so a backtest or an
analysis can read prices over any window and see which part came before the
listing. It is a ConnectRPC method, like `GetCandlesColumns`, with no REST
route.

- Request `GetIndexPriceCandlesRequest`: `symbol_id`, `timeframe` (required;
  every candle timeframe except `SEC_1`), `limit` (default
  500, max 10000), inclusive `start_time` and `end_time`, and `page_token`.
- Response `GetIndexPriceCandlesResponse`: `symbol_id`, `timeframe`, the
  columns `ts_sec`, `open`, `high`, `low`, `close` and `source`, and
  `next_page_token`. Element `i` of every column is the same candle.
- Enum `IndexPriceCandleSource`: `INDEX_PRICE_CANDLE_SOURCE_REFERENCE` and
  `INDEX_PRICE_CANDLE_SOURCE_INDEX`.
- Prices use the pair's `reference_price_scale` from `GetSpotConfig`, the
  scale of both series.
- There is no volume field: neither series carries trading volume.
- Gaps exist. From the listing on, a bucket in which the index price had no
  valid value is omitted, never filled from the reference series. Index price
  candles begin with this release: earlier buckets after a listing are absent
  the same way.
- Candles are closed only, newest first, with strictly descending `ts_sec`
  and the same bucket alignment as `GetCandles`. The bucket containing
  `listing_at` is an index price candle and the one before it a reference
  candle; no `ts_sec` appears twice.
- History: reference candles reach back 180 days at timeframes shorter than
  one hour, five years from one hour to twelve hours, and up to 20 years, as
  far as the market's history goes, at one day and longer. Index price
  candles are kept without a time limit. The newest closed candles can appear some time
  after their bucket closes, and reference candles of the most recent 48
  hours can still be revised.
- `SEC_1` fails with `invalid_argument` and the error code `BAD_REQUEST`.
- The response is unavailable when the pair's price instrument is not known
  yet; retry with backoff.

`PAGE_TOKEN_INVALID` is a new market data error code, ConnectRPC
`invalid_argument` and REST 400: a `page_token` that is malformed, longer than
512 characters, from another method, or bound to another request.

The breaking part, on `GetCandles` and `GetCandlesColumns` (REST `/v1/spot/markets/{symbol}/candles`
included):

- A bad `page_token` now fails with `PAGE_TOKEN_INVALID`, instead of
  `INVALID_ARGUMENT`. The status is unchanged.
- A token is bound to `start_time` and `end_time` as sent: a token from a
  request without a bound is refused when the bound is sent, the Unix epoch
  included, and the other way round. Tokens issued before this release are
  refused once with `PAGE_TOKEN_INVALID`.
- A `start_time` or `end_time` that is no valid Timestamp (nanos outside
  0..999999999, or seconds outside the years 0001 to 9999) now fails with
  `INVALID_ARGUMENT` instead of being normalized.

`GetIndexPriceCandles` answers a bad token and an invalid Timestamp the same
way, and its tokens and the chart's are not interchangeable.

## How clients use it

```json
POST /marketdata.v1.MarketDataService/GetIndexPriceCandles
{"symbolId": 1, "timeframe": "HOUR_1", "startTime": "2026-01-01T00:00:00Z",
 "endTime": "2026-02-01T00:00:00Z", "limit": 745}

{"symbolId": 1, "timeframe": "HOUR_1",
 "tsSec": ["1769904000", "1769900400"],
 "open": ["9501250", "9499000"], "high": ["9512000", "9502000"],
 "low": ["9498025", "9497500"], "close": ["9510100", "9501250"],
 "source": ["INDEX_PRICE_CANDLE_SOURCE_INDEX", "INDEX_PRICE_CANDLE_SOURCE_REFERENCE"],
 "nextPageToken": ""}
```

When `next_page_token` is set, call again with the same `symbol_id`,
`timeframe`, `start_time` and `end_time` and that token to read older
candles. An empty token means no older candle exists in the range. Treat a
missing `ts_sec` as a gap.

## Migration

Clients that match on `INVALID_ARGUMENT` for a bad candle `page_token` on
`GetCandles` or `GetCandlesColumns` match `PAGE_TOKEN_INVALID` instead, drop
stored cursors and request the first page again. Send each token with exactly
the bounds of the request that returned it, and send valid Timestamps.
