## What and why

A conversation can now be about one thing, starting with one of the caller's
strategies. A client that shows the assistant beside a strategy names it with
each message, and every message about that strategy lands in the same
conversation, which the client reopens later.

- `Subject` (a oneof, first case `strategy`) and `StrategySubject
  {strategy_id}` are new messages.
- `SendMessageRequest.subject` (11) selects the conversation about the
  subject, and starts it when there is none yet.
- `Conversation.subject` (5) says what a conversation is about. It is omitted
  for a general conversation.
- `ListConversationsRequest.subject` (3) lists only the conversation about a
  subject.
- `ErrorCode.CONVERSATION_SUBJECT_MISMATCH` (21), with FAILED_PRECONDITION,
  refuses a message whose subject is not its conversation's.

A subject grants nothing: every read and change the assistant makes is still
checked against the caller's own access.

## How clients use it

To open the conversation about a strategy, list it first. The answer holds
zero or one conversation:

```json
POST /ai.v1.AssistantService/ListConversations
{ "subject": { "strategy": { "strategyId": "1234567890123" } } }
```

When there is one, read its messages with `ListMessages` as usual. To send a
message, name the subject and omit `conversationId`. The answer's
`conversationId` is the conversation about the strategy: the existing one, or
the one this message started.

```json
POST /ai.v1.AssistantService/SendMessage
{
  "text": "Make the entry wait for two closes above the band",
  "idempotencyKey": "studio-7f3c",
  "subject": { "strategy": { "strategyId": "1234567890123" } }
}
```

There is at most one conversation per subject, so two tabs that start it at
the same time share one conversation.

A conversation's subject is fixed when it starts:

- With `conversationId`, omit `subject`, or send the conversation's own one.
- Any other subject is FAILED_PRECONDITION `CONVERSATION_SUBJECT_MISMATCH`,
  and nothing is recorded. So is a subject for a general conversation. Switch
  to the subject's own conversation instead.
- `subject` is part of the request the idempotency key covers: a retry sends
  the subject the first attempt sent.

`ListConversations` without a subject still lists every conversation,
including those about a subject, which carry `subject`.

## Migration

None: the fields are new, and a client that sends no subject behaves exactly
as before.
