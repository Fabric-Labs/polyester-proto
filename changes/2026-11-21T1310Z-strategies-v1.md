## What and why

Bots now read PAUSED when they pause, with why. Until now no bot was ever
reported paused.

- **`Bot.status` PAUSED** is returned by `ListBots`, `GetBot` and the
  strategy's `bot`, once the bot's pause has been reported to the service. A
  paused bot that is being stopped reads STOPPING, and a stopped one STOPPED.
- **`Bot.pause_reason`** is set with PAUSED:
  - `BOT_DECIDED`: the bot's own code paused it;
  - `UNRECORDED_ORDER` (new value, 4): the bot found one of its own orders
    whose placement it hadn't recorded, for example after a restart, and
    paused so you can check its state. An order placed by hand or by another
    app doesn't pause the bot.
- **`Bot.status_reason`** is set only with PAUSED: the bot's own message, or
  "The bot paused itself." when it gave none, and a fixed sentence for
  `UNRECORDED_ORDER`.
- **`ListBotsResponse.status_counts`** counts paused bots under PAUSED.
- **`StrategyBot.status`** can now read PAUSED as well as RUNNING and
  STOPPING.

## How clients use it

Nothing new to call. A paused bot, as `GetBot` returns it:

```http
POST /strategies.v1.StrategiesService/GetBot
Content-Type: application/json
Connect-Protocol-Version: 1

{"botId": "1234"}
```

```json
{
  "bot": {
    "botId": "1234",
    "name": "Weekly DCA",
    "status": "PAUSED",
    "pauseReason": "UNRECORDED_ORDER",
    "statusReason": "The bot found one of its own orders whose placement it hadn't recorded, for example after a restart, and paused so you can check its state."
  }
}
```

A paused bot has no `runningSince`; its paused time counts as running in
`uptimeRatio`.

## Migration

None required. A client that shows `pause_reason` should give
`UNRECORDED_ORDER` its own wording; until then, show `status_reason`, which
always explains a PAUSED bot.
