## What and why

**Availability:** devnet only.

Two changes to the assistant API, both additive on the wire.

**`SendMessage` can be conditional on the conversation's latest run.** A
client that offers to continue a request it showed the user, such as a button
under an answer, can make sure the message never lands after a newer one, from
any device or channel.

- `SendMessageRequest.expected_latest_run_id` (new, optional `fixed64`): the
  message is recorded only while this run is still the conversation's latest
  run. The check happens as the message is recorded. When another run is the
  latest, nothing is recorded and the call fails with `FAILED_PRECONDITION`
  and the new `ErrorCode` `CONVERSATION_ADVANCED`. It requires
  `conversation_id` (`INVALID_ARGUMENT` otherwise).
- The field is part of the request the idempotency key covers. Repeating a
  request that was already recorded returns its run, whatever ran since, so
  the condition never breaks a retry.
- `ErrorCode.CONVERSATION_ADVANCED` (new value).

**`ListAssistantKeys` with `ASSISTANT_KEY_VIEW_FULL` now lists the keys in the
order an account picker shows them,** so the accounts that matter most come
first:

- the main account's key first;
- then the subaccounts' keys by the subaccount's equity, highest first;
- keys with equal equity, and keys whose equity could not be read (which come
  last), by account name.

The default view still lists the keys oldest first; only the full view's
order changes. No field, message or enum of that call changes.

## How clients use it

Continue a request only while its answer is still the latest:

```json
POST /ai.v1.AssistantService/SendMessage
{
  "conversationId": "5000000000001",
  "text": "Continue this request on the account I just chose: \"Buy 0.1 BTC\"",
  "idempotencyKey": "continue-5000000000042",
  "subaccountId": "5000000000007",
  "expectedLatestRunId": "5000000000042"
}
```

On `FAILED_PRECONDITION` with `CONVERSATION_ADVANCED`, the conversation has
moved on: tell the user instead of retrying. On an unknown outcome, repeat the
same request with the same key.

List the keys for an account picker:

```json
POST /ai.v1.AssistantService/ListAssistantKeys
{ "view": "ASSISTANT_KEY_VIEW_FULL" }
```

Show the keys in the order returned. Equity is valued in USDT, as the
portfolio values it. An account whose equity can't be read is listed after
the others, by name, and the call still succeeds.

## Migration

None. The new field is optional, and the error code appears only for callers
that set it. The default view of `ListAssistantKeys` keeps its order. A client
that sorted the full view itself may drop its own sort.
