## What and why

The bot pages need more than the bot reads carried, and `ListBots` and
`GetBot` now answer instead of `UNIMPLEMENTED`. This change adds what the
pages show and removes one bot status that is never produced.

- **`ListBots` and `GetBot` are served.** They read the bots of the caller's
  main account only: another account's bot, a member's included, is
  `NOT_FOUND` with `BOT_NOT_FOUND`.
- **New `Bot` fields:**
  - `markets`: the markets the bot trades, for example `BTC/USDT`;
  - `funding` (new `BotFunding`): the subaccount the initial funding came
    from, its current label, and `initial_funding`. Absent until the deploy
    flow records the deploy proposal a bot came from;
  - `uptime_ratio`: the share of the time since the bot was first deployed
    during which it was running, a decimal string from `"0"` to `"1"`. Time
    spent paused counts as running;
  - `running_since`: when the bot last started, set only while `RUNNING`.
- **`ListBotsResponse.status_counts`** (new `BotStatusCount`): how many of
  all the caller's bots are in each status, on every page.
- **`SettingValue`** gains `description`, `kind` and `asset`, from the
  version's settings form. `GetBot` sets them; leave them empty in requests.
  `GetBot.settings` is empty until the deploy flow records the proposal.
- **`DeployStatus.failed_at`**: the step a `FAILED` deploy failed in, beside
  `failure`. The deploy flow sets it.
- **`GetDeployProposalResponse`** gains `created_at` and
  `funding_subaccount_label`.
- **New `ListBotVersions`**: the versions one bot ran, newest first, with
  when each run started and when its stop was recorded.
- **New `GetStrategyVersion`**: a version's manifest, code and settings form,
  for its owner only, to start a new strategy from it.
- **`Bot.pause_reason`** (new `Bot.PauseReason`): why a `PAUSED` bot paused,
  beside the `status_reason` text: the bot's own decision, failures in a
  row, or an environment reset. Set only with `PAUSED`.
- **`ProposeDeploy`'s `deploy_url`** now names the proposal by its public ID
  in base58, as the website shows every ID, instead of its decimal value.
  Treat the URL as opaque: open it, never parse it.
- **`Bot.Status` value `QUARANTINED` (6) is removed.** No call ever returned
  it. A bot stopped by repeated failures is `PAUSED`, with the reason in
  `status_reason`.
- **Comments now state:**
  - `STOPPED`, and `PAUSED` with its reason, are read only once the bot's
    stop or pause has been reported to the service. Until then a stopped bot
    reads `STOPPING`, and a paused one `RUNNING`.
  - `StopBot` works in every state but `STOPPED`, and `BOT_NOT_RUNNING` means
    the bot has already stopped. On a `STOPPING` bot, the same mode returns
    the existing stop, and the other mode is `BOT_ALREADY_STOPPING`.
  - A `KEEP_ORDERS` stop hands the bot's open orders to its subaccount: they
    stay in the book as the subaccount's own orders, and the bot reads
    `STOPPED` once its in-flight orders are settled, never held in `STOPPING`
    by the orders it kept. A `CANCEL_ORDERS` stop reads `STOPPING` until
    every cancelled order has ended and its fills are reconciled.
  - `STOP_STRATEGIES` is a main-account API-key permission. A member stops a
    bot with a session, through a role with the stop-bots permission.

## How clients use it

```json
POST /strategies.v1.StrategiesService/ListBots
{"limit": 50}

{"bots": [{"botId": "…", "name": "Weekly DCA", "status": "RUNNING",
           "versionId": "sha256:…", "quoteAsset": "USDT", "markets": ["BTC/USDT"],
           "uptimeRatio": "0.9875", "runningSince": "2026-11-20T09:00:00Z",
           "funding": {"subaccountId": "…", "subaccountLabel": "Savings",
                       "initialFunding": [{"asset": "USDT", "amount": "200"}]}}],
 "nextPageToken": "…",
 "statusCounts": [{"status": "RUNNING", "count": 1}, {"status": "STOPPING", "count": 1}]}

POST /strategies.v1.StrategiesService/ListBotVersions
{"botId": "…", "limit": 50}

{"versions": [{"versionId": "sha256:…", "name": "Weekly DCA", "runtimeVersion": "2026-11",
               "startedAt": "…", "stoppedAt": "…"}],
 "nextPageToken": ""}

POST /strategies.v1.StrategiesService/GetStrategyVersion
{"versionId": "sha256:…"}

{"versionId": "sha256:…", "name": "Weekly DCA", "runtimeVersion": "2026-11",
 "manifest": {…}, "code": "…", "settingsForm": [ … ], "valid": true, "createdAt": "…"}
```

- `ListBots` is newest deployed first. `ListBotVersions` is newest run
  first, one entry per run, so a version deployed again appears again. Both
  take `limit` (default 50, max 200) and an opaque, keyset-backed, exclusive
  `page_token`. `ListBots` binds its token to the caller, and
  `ListBotVersions` to the caller and `bot_id`. `next_page_token` is empty on
  the last page.
- `status_counts` lists only statuses that have a bot, in status order. It
  is not a pagination total.
- Every new call is declared `NO_SIDE_EFFECTS` and has no REST route. An API
  key needs `READ_STRATEGIES` and must be scoped to the main account.
- `GetStrategyVersion` reads an expired version while a deploy proposal or a
  bot of the caller uses it; otherwise it is `VERSION_NOT_FOUND`.
- `GetBot` leaves `balances`, `open_orders`, `decisions` and `errors` empty
  until they are available.

## Migration

- Drop any handling of `Bot.Status` `QUARANTINED`. No server ever returned
  it, so no stored data carries it. A client generated from the previous
  contract that receives an unknown status shows it as unrecognized. Treat a
  `PAUSED` bot with a `status_reason` as the paused-after-failures case.
- Nothing else changes for existing callers: every other change is a new
  field or call.
