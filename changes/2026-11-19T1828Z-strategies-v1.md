## What and why

`ValidateStrategy` now checks bots and stores them as versions. The contract
is unchanged; its comments now state what it does:

- Bots are written against one runtime version, `2026-11`.
  `GetStrategyReference` returns it in `runtime_version`, each template names
  it, and a request may name it. Any other value is still
  `RUNTIME_VERSION_UNSUPPORTED`. The rest of the runtime catalog
  (`manifest_schema`, `indicators`, `limits`, `indicator_library`) stays
  empty until it is available.
- A manifest is at most 65536 bytes (64 KiB) as compact JSON; a larger one is
  `MANIFEST_TOO_LARGE`.
- `MoneyCard.budget` is unset: no total spending limit is enforced yet, and
  the funding a deploy moves bounds what a bot can spend.
  `MoneyCard.daily_loss_threshold` is the threshold the manifest declares, or
  unset when it declares none. It is not enforced yet: nothing pauses or
  stops a bot on it, so don't present it as a stop.

## How clients use it

```json
POST /strategies.v1.StrategiesService/ValidateStrategy
{"name": "Weekly DCA", "manifest": {"name": "Weekly DCA", "markets": ["BTC/USDT"],
  "schedule": "mon 09:00 UTC",
  "limits": {"max_order": {"asset": "USDT", "amount": "60"}, "max_open_gtc_orders": 2}},
 "code": "def on_timer(bot, state, timer):\n    return state\n"}

{"versionId": "sha256:…", "runtimeVersion": "2026-11", "valid": true,
 "moneyCard": {"maxOrder": {"asset": "USDT", "amount": "60"}, "maxOpenGtcOrders": 2,
               "markets": ["BTC/USDT"], "events": ["schedule mon 09:00 UTC"]}}
```

- A bot with mistakes answers `valid: false` with up to 50 errors and 50
  warnings, each with a manifest path or a code line and column, a stable
  `rule`, a message and a hint. Fix them and validate again.
- The same runtime version, manifest and code always give the same
  `version_id`, whatever the manifest's key order or spacing. The name is not
  part of it.
- Behaviour examples (`scenarios` in the manifest) follow the format the
  reference's Scenarios section gives: each has a `name`, `at`, an `event`
  (start, timer, candle, price, fill, settled or order), what `observe`s
  (prices, balances, indicators such as `"rsi BTC/USDT 1d 14"`, candles and
  open orders), `continue_from` or `state`, and the ordered `expect`ed
  orders, cancels and watched levels. A scenario that doesn't fit is a
  `SCENARIO_UNPARSEABLE` error at its field.
- The reference's manifest section lists the rules: every limit is in the
  markets' one quote asset, `max_order` and `max_open_gtc_orders` are
  required, `daily_loss_threshold` is optional, and a setting is a `quote`
  amount or a `number`.

## Migration

None: there are no field or value changes, and `ValidateStrategy` answered
Unimplemented until now, so no stored version uses another scenario format.
Write behaviour examples as the reference shows; the template has two. A
client that took a set `runtime_version` to mean the whole catalog is
available should check `manifest_schema` instead.
