## What and why

`GetPortfolioEquitySnapshot` answers an API key scoped to a subaccount as
every other read that needs a key scoped to the main account does: 403 /
PermissionDenied with code `AUTH_API_KEY_ACCESS_DENIED` and the detail
`"READ_BALANCES requires an API key scoped to the main account"`. It used to
answer `AUTH_SESSION_KIND_NOT_ALLOWED`, "interactive session required",
which hid that a key scoped to the main account with READ_BALANCES reads
the snapshot. The status is unchanged, and sessions and keys scoped to the
main account are answered as before.

## How clients use it

Read the snapshot with a session token, or with an API key scoped to the
main account whose policy grants READ_BALANCES:

```bash
curl -sS https://<api-host>/v1/equity/portfolio/snapshot \
  -H 'X-API-KEY-ID: <main account key id>' \
  -H 'X-API-TIMESTAMP: <unix ms>' \
  -H 'X-API-SIGNATURE: <signature>'
# ConnectRPC: POST https://<api-host>/ledger.read.v1.LedgerReadService/GetPortfolioEquitySnapshot {}
```

A key scoped to a subaccount is refused:

```json
{"code": "AUTH_API_KEY_ACCESS_DENIED", "status": 403,
 "detail": "READ_BALANCES requires an API key scoped to the main account"}
```

## Migration

None for successful calls. A client that matched `AUTH_SESSION_KIND_NOT_ALLOWED`
for a subaccount-scoped key on this read matches `AUTH_API_KEY_ACCESS_DENIED`
instead, and can retry with a key scoped to the main account.
