## What and why

A new `ledger.read.v1.StatementExportService` produces a whole-period account statement as one CSV file in the background, so accounts no longer page through `LedgerReadService.ExportStatement` for long periods.

- `CreateStatementExport` asks for a file of one account, optionally limited to one asset, for a period of up to 366 days. It is idempotent per `idempotency_key`.
- `GetStatementExport` and `ListStatementExports` report its status (`QUEUED`, `PROCESSING`, `READY`, `FAILED`, `EXPIRED`), progress (`movements`, `bytes`) and expiry.
- A `READY` file is downloaded with an authenticated `GET /v1/statements/exports/{exportId}/file` for 7 days. It is byte for byte the `ExportStatement` pages for the same account, asset and period up to `complete_through`, concatenated.
- Access follows `ExportStatement`: API keys need the `READ_STATEMENTS` policy action, with the same account and subaccount rules.
- `ledger.read.v1.ErrorCode` gains `IDEMPOTENCY_KEY_REUSED`, `STATEMENT_EXPORT_LIMIT_REACHED`, `STATEMENT_EXPORT_NOT_READY`, `STATEMENT_EXPORT_EXPIRED` and `STATEMENT_EXPORT_FAILED`.

## How clients use it

Create an export, poll it, then download the file:

```http
POST https://<api-host>/ledger.read.v1.StatementExportService/CreateStatementExport
Content-Type: application/json

{"startTime": "2026-01-01T00:00:00Z", "endTime": "2027-01-01T00:00:00Z", "idempotencyKey": "statement-2026"}
```

The same over REST is `POST /v1/statements/exports` with the same body. Then:

- `GET /v1/statements/exports/{exportId}` (`GetStatementExport`) until `status` is `READY`;
- `GET /v1/statements/exports?subaccountId=&limit=&pageToken=` (`ListStatementExports`): newest first, at most 100 per page, 20 by default.
- `GET /v1/statements/exports/{exportId}/file` returns `text/csv`. It supports single-range `Range` requests with `If-Range`. With `?redirect=true` it answers `307` to a URL valid for 60 seconds.

Limits and outcomes:

- A root account has at most 5 exports `QUEUED` or `PROCESSING`; another create answers `RESOURCE_EXHAUSTED` (`STATEMENT_EXPORT_LIMIT_REACHED`; REST `429`).
- One account produces one export at a time; the others wait `QUEUED`.
- A period with more than 4,000,000 ledger movements fails as `TOO_LARGE`: split it.
- A period still open at create time ends then: `complete_through` is the end of what the file covers.
- Repeating a create with the same key returns the same export. The same key with other fields answers `FAILED_PRECONDITION` (`IDEMPOTENCY_KEY_REUSED`; REST `409`).
- Before `READY`, or after `FAILED`, the download answers `409`. After `expires_at` it answers `410`.

## Migration

None: the service is new. `ExportStatement` is unchanged.
