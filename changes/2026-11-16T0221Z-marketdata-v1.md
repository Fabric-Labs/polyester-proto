## What and why

Two errors now answer one ConnectRPC code per case across the API.

- **Request too large.** A request whose body is over the API's size limit
  answers the ConnectRPC code `resource_exhausted`, as gRPC answers an
  oversized message, on every API. Until now an API-key request, and every
  orders read and ledger read request, that was too large got a REST problem
  body even when it was a ConnectRPC, gRPC or gRPC-web call, which those
  clients decode as `unknown`. REST requests keep the HTTP 413 problem with
  `code` `REQUEST_TOO_LARGE`.
- **Unknown symbol in market data.** A market data read of trades or candles
  for a symbol that is not listed answers the ConnectRPC code `not_found`
  instead of `invalid_argument`, as the order book already does. The symbol
  names the resource being read. REST already answers 404 with `code`
  `UNKNOWN_SYMBOL`, unchanged.

An order that names an unknown symbol in its request body still answers
`invalid_argument` and HTTP 400. No message, field or enum value changed.

## How clients use it

```http
POST /orders.v1.OrdersService/CreateOrder
HTTP/1.1 429 Too Many Requests

{"code":"resource_exhausted","message":"request too large"}
```

```http
POST /v1/orders
HTTP/1.1 413 Request Entity Too Large

{"type":"https://polyester.dev/problems/request-too-large","title":"Request Entity Too Large","status":413,"detail":"request too large","code":"REQUEST_TOO_LARGE"}
```

```http
POST /marketdata.v1.MarketDataService/GetTrades
HTTP/1.1 404 Not Found

{"code":"not_found","message":"unknown symbol_id: 8"}
```

ConnectRPC answers `resource_exhausted` with HTTP 429 by its own protocol
mapping; branch on the code, not the status.

## Migration

1. Where a ConnectRPC client detects an oversized request by matching
   `invalid_argument` or `unknown`, match `resource_exhausted` instead.
   Do not retry it unchanged: send a smaller request.
2. Where a ConnectRPC client detects an unknown symbol on `GetTrades`,
   `GetCandles` or `GetCandlesColumns` by matching `invalid_argument`, match
   `not_found` instead.

REST clients that branch on the HTTP status or the problem `code` need no
change.
