## What and why

A ladder whose levels the user canceled before any of them filled now ends
`STATUS_CANCELED` with `cancel_reason` `TRIGGER_CANCEL_REASON_USER_REQUEST`,
and its history gains one `CANCELED` event, as when the ladder itself is
canceled. Before, it ended `STATUS_COMPLETED` with nothing executed and no
cancel reason, which read as if the ladder had finished.

The ladder ends this way once none of its levels remains open, when nothing
filled and its levels were canceled, for example one by one, with a
cancel-all, or by the dead man's switch the user set. Every other ending is
unchanged:

- A ladder that filled any quantity ends `STATUS_COMPLETED`, however its
  other levels ended, canceled by the user included. `executed_qty_scaled` and
  `executed_levels` say what filled.
- A ladder whose levels were all rejected before any was placed ends
  `STATUS_FAILED` with the first rejected level's reason.
- A ladder that filled nothing and whose levels were canceled only by
  self-trade prevention ends `STATUS_COMPLETED`; each level's own order
  states why it was canceled.
- Canceling the ladder itself ends it `STATUS_CANCELED` at once, as before.

The comments on `TriggerStatus.STATUS_COMPLETED` and `STATUS_CANCELED` say
so. No field, enum value or method changed.

## How clients use it

Nothing new to call. Read the ladder's status and reason as for any canceled
trigger, from the trigger reads, the trigger history and the private stream:

```bash
curl -sS https://<api-host>/triggers.v1.TriggersService/GetTrigger \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer <token>' \
  -d '{"triggerId": "1234567890123456789"}'
# {"trigger": {"type": "LADDER", "status": "STATUS_CANCELED",
#   "cancelReason": "TRIGGER_CANCEL_REASON_USER_REQUEST", ...}}

curl -sS https://<api-host>/v1/triggers/3sDK21t5nHJ \
  -H 'Authorization: Bearer <token>'
```

## Migration

None for clients that treat `STATUS_CANCELED` as a terminal status for every
trigger type. A client that relied on a ladder ending `STATUS_COMPLETED` once
its levels were canceled should expect `STATUS_CANCELED` with a user request
reason when nothing filled.
