## What and why

The REST candles endpoint now always sends the fields its published schema
requires. A market or timeframe with no candles yet, for example every daily
or weekly series right after a market opens, used to answer with only `symbol`
and `timeframe`. It now also sends `candles: []`, `referenceCandles: []` and
`nextPageToken: ""`, as the trades endpoint already does. A page with fewer
candles than `limit`, or a request without `includeReference`, likewise sends
an empty `nextPageToken` and `referenceCandles`.

The REST response's `symbol` is now documented as what it always was: the
trading pair symbol from the request path, such as `BTC-USDT`, not a numeric
market identifier.

ConnectRPC `GetCandles` is unchanged.

## How clients use it

```bash
curl -sS 'https://<api-host>/v1/spot/markets/BTC-USDT/candles?timeframe=1d'
# A series with no closed candle yet:
# {"candles":[],"nextPageToken":"","referenceCandles":[],"symbol":"BTC-USDT","timeframe":"1d"}
```

An empty `nextPageToken` means there are no more pages. `referenceCandles` is
non-empty only with `includeReference=true` and when a reference series exists
for the timeframe.

## Migration

None: the response now matches the published schema. Clients that tested
whether `candles` or `nextPageToken` was present, rather than whether it was
empty, now always find it.
