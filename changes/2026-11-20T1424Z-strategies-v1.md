## What and why

A user's bots now live in **strategies**: a named bot and the ordered
history of its saved drafts. Saving a draft is how a bot is checked and
stored, so the separate check call is removed.

- **New `CreateStrategy`**: creates a strategy, blank, from a bot template
  (`template_id`), or as a copy of one of the caller's own versions
  (`version_id`). A template or a copy is saved as revision 1; a blank
  strategy has no revision until its first save. An account has at most 100
  strategies (`STRATEGY_CAP_REACHED`). Idempotent per `idempotency_key`.
- **New `SaveDraftVersion`**: checks a bot and saves it as the next revision
  of a strategy. `expected_revision` must be the strategy's current
  revision, so two writers never overwrite each other; otherwise it is
  `DRAFT_REVISION_CONFLICT`, whose detail carries the current revision and
  its version. A bot with mistakes is saved too, with `valid` false and its
  errors. A save whose content is already the current revision's adds no
  revision, and renames the strategy if its name is new.
  `idempotency_key` is optional.
- **New reads:** `GetStrategy` (a strategy and its current version, as
  `GetStrategyVersion` returns it), `ListStrategies` (most recently saved or
  renamed first) and `ListStrategyRevisions` (newest first, with how each
  revision was saved).
- **New `RenameStrategy`.**
- **New messages:** `Strategy`, `StrategyOrigin`, `StrategyDuplicateOrigin`,
  `StrategyRevision` (with the `StrategyRevision.SavedBy` enum),
  `StrategyCapDetail`, `RevisionConflictDetail`, and each new call's request
  and response.
- **New `ErrorCode` values:** `STRATEGY_NOT_FOUND` (25),
  `DRAFT_REVISION_CONFLICT` (26), `STRATEGY_CAP_REACHED` (27) and
  `TEMPLATE_NOT_FOUND` (28). `ErrorDetail` gains `strategy_cap` (7) and
  `revision_conflict` (8).
- **Removed: `ValidateStrategy` and `ValidateStrategyRequest`.**
- **Renamed: `ValidateStrategyResponse` is now `VersionValidation`**, a
  version's check result. Its fields are unchanged, and `SaveDraftVersion`
  and `CreateStrategy` return it.
- A version a revision of a strategy names never expires, so
  `GetStrategyVersion` reads it for as long as the strategy keeps it.

## How clients use it

```json
POST /strategies.v1.StrategiesService/CreateStrategy
{"name": "Weekly DCA", "idempotencyKey": "create-1"}

{"strategy": {"strategyId": "…", "name": "Weekly DCA", "revision": "0",
              "headVersionId": "", "valid": false,
              "createdAt": "…", "updatedAt": "…"}}

POST /strategies.v1.StrategiesService/SaveDraftVersion
{"strategyId": "…", "expectedRevision": "0", "name": "Weekly DCA",
 "manifest": {…}, "code": "…", "idempotencyKey": "save-1"}

{"revision": "1",
 "version": {"versionId": "sha256:…", "runtimeVersion": "2026-11", "valid": true,
             "errors": [], "warnings": [], "moneyCard": {…}, "settingsForm": [ … ]}}

POST /strategies.v1.StrategiesService/GetStrategy
{"strategyId": "…"}

{"strategy": {"strategyId": "…", "revision": "1", "headVersionId": "sha256:…", …},
 "head": {"versionId": "sha256:…", "manifest": {…}, "code": "…", …}}
```

- On `DRAFT_REVISION_CONFLICT`, read the strategy again, apply the change to
  its current draft, and save with the new revision. Never resend the same
  request blindly. The conflict's `head_version_id` tells a client without
  an idempotency key whether its own save already landed.
- `ListStrategies` and `ListStrategyRevisions` take `limit` (default 50, max
  200) and an opaque, keyset-backed, exclusive `page_token`, bound to the
  caller, and for revisions also to `strategy_id`. `next_page_token` is
  empty on the last page.
- Writes need `DRAFT_STRATEGIES` and reads `READ_STRATEGIES`, on an API key
  scoped to the main account. Another account's strategy is
  `STRATEGY_NOT_FOUND`. None of the new calls has a REST route.

## Migration

- Replace `ValidateStrategy` with drafts: create a strategy once with
  `CreateStrategy`, then save each change with `SaveDraftVersion`, passing
  the revision it was made from as `expected_revision` (0 for the first
  save). The response's `version` is what `ValidateStrategy` returned.
- Rename `ValidateStrategyResponse` to `VersionValidation` in client code.
  The fields and their numbers are unchanged.
