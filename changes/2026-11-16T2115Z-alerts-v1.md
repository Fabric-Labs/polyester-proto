## What and why

A price alert can ask for the `TELEGRAM` channel only where Telegram alerts are
available and a Telegram account is linked to the caller's account. Before,
such an alert was accepted without a link, and its Telegram message then went
nowhere when it fired.

- Where Telegram alerts are not available (for example on testnet, which has
  in-app alerts only), `CreateAlert` and `UpdateAlert` refuse `TELEGRAM` with
  `FAILED_PRECONDITION` and the new `alerts.v1.ErrorCode`
  `TELEGRAM_UNAVAILABLE`, checked before the link. Linking Telegram does not
  change this answer there.

- `CreateAlert` refuses an alert whose `channels` include `TELEGRAM` when no
  Telegram account is linked: `FAILED_PRECONDITION` with the new
  `alerts.v1.ErrorCode` `TELEGRAM_NOT_LINKED` in an `alerts.v1.ErrorDetail`.
  Nothing is created.
- `UpdateAlert` refuses the same way an update that changes an alert whose
  channels then include `TELEGRAM`. An update that changes nothing, and a
  repeat of an earlier request under its idempotency key, still answer as
  before.
- When a fired alert's Telegram message cannot be delivered, for example
  because Telegram was unlinked after the alert was set, the fired alert now
  shows in the notification inbox (`NotificationService`, type `PRICE_ALERT`),
  even when the alert asked for `TELEGRAM` only. A Telegram-only alert whose
  message was sent stays out of the inbox, as before.

## How clients use it

Offer Telegram for an alert only once the user has linked Telegram, and send
them to link it in their account settings otherwise:

```http
POST https://<api-host>/alerts.v1.PriceAlertService/CreateAlert
Content-Type: application/json

{"symbolId": 1, "direction": "ABOVE", "priceTicks": "100000000000000", "channels": ["IN_APP", "TELEGRAM"]}
```

Without a linked Telegram account the answer is:

```json
{"code": "failed_precondition", "message": "no Telegram account is linked; link Telegram in the account settings or choose IN_APP only", "details": [{"type": "alerts.v1.ErrorDetail", "value": "CA0"}]}
```

`TELEGRAM_NOT_LINKED` is enum value 13 and `TELEGRAM_UNAVAILABLE` is 14. For
`TELEGRAM_NOT_LINKED`, retrying does not help until the user links Telegram; for
`TELEGRAM_UNAVAILABLE`, do not offer Telegram at all. To keep the alert without
Telegram, send `channels: ["IN_APP"]`. After unlinking Telegram, change an alert's channels to
`["IN_APP"]` in the same `UpdateAlert` to change it further.

## Migration

1. Handle `FAILED_PRECONDITION` with `TELEGRAM_NOT_LINKED` from `CreateAlert`
   and `UpdateAlert`: tell the user to link Telegram, or offer the alert
   without Telegram. A client that only ever sends `IN_APP` sees no change.
2. Handle `FAILED_PRECONDITION` with `TELEGRAM_UNAVAILABLE` the same way, but
   without asking the user to link Telegram: Telegram alerts are not offered
   in that environment, so offer the alert in-app only.
3. A notification inbox can now hold a `PRICE_ALERT` notification of an alert
   that asked for `TELEGRAM` only; show it like any other price alert.
