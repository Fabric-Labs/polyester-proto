## What and why

Reward awards now include optional `revealed_at` and `delivery_seen_at` timestamps shared across the recipient's sessions and devices. `AcknowledgeMyRewardAward` records these independent marks so a new browser does not replay already viewed reward dialogs.

## How clients use it

Use a session token for the owning root account. No account selector or step-up token is accepted.

```http
POST /rewards.v1.RewardCampaignService/AcknowledgeMyRewardAward
Content-Type: application/json
Authorization: Bearer <session-token>

{"awardId":"00000000-0000-0000-0000-000000000001","revealed":true}
```

REST: `POST /v1/rewards/awards/{award_id}/acknowledge`, with the same JSON body; the path-bound `awardId` may be omitted from the body. Send `deliverySeen: true` after showing delivery of a paid award. Both marks may be sent together after payment. At least one must be true. An early delivery mark fails the entire call with `failed_precondition` (HTTP 412 on REST); another account's award returns `not_found`. False leaves an existing mark unchanged.

The response contains the current `award`. First acknowledgement timestamps are assigned by the service and never overwritten by retries. Fulfillment state and revision are unchanged. `ListMyRewardAwards` returns both timestamps, absent until acknowledged, in the existing newest-first order (publication time then award ID). Pagination is unchanged: limit defaults to 50, maximum 100; page tokens are opaque, exclusive and account-bound. Timestamps use the standard Protobuf Timestamp representation (RFC 3339 strings in JSON).

## Migration

Use the returned timestamps to gate reveal and delivery dialogs instead of relying on per-device storage. Acknowledge after the corresponding dialog has been shown; retry failed calls. Existing awards remain unseen until explicitly acknowledged. The app may submit its known local marks once on first load after deployment, then use the returned server state. Previously built clients continue to work; adopting the new fields and RPC is required to suppress cross-device replays. A fresh list on page load or focus also observes acknowledgements made in another session, even when `awardsMayChange` is false.
