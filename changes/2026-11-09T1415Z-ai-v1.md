## What and why

**Availability:** devnet only. Not available on testnet yet; the service isn't deployed or routed there.

The assistant can now show how the user's balances and account value changed
over time, and the user's transfer history. When a user asks "how did my
balance change this week?" or "can you see my transfers?", the run shows a
chart or a table next to the assistant's answer, with the exact values the
ledger API returned.

- New `View` case `balance_history_chart` (field 9), message
  `BalanceHistoryChart { ledger.read.v1.GetBalanceHistoryResponse history = 1; }`:
  each asset's balance per account bucket over the window. A series whose every
  point is zero is left out.
- New `View` case `equity_history_chart` (field 10), message
  `EquityHistoryChart { ledger.read.v1.GetEquityHistorySeriesResponse history = 1; }`:
  the value of the holdings in USDT over the window, per account bucket or per
  asset. `btc_prices_q` is not set.
- New `View` case `transfers_table` (field 11), message
  `TransfersTable { repeated ledger.read.v1.TransferRow transfers = 1; bool truncated = 2; }`:
  the user's settled transfer legs, newest first. `link_id` is not set, and
  `ts_us` has millisecond precision.

Each view carries the ledger read API's own messages for the user's trading
account, so a client renders them with the code it already has for the
`GetBalanceHistory`, `GetEquityHistorySeries` and `ListTransfers` responses.

## How clients use it

Watch a run as before; a chart or table arrives as a `view` event after the
tool call that produced it:

```text
POST /ai.v1.AssistantService/WatchRun
{"runId": "6349022007070785130", "afterSeq": "0"}

{"event": {"seq": "1", "toolStarted": {"toolCallId": "call-1", "name": "get_equity_history", "input": {"range": "7d"}}}}
{"event": {"seq": "2", "toolFinished": {"toolCallId": "call-1", "name": "get_equity_history", "ok": true}}}
{"event": {"seq": "3", "view": {"equityHistoryChart": {"history": {"range": "DAY_7", "bucket": "15m", "startTsSec": 1793810700, "endTsSec": 1794231900, "quoteAsset": "USDT", "points": 469, "series": [{"account": {"accountCode": 301, "name": "trading"}, "equityQ": ["0", "…"]}]}}}}}
```

- Point `i` of every series is at
  `start_ts_sec + i × (end_ts_sec − start_ts_sec) / (points − 1)`; the last
  point is at `end_ts_sec`.
- `balance_q` is in asset units scaled by 1e7, `equity_q` in USDT scaled by
  1e4, and transfer amounts at the fixed 18-decimal ledger scale, as in the
  ledger read API. Resolve `asset_id` with `GetSpotConfig`.
- The account's total equity at a point is the sum of every equity series at
  that point.
- A transfers table holds at most 100 legs; `truncated` is true when more
  matched. Only settled transfers are listed: a deposit or withdrawal still in
  progress is in the user's funding history, not here.

## Migration

None: the view cases and messages are new. A client built on the previous
contract skips an unknown `View` case, as the contract already requires.
