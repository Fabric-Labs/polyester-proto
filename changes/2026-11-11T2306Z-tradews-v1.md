## What and why

A correction to the descriptions in the trading WebSocket SBE schema
(`tradews.xml`, schema 7). Nothing on the wire changes: no field, template,
enum value, layout or version.

- `marketMaxSlippageTicks` on `CreateOrder` said both "non-negative" and
  "positive". It is positive: an optional MARKET slippage limit as an
  absolute price delta in 1e-9 quote-unit ticks. A value of 0 or less is
  refused with `MAX_SLIPPAGE_INVALID`, and null uses the pair default. The
  batch-item field already said so.

## How clients use it

Nothing changes in how clients call: send a positive `marketMaxSlippageTicks`,
or leave it null for the pair default, as before.

```text
CreateOrder (template 2): marketMaxSlippageTicks = 500   // 500 ticks = 0.0000005 quote units of price delta
CreateOrder (template 2): marketMaxSlippageTicks = null  // pair default
```

## Migration

None: the descriptions change, not the contract. A client that sent 0 was
already refused with `MAX_SLIPPAGE_INVALID`.
