## What and why

REST reference descriptions now use the enum names returned in REST JSON. For example, trigger-event descriptions refer to `FIRE_REFUSED`, attached-risk descriptions refer to `OCO`, and trigger-failure descriptions refer to `INDEX_PRICE_UNAVAILABLE`. This is a description-only correction: fields, enum lists, requests, responses, and wire behavior do not change. ConnectRPC reference descriptions are unchanged.

## How clients use it

Continue calling the same APIs. For example, `GET /v1/triggers/<trigger-id>/events` returns trigger events whose REST event type can be:

```json
{"eventType": "FIRE_REFUSED"}
```

The equivalent ConnectRPC method, `/triggers.v1.TriggersService/ListTriggerEvents`, continues to use the prefixed spelling `EVENT_FIRE_REFUSED`.

## Migration

None. Existing clients continue to encode and decode the same values. Enum names intentionally preserved by an API remain unchanged.
