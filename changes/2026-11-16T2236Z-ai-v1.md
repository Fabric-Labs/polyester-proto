## What and why

**Availability:** devnet only.

A user can add their own OpenAI API key and use the assistant on it, billed to
their OpenAI account, instead of the assistant's own allowance.

- Three new RPCs on `AssistantService`, each for a signed-in session only (an
  API key is refused with `PERMISSION_DENIED`):
  - `SetModelKey(api_key)`: checks the key with one small OpenAI request on
    the assistant's model, then saves it encrypted, replacing any earlier key.
    The key is never returned.
  - `GetModelKey()`: the key's status, or no `key` when there is none.
  - `DeleteModelKey()`: deletes it; deleting when there is none succeeds.
- New message `ModelKey`: `suffix` (the key's last four characters),
  `added_at`, `last_check` (`ModelKeyCheck`) and `checked_at`.
- New enum `ModelKeyCheck`: `KEY_VALID`, `KEY_REJECTED`, `KEY_NO_QUOTA`,
  `KEY_MODEL_UNAVAILABLE`.
- New `ErrorCode` values for `SetModelKey`, each with `FAILED_PRECONDITION`
  and nothing saved: `MODEL_KEY_REJECTED` (wrong, revoked or disabled key),
  `MODEL_KEY_NO_QUOTA` (the OpenAI account has no quota left),
  `MODEL_KEY_MODEL_UNAVAILABLE` (the key cannot use the assistant's model).
  When OpenAI cannot be reached, the call fails with `UNAVAILABLE` and
  `SERVICE_UNAVAILABLE`.
- New `FailureCategory` value `MODEL_KEY_REFUSED` on `RunFailed`: a run that
  used the user's key ended because OpenAI refused it for any of the run's
  requests (its answer, a check it makes, or a web search), or because the
  run's key was deleted or replaced before the run could finish with it. `RunFailed.message` says why and how to fix or
  remove the key; `GetModelKey` shows the reason in `last_check`. A run never
  falls back to the assistant's own allowance.

## How clients use it

```http
POST /ai.v1.AssistantService/SetModelKey
{"apiKey": "sk-proj-..."}
→ {"key": {"suffix": "x7Qa", "addedAt": "2026-11-17T09:00:00Z", "lastCheck": "KEY_VALID", "checkedAt": "2026-11-17T09:00:00Z"}}

POST /ai.v1.AssistantService/GetModelKey
{}
→ {"key": {...}}   or   {}

POST /ai.v1.AssistantService/DeleteModelKey
{}
→ {}
```

`api_key` must be an OpenAI secret key: `sk-` followed by 20 to 300
letters, digits, `-` or `_` (`INVALID_ARGUMENT` otherwise). Once a key is
saved, every message the user sends, on any channel, runs on it. A run uses
only the key saved when its message was sent: replacing or deleting the key
never moves a run to another key or to the assistant's allowance, so it
finishes on its key or ends `MODEL_KEY_REFUSED`. The per-run limits and request rate
limits still apply. `SetModelKey` shares the message rate limit, because it
sends a request to OpenAI.

## Migration

None: the RPCs, messages and enum values are new. Clients that switch on
`FailureCategory` or `ErrorCode` should handle the new values, or treat them as
unknown.
