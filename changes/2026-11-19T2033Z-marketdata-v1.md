## What and why

`GetCandlesColumnsResponse` gains `is_closed` (field 17), a column of
closed-bucket flags aligned with `ts_sec`: one entry per row, oldest-first.
It is true when the bucket is closed; with `include_incomplete=false` every
row is closed. With `include_incomplete=true`, the current open candle is
appended last and is the only row that reads false.

Until now only the row form, `GetCandles`, carried `CandlePoint.is_closed`,
so a client of the columnar form could not tell whether the newest row was
still forming. Both forms now report the same value for the same bucket.

Reference rows (`reference_ts_sec` and the other `reference_*` columns) are
always closed buckets, also with `include_incomplete=true`, so they have no
flag of their own.

## How clients use it

`GetCandlesColumns` is ConnectRPC only; it has no REST route.

```bash
curl -sS https://<api-host>/marketdata.v1.MarketDataService/GetCandlesColumns \
  -H 'Content-Type: application/json' \
  -d '{"symbolId": 1, "timeframe": "MIN_1", "limit": 2, "includeIncomplete": true}'
```

```json
{
  "symbolId": 1,
  "timeframe": "MIN_1",
  "tsSec": ["1795111380", "1795111440", "1795111500"],
  "isClosed": [true, true, false],
  ...
}
```

Read `isClosed[i]` together with `tsSec[i]`. The open candle does not count
toward `limit`, and it appears only on the first page, never on pages
requested with `page_token`.

## Migration

None: the field is new. Clients that inferred the closed state from
`include_incomplete` can read `is_closed` instead.
