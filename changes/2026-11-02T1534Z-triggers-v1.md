## What and why

Trigger reads now keep their read-your-write promise after every trigger
change. Once `ModifyTrigger`, `PauseTrigger` or `ResumeTrigger` has answered,
`GetTrigger` and `ListTriggers` return the trigger as changed, or a retryable
`UNAVAILABLE` until they can. Before, a read right after such an answer could
rarely return the trigger's previous state, for example the old trigger
price, with a success status.

Released in 9.2.1. Not in 9.2.

## How clients use it

Nothing new to call. Retry `UNAVAILABLE` on `GetTrigger` and `ListTriggers`,
with the same request and a short backoff. The error is:

- ConnectRPC: code `unavailable`, an `orders.v1.ErrorDetail` with
  `ERROR_CODE_UNAVAILABLE`, and the message "Triggers are catching up with
  recent activity; retry the request."
- REST (`GET /v1/triggers/{trigger_id}`, `GET /v1/triggers`): HTTP 503,
  `application/problem+json`, `"code": "UNAVAILABLE"`.

ConnectRPC JSON carries the trigger ID as a decimal string of the `fixed64`.
REST paths take its base58 public ID: here `1234567890123456789` is
`3sDK21t5nHJ`.

```bash
# ConnectRPC, right after a ModifyTrigger answer:
curl -sS https://<api-host>/triggers.v1.TriggersService/GetTrigger \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer <token>' \
  -d '{"triggerId": "1234567890123456789"}'
# {"code": "unavailable",
#  "message": "Triggers are catching up with recent activity; retry the request.", ...}

# REST:
curl -sS https://<api-host>/v1/triggers/3sDK21t5nHJ \
  -H 'Authorization: Bearer <token>'
# HTTP 503  {"status": 503, "code": "UNAVAILABLE", "detail": "Triggers are catching up ..."}
```

A successful retry returns the trigger with the change applied, never the
state from before the answered change.

## Migration

None for clients that already retry `UNAVAILABLE` on trigger reads. These
reads could already answer it, for example right after a create. Clients
that treated a 503 from these reads as a failure will now see it slightly
more often, right after a modify, pause or resume. They should retry it.
