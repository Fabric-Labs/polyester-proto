## What and why

A conversation now says which account its latest message used, so a client
that opens it, on any device, can select that account again. Before, a
reopened conversation fell back to the client's default account: a follow-up
such as "cancel that order" was refused, and a balance question was answered
for the main account instead of the subaccount the conversation was about.

- **`ConversationAccount`** (new message) is the account selection of the
  conversation's latest message, from any client: its `account_selection` and
  its `subaccount_id`, exactly as that message's `SendMessageRequest` named
  them. `subaccount_id` is omitted for the main account and when
  `account_selection` is `ACCOUNT_SELECTION_NONE`.
- **`ListMessagesResponse.last_account`** (new field 3) is that account as it
  stands when the conversation is read, on every page. Select it when the
  conversation opens.
- **`Conversation.last_account`** (new field 6) is the same account as of the
  `ListConversations` call, for showing each conversation in a list. A message
  sent since, from another tab or device, may have selected another account,
  so restore the account from `ListMessages`, not from the list.
- Both report the last choice only. Every message still names its own account,
  and an omitted `subaccount_id` still means the main account.

## How clients use it

Open a conversation with `ListMessages` as before, and read the new field:

```http
POST /ai.v1.AssistantService/ListMessages
Content-Type: application/json
Connect-Protocol-Version: 1

{"conversationId": "1234", "limit": 50}
```

The response:

```json
{
  "messages": [],
  "nextPageToken": "",
  "lastAccount": { "subaccountId": "5678" }
}
```

(`messages` is shortened here.) Select that account in the account picker, and
send the next `SendMessage` with the same `subaccount_id` and
`account_selection`. `"lastAccount": {}` means the main account;
`{"accountSelection": "ACCOUNT_SELECTION_NONE"}` means no account.

`ListConversations` returns the same field on each conversation, for example
to show which account each conversation is on:

```json
{
  "conversationId": "1234",
  "title": "Buy 0.1 SOL",
  "createdAt": "2026-11-21T17:10:00Z",
  "updatedAt": "2026-11-21T17:15:00Z",
  "lastAccount": { "subaccountId": "5678" }
}
```

## Migration

None: the fields are new. Clients that ignore them keep working.
