## What and why

**Availability:** devnet only. Not available on testnet yet; the service isn't deployed or routed there.

The assistant can now offer the user a button that takes them to a place in
the app, such as the Subaccounts page, the settings or the deposit dialog,
when they ask where or how to do something there ("How do I create a
subaccount?"). The client declares the places it can take the user to with
each message; the assistant picks among them by id, and the client maps each id
to its own page or dialog. No link or route is ever sent by the assistant.

- `SendMessageRequest.destinations` (new, `repeated Destination`, at most 100,
  each `id` at most once): the places the run may suggest. Omit it, as a client
  that cannot navigate does, and the run suggests nothing.
- `Destination` (new): `id` (lowercase letters, digits and hyphens, 1 to 64
  characters, for example `page-subaccounts`), `title` (1 to 80 characters) and
  `description` (at most 200 characters: what the user does there, in a few
  words or keywords). The assistant reads the title and description to choose.
- `RunEvent.destinations_suggested` (new, `DestinationsSuggested`): the
  `tool_call_id` of the `suggest_destinations` call and its 1 to 3
  `destination_ids`, most relevant first, each one the run's message declared.
  It follows that call's `ToolFinished` event (`ok` true), and replaying the run
  returns it again.

## How clients use it

Declare the destinations with each message, then render a button for each id
a `destinationsSuggested` event names:

```text
POST /ai.v1.AssistantService/SendMessage
{"text": "How do I create a subaccount?", "idempotencyKey": "msg-7f3c",
 "destinations": [
   {"id": "page-subaccounts", "title": "Subaccounts", "description": "sub accounts, accounts, account management"},
   {"id": "page-settings", "title": "Settings", "description": "account settings, preferences"},
   {"id": "action-deposit", "title": "Deposit Funds", "description": "deposit, add funds, fund account"}
 ]}

POST /ai.v1.AssistantService/WatchRun
{"runId": "6349022007070785130", "afterSeq": "0"}

{"event": {"seq": "4", "toolStarted": {"toolCallId": "call_1", "name": "suggest_destinations", "input": {"ids": ["page-subaccounts"]}}}}
{"event": {"seq": "5", "toolFinished": {"toolCallId": "call_1", "name": "suggest_destinations", "ok": true}}}
{"event": {"seq": "6", "destinationsSuggested": {"toolCallId": "call_1", "destinationIds": ["page-subaccounts"]}}}
```

- Send the same set with every message of a conversation. Their order does
  not matter.
- The destinations are part of the request the idempotency key covers: retry a
  message with the same destinations, in any order.
- An invalid list (a malformed id, an empty title, a repeated id, more than
  100) is `INVALID_ARGUMENT`, and nothing is recorded.
- A replay returns the same `destinationsSuggested` events. Skip an id the
  client no longer knows, for example after a release removed that page.
- The answer text never carries links to app pages: the buttons do. Links to
  documentation pages stay in the text.

## Migration

None: the field and the event are new. A client that sends no destinations
gets no suggestions, and a client that does not recognize the
`destinationsSuggested` event skips it, as the `RunEvent` contract says.
