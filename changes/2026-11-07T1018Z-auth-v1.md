## What and why

`AuthErrorCode` gains `AUTH_WALLET_ALREADY_LINKED` (55), and `LoginWithWallet`
answers it instead of an internal error in one case. The signed login is valid,
but no account uses the submitted account address, and the wallet that signed it
is already linked to another account. Wallets are not moved between accounts,
and no account, session or binding is created, so nothing changes. The case
arises, for example, when a wallet that signed up through its smart account
later logs in with its own wallet address, or the reverse.

Logging in with the address the wallet's account already uses still succeeds.

## How clients use it

`POST /auth.v1.AuthService/LoginWithWallet` now answers HTTP 409:

```json
{
  "code": "already_exists",
  "message": "this wallet is already linked to another account; log in with the account address it already uses",
  "details": [
    {
      "type": "auth.v1.AuthErrorDetail",
      "debug": {
        "code": "AUTH_WALLET_ALREADY_LINKED",
        "message": "this wallet is already linked to another account; log in with the account address it already uses"
      }
    }
  ]
}
```

REST `POST /v1/auth/login/wallet` answers HTTP 409 `application/problem+json`:

```json
{
  "status": 409,
  "code": "AUTH_WALLET_ALREADY_LINKED",
  "title": "Wallet Already Linked",
  "type": "https://polyester.dev/problems/auth-wallet-already-linked",
  "detail": "this wallet is already linked to another account; log in with the account address it already uses"
}
```

Retrying the same request answers the same refusal. To log in, request a new
challenge for the account address the wallet already uses.

## Migration

None: the new code replaces an internal error that clients could not act on.
Clients that switch on `AuthErrorCode` should show the message and offer the
login with the wallet's existing account address.
