## What and why

A ladder is refused whole, with `LADDER_LEVEL_REJECTED`, when one of its
orders can't be placed. The reason that order can't be placed is now returned
as data. `orders.v1.ErrorDetail` has two new fields:

- `cause_code` (`ErrorCode`): the code the refused order would return as a
  single order, for example `MAX_OPEN_ORDERS_PER_PAIR`, `PRICE_BAND_VIOLATION`
  or `INSUFFICIENT_FUNDS`.
- `level_index` (optional `uint32`): the refused order's zero-based index
  among the ladder's orders. It is the `i` of the violation path
  `trigger.strategy.ladder.levels[i]`, so `0` is the first order.

Before, the order's code appeared only in the message ("Ladder order 1 can't
be placed (MAX_OPEN_ORDERS_PER_PAIR)…") and as the violation's `rule_id`.
Clients can now show the same text they show for that code on a single order.
The top-level `code` stays `LADDER_LEVEL_REJECTED`. Every other error leaves
`cause_code` unspecified and omits `level_index`.

## How clients use it

Create a ladder with `CreateTrigger`. When the ladder is refused for one of
its orders, read `cause_code` and `level_index` from the error's
`orders.v1.ErrorDetail`. Over REST, read `causeCode` and `levelIndex` from the
problem body.

```http
POST /triggers.v1.TriggersService/CreateTrigger
{"trigger":{"symbolId":1,"qtyScaled":"200000000","ladder":{"side":"SELL","priceMinTicks":"50000000","priceMaxTicks":"100000000","levels":2}}}

400 invalid_argument, details[orders.v1.ErrorDetail]:
{"code":"ERROR_CODE_LADDER_LEVEL_REJECTED","causeCode":"ERROR_CODE_MAX_OPEN_ORDERS_PER_PAIR","levelIndex":0,
 "violations":[{"fieldPath":"trigger.strategy.ladder.levels[0]","ruleId":"MAX_OPEN_ORDERS_PER_PAIR","message":"..."}]}
```

```http
POST /v1/triggers
{"trigger":{"symbol":"BTC-USDT","qty":"2","ladder":{"side":"SELL","priceMin":"50","priceMax":"100","levels":2}}}

HTTP/1.1 400 Bad Request
Content-Type: application/problem+json

{"code":"LADDER_LEVEL_REJECTED","causeCode":"MAX_OPEN_ORDERS_PER_PAIR","levelIndex":0,
 "violations":[{"fieldPath":"trigger.ladder.levels[0]","ruleId":"MAX_OPEN_ORDERS_PER_PAIR","message":"..."}], ...}
```

A ladder order refused because the account's request quota is spent keeps
its rate-limit answer: over ConnectRPC `resource_exhausted`, with
`LADDER_LEVEL_REJECTED`, `cause_code` `RATE_LIMIT_EXCEEDED`, `level_index`,
and `rate_limit`; over REST `429` `RATE_LIMIT_EXCEEDED`, with neither field.

## Migration

None: the fields are new and optional, and every existing field keeps its
meaning. A client that parsed the message text or read `violations[0].rule_id`
for the order's code can read `cause_code` instead.
