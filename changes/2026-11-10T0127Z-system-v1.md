## What and why

New public `system.v1.SystemService` with one RPC, `GetVersion`. It returns
the exact build an environment serves: its version, the full source revision
of that build, and the environment that answered (`devnet`, `testnet`,
`mainnet`, or `local` for a development stack). Clients and support tools can
confirm which build they talk to, for example after an announced upgrade. It
needs no authentication.

A release reports its version as `MAJOR.MINOR.PATCH`, such as `0.10.0` (`0.x`
until mainnet starts at `1.0.0`). A build made after a release, which devnet
may run, appends the number of source revisions since that release and `g`
with the first 12 hexadecimal digits of its own revision:
`0.10.0-12-g4e21a2f09670` is 12 revisions after release `0.10.0`.

## How clients use it

REST:

```http
GET /v1/system/version
```

ConnectRPC, POST or cacheable GET:

```http
POST /system.v1.SystemService/GetVersion
Content-Type: application/json

{}
```

Response:

```json
{
  "version": "0.10.0",
  "commit": "4e21a2f0967068fc944f5229eead01985df301b9",
  "environment": "testnet"
}
```

The answer changes only when the environment deploys a new build; it is
cacheable for a few seconds. Compare the part before the first `-` to tell
which release a build follows; do not parse the rest as a semantic-version
pre-release. Calls count against the public per-IP read
budget.

## Migration

None: the service is new.
