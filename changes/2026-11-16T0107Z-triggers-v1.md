## What and why

A new public code, `ERROR_CODE_CLIENT_LIST_ID_INVALID` (318), names an OCO
client list ID that breaks its rule: 1 to 36 characters of letters, digits,
period, underscore, colon, slash or hyphen. An empty ID, a 37-character ID or
one with any other character is refused with it everywhere the ID is read,
so a client matches one code for the same mistake on every surface:

| Surface | Before | Now |
| --- | --- | --- |
| ConnectRPC `CreateOco` | `ERROR_CODE_VALIDATION_ERROR` | `ERROR_CODE_CLIENT_LIST_ID_INVALID` |
| REST `POST /v1/triggers/oco` | `VALIDATION_ERROR` | `CLIENT_LIST_ID_INVALID` |
| ConnectRPC `ListTriggers` `client_list_id` filter | no typed code | `ERROR_CODE_CLIENT_LIST_ID_INVALID` |
| REST `GET /v1/triggers?clientListId=` | `VALIDATION_ERROR` | `CLIENT_LIST_ID_INVALID` |
| Trading WebSocket `CreateOco` (SBE and protobuf) | `BAD_REQUEST` (1) | `CLIENT_LIST_ID_INVALID` (318) |

Every other trigger and order identifier already had its own code
(`ERROR_CODE_CLIENT_TRIGGER_ID_INVALID`, `ERROR_CODE_INVALID_CLIENT_ORDER_ID`).
The transport status is unchanged: ConnectRPC answers `INVALID_ARGUMENT` and
REST answers HTTP 400, with the same field violation as before. The SBE
trading WebSocket schema adds the `RejectCode` value `CLIENT_LIST_ID_INVALID`
(318) at the same schema version, and its `semanticVersion` goes from 2.4.0 to
2.5.0.

## How clients use it

A client list ID with a character outside the set:

```http
POST /triggers.v1.TriggersService/CreateOco
Content-Type: application/json

{"oco":{"symbolId":1,"side":"SELL","clientListId":"oco+1","qtyScaled":"1000000","takeProfit":{"triggerPriceTicks":"80000000000000","child":{"marketIoc":{}}},"stopLoss":{"triggerPriceTicks":"60000000000000","child":{"marketIoc":{}}}}}
```

answers `invalid_argument` with an `orders.v1.ErrorDetail` whose `code` is
`ERROR_CODE_CLIENT_LIST_ID_INVALID` and whose violation names
`oco.client_list_id`. REST answers the same request on
`POST /v1/triggers/oco` with HTTP 400, `"code":"CLIENT_LIST_ID_INVALID"` and
a violation on `oco.clientListId`.

`GET /v1/triggers?clientListId=` (a present empty filter) answers HTTP 400
with `"code":"CLIENT_LIST_ID_INVALID"`, and `ListTriggers` with an empty
`client_list_id` answers `invalid_argument` with the same typed code.

## Migration

1. A client that matched `ERROR_CODE_VALIDATION_ERROR` (REST
   `VALIDATION_ERROR`) for an invalid client list ID on `CreateOco` or the
   `ListTriggers` filter must match `ERROR_CODE_CLIENT_LIST_ID_INVALID` (REST
   `CLIENT_LIST_ID_INVALID`) instead.
2. A trading WebSocket client that matched `BAD_REQUEST` for a `CreateOco`
   refused for its client list ID must match `CLIENT_LIST_ID_INVALID` (318).
   An SBE client built on `semanticVersion` 2.4.0 still decodes every frame;
   it reads 318 as an unknown `RejectCode` value until it updates.

Field violations, HTTP statuses and ConnectRPC status codes are unchanged.
