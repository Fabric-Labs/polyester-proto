## What and why

`orders.v1.Order.orig_qty_scaled` documents every case in which it is 0.
The field itself is unchanged.

Before, the documentation named only the placeholder replacement order of a
batch item refused when it applied. An order can also end with
`orig_qty_scaled` equal to its filled quantity, `cum_qty_scaled`, so 0
when it had no fill:

- self-trade prevention decremented a base-quantity order to its end
  (`CANCEL_REASON_STP_DECREMENT`);
- a modify set its total quantity at or below its filled quantity
  (`CANCEL_REASON_QTY_AT_OR_BELOW_FILLED`).

A quote-sized buy never ends at 0 through STP: with no fill it keeps its
original quantity. A working order always has it above 0. Clients that
treated 0 as missing or invalid data misread these ended orders.

## How clients use it

Read `orig_qty_scaled` as a quantity that may be 0, scaled by the pair's
`base_quantity_scale`, on every order the reads return:

- `/orders.v1.OrdersReadService/GetOrder`, `GetOrderHistory` and
  `GetOpenOrders`;
- REST `GET /v1/spot/orders/{order_id}` and `GET /v1/orders/history`, as
  `origQty`;
- the private WebSocket's order lists (`privatews.v1`);
- the assistant's order results.

Connect JSON omits zero-valued fields, so a 0 arrives as an absent
`origQtyScaled` and `cumQtyScaled`. Read an absent value as 0:

```json
POST /orders.v1.OrdersReadService/GetOrder
{"orderId": "4611686018427388929"}
→ {"order": {"orderId": "4611686018427388929",
             "status": "CANCELED",
             "cancelReason": "CANCEL_REASON_STP_DECREMENT", ...}}
```

REST always emits `origQty` and `cumQty`, as decimal strings in base asset
units. The same order, addressed by its base58 ID:

```json
GET /v1/spot/orders/Bht3tfQZvRn
→ {"order": {"orderId": "Bht3tfQZvRn",
             "status": "CANCELED",
             "cancelReason": "STP_DECREMENT",
             "origQty": "0", "cumQty": "0", ...}}
```

A 0 on a canceled order with one of those two reasons means it ended with
nothing filled. It is not a decoding failure.

## Migration

None on the wire: the field, its type and its encoding are unchanged.

Clients that map `orig_qty_scaled` = 0 to "absent" or "invalid" should
treat it as a real 0 on ended orders. Treat only a negative value as
malformed.
