## What and why

Every REST error body (`application/problem+json`) now has the same `type`
for the same `code` on every endpoint:
`https://polyester.dev/problems/` followed by the code in lowercase, with
hyphens for underscores. Before, some endpoints used the code as written, so
one refusal had two types. For example, `AUTH_SESSION_KIND_NOT_ALLOWED`
answered `https://polyester.dev/problems/AUTH_SESSION_KIND_NOT_ALLOWED` on the
daily claim endpoints and `https://polyester.dev/problems/auth-session-kind-not-allowed`
on the VIP and API key endpoints.

The REST endpoints whose `type` changes:

- Daily claim (`/v1/trading/daily-claim`, `/v1/trading/daily-claim/claim`):
  every code.
- QuickSwap and QuickSwap broker (`/v1/quickswaps`, `/v1/quickswap/...`):
  every code, for example `ADDRESS_UNAVAILABLE` now answers
  `https://polyester.dev/problems/address-unavailable`.
- Chain analytics, deposit addresses, chain flows and the deposit and
  withdraw configuration (`/v1/chain/analytics/...`,
  `/v1/chain/deposit-addresses...`, `/v1/chain/flows...`,
  `/v1/chain/deposit-withdraw/config`): every code, for example
  `invalid_request` now answers `https://polyester.dev/problems/invalid-request`.
- Trading withdrawals and internal transfers
  (`/v1/chain/trading-withdraws...`, `/v1/trading/internal-transfers...`):
  `invalid_request`, `request_too_large`, `internal_error` and
  `upstream_error`. Their domain codes already used the canonical form.
- Collaboration whiteboards (`/v1/collab/whiteboards/...`): error bodies had
  no `type`; they now carry one, for example `PERMISSION_DENIED` answers
  `https://polyester.dev/problems/permission-denied`. This change is additive.

Every REST endpoint not listed above already answered the canonical form and
is unchanged. The REST Problem schemas of orders, triggers and QuickSwap now
describe the format of `type`. The `code` field, HTTP statuses and
ConnectRPC errors do not change.

## How clients use it

Branch on `code`; `type` is its URI form and is the same on every endpoint.
A daily claim request without credentials:

```bash
curl -sS https://<api-host>/v1/trading/daily-claim
```

```json
{
  "type": "https://polyester.dev/problems/unauthenticated",
  "title": "Unauthorized",
  "status": 401,
  "detail": "unauthenticated",
  "code": "UNAUTHENTICATED"
}
```

## Migration

Clients that compare `type` with a value built from the code as written must
lowercase it and replace underscores with hyphens, or compare `code` instead.
Clients that read only `code`, `status` or `detail` need no change, and
neither do whiteboard clients, for which `type` is a new field.
