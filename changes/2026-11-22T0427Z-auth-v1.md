## What and why

Strategy-bot keys that `SetStrategyBotAccess` newly issues no longer get `READ_PNL`. Their API policy trades spot and reads the sub-account's orders and balances (`TRADE_SPOT`, `READ_SPOT`, `READ_BALANCES`), and nothing else. The bot's page reads profit and loss with the user's own session, so the bot key doesn't need the permission.

Only the RPC's comment changes. No message, field or enum value changes, and `READ_PNL` stays a valid policy action everywhere else.

## How clients use it

Call `SetStrategyBotAccess` as before:

```http
POST /auth.v1.ApiKeyService/SetStrategyBotAccess
{"deploy_operation_id": "deploy-1842", "subaccount_id": "9223372036854775809", "public_key_ed25519": "AAECAwQFBgcICQoLDA0ODxAREhMUFRYXGBkaGxwdHh8=", "strategy_bot_id": "9223372036854775810", "limits": {"spot_market_scope": "ALLOWLIST", "spot_markets": [{"symbol_id": 1}], "max_order_notional": "5000000000", "max_open_orders": 20}}
```

A key issued after this change gets `PermissionDenied` on profit and loss reads, as any key without `READ_PNL` does. An exact retry under the same `deploy_operation_id` can return a key issued before the change. That key's stored grant keeps the permissions it was issued with until the access is ended with `EndStrategyBotAccess` and set again under a new `deploy_operation_id`. To read profit and loss, use a signed-in session or a key whose policy allows `READ_PNL`.

## Migration

None. Clients don't change. A strategy bot's key never needed `READ_PNL`.
