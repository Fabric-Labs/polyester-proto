## What and why

Backtests now run past a market's listing on its index price. A backtest
replays each market's one continuous price series: external reference prices
from before its listing, and the market's index price from the listing on.
Before, every backtest window ended at the listing.

So `NotBacktestableReason.NO_REFERENCE_CANDLES` now means a market the bot
needs has no available price history at all, neither reference nor index, for
a timeframe the bot reads. Only `StartBacktest` answers it, as the reason of
its `NOT_BACKTESTABLE` error: a backtest that started never ends with it, so
`Backtest.not_backtestable_reason` never holds it on a new backtest. A window
that turns out empty while a backtest runs is retried, then fails as a backtest
that couldn't finish. A requested window without data for a market that has
history elsewhere answers `WINDOW_HAS_NO_DATA` instead, which is not a reason
to deploy without a backtest. Only the comments of these enum values change;
the values and the wire are unchanged.

A finished report's `fidelity` names where each market's prices switch from
reference to index, missing buckets of either series are reported in
`data_gaps`, and a minute-level bot's warning names the window the backtest
covered.

## How clients use it

```http
POST /strategies.v1.StrategiesService/StartBacktest
{"versionId": "sha256:...", "idempotencyKey": "..."}
```

An unset `start_time` and `end_time` still mean the most recent 365 days of
available data, which can now reach past the listing. A refusal for a market
without any history carries this `ErrorDetail`:

```json
{"code": "NOT_BACKTESTABLE", "notBacktestableReason": "NO_REFERENCE_CANDLES"}
```

## Migration

None: the enum values and their wire are unchanged. A client that showed
`NO_REFERENCE_CANDLES` as "no prices before the listing" should show it as "no
price history for this market".
