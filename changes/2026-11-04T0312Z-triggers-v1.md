## What and why

Modifying a trigger with an off-tick trigger or activation price returns `PRICE_TICK_SIZE` with a `tick_size` field violation, including when the request omits the optional symbol. The trigger keeps its previous values. REST trigger error explanations use REST field names and decimal price tick sizes.

## How clients use it

For `PUT /v1/triggers/{triggerId}`, inspect `code` and `violations[].fieldPath` / `ruleId`. An off-tick `triggerPrice` returns `PRICE_TICK_SIZE` with `triggerPrice` / `tick_size`; an off-tick `activationPrice` names `activationPrice`. For example, a price of `70000.005` on a `0.01` price grid is refused.

```http
PUT /v1/triggers/{triggerId}
Content-Type: application/json

{"triggerPrice":"70000.005"}
```

```http
POST /triggers.v1.TriggersService/ModifyTrigger
Content-Type: application/json

{"triggerId":"123","triggerPriceTicks":"70000005000000"}
```

For `/triggers.v1.TriggersService/ModifyTrigger`, the equivalent fields are `trigger_price_ticks` and `activation_price_ticks`. ConnectRPC retains its existing field names and scaled price units. A positive trailing distance may be off the price grid. A child limit price cannot be modified.

## Migration

None: the error code and violation shape already exist. Branch on the stable code and rule identifier; display the explanation without parsing its text.
