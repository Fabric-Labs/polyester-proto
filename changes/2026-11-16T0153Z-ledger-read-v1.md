## What and why

`LedgerReadService.ExportStatement` is removed, with `ExportStatementRequest`,
`ExportStatementResponse` and its REST route `GET /v1/statements`. Account
statements now have one API, `StatementExportService`: a whole-period
statement of one account, optionally one asset, for up to 366 days, produced
in the background as one CSV file. It offers the same account, asset and
period choices, the same columns and the same access rules: API keys need the
`READ_STATEMENTS` policy action.

A call to `ExportStatement` now answers `unimplemented`, and
`GET /v1/statements` answers `404 Not Found`. The CSV columns, documented on
`ExportStatementResponse.csv` until now, are documented on `StatementExport`.

## How clients use it

Create an export, poll it until `status` is `READY`, then download its file:

```http
POST https://<api-host>/ledger.read.v1.StatementExportService/CreateStatementExport
Content-Type: application/json

{"startTime": "2026-10-01T00:00:00Z", "endTime": "2026-11-01T00:00:00Z", "idempotencyKey": "statement-2026-10"}
```

- REST create: `POST /v1/statements/exports` with the same body.
- Poll: `GET /v1/statements/exports/{exportId}` (`GetStatementExport`).
- List: `GET /v1/statements/exports` (`ListStatementExports`), newest first.
- Download: `GET /v1/statements/exports/{exportId}/file` returns the whole
  statement as `text/csv`: the header row, then every row oldest first. It
  supports `Range` requests; `?redirect=true` answers `307` to a URL valid for
  60 seconds. A `READY` file can be downloaded for 7 days.

`subaccountId` and `assetId` select the account and asset as they did on
`ExportStatement`. A root account has at most 5 exports `QUEUED` or
`PROCESSING` at a time.

## Migration

1. Replace every `ExportStatement` call (`GET /v1/statements`) with
   `CreateStatementExport` for the same `startTime`, `endTime`, `subaccountId`
   and `assetId`, plus an `idempotencyKey` of your choice.
2. Poll `GetStatementExport` until `status` is `READY`, or handle `FAILED`
   (`failureReason`: split a `TOO_LARGE` period, retry `UNAVAILABLE` with a
   new export).
3. Download the file instead of concatenating pages. Drop the page loop, the
   `pageToken`/`Next-Page-Token` cursor and the `Statement-Complete-Through`
   header; the export's `completeThrough` is the end of what the file covers.
