## What and why

A backtest replays a reference price history that doesn't include trading
volume. A bot that reads volume, such as a candle's volume or the VWAP
indicator, would be replayed on volumes of zero and show results it would
never have had. Such a bot is now not backtested, and the reason says so.

- **New `NotBacktestableReason` value:** `READS_VOLUME` (6). `StartBacktest`
  answers `NOT_BACKTESTABLE` with it, and a backtest that finds it during
  replay ends with status `NOT_BACKTESTABLE` and this reason.
- Like every reason a bot isn't backtested, it lets the bot be deployed
  without a backtest: the deploy proposal carries the reason, so the deploy
  page can tell the user before they approve.

## How clients use it

Nothing new to call. `StartBacktest` refuses a bot that reads volume with
Connect code `failed_precondition`, and an `ErrorDetail` with code
`NOT_BACKTESTABLE` and the new reason:

```http
POST /strategies.v1.StrategiesService/StartBacktest
Content-Type: application/json
Connect-Protocol-Version: 1

{"versionId": "sha256:…", "idempotencyKey": "bt-1"}
```

```json
{
  "code": "failed_precondition",
  "message": "the bot can't be backtested on candles: …",
  "details": [{
    "type": "strategies.v1.ErrorDetail",
    "debug": {"code": "NOT_BACKTESTABLE", "notBacktestableReason": "READS_VOLUME"}
  }]
}
```

The same value can appear as `Backtest.notBacktestableReason` on a backtest
whose status is `NOT_BACKTESTABLE`, and as the deploy proposal's
`notBacktestableReason`.

## Migration

None required. A client that shows `not_backtestable_reason` should give
`READS_VOLUME` its own wording, for example "it reads trading volume, which
backtests don't have"; until then, treat an unknown reason as "can't be
backtested".
