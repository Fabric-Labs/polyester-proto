## What and why

`ClaimDailyReward` no longer answers `deadline_exceeded` after it submitted
today's reward payout but could not confirm the claim's result in time. The
payout may have completed, so a timeout misled clients into reporting a
failure for a reward that was paid or is being paid.

The click now answers the claim's stored state instead: `CLAIM_CLAIMED` with
its transfers when the claim completed, or `CLAIM_PROCESSING` while it is still
being processed. Only when that state cannot be read either does it return the
new error code `ERROR_CODE_CLAIM_OUTCOME_UNKNOWN` (REST `CLAIM_OUTCOME_UNKNOWN`,
ConnectRPC `unavailable`, HTTP 503). Its `ErrorDetail` carries the new
`claim_id` field naming the claim; the REST problem body carries the same value
as `claim_id`. `claim_id` is empty for every other error code.

The claim is never paid twice: retrying the claim returns the same claim and
its current state.

## How clients use it

Treat `CLAIM_OUTCOME_UNKNOWN` as "submitted, not yet confirmed": read the claim
status, or retry the claim, until it reports `CLAIM_CLAIMED`.

ConnectRPC, `POST /claims.v1.ClaimsService/ClaimDailyReward` with a JSON body:

```bash
curl -sS -X POST https://<api-host>/claims.v1.ClaimsService/ClaimDailyReward \
  -H 'Authorization: Bearer <session-jwt>' -H 'Content-Type: application/json' -d '{}'
```

```json
{
  "code": "unavailable",
  "message": "claim payout result is not confirmed yet; check the claim status",
  "details": [
    {"type": "claims.v1.ErrorDetail", "value": "<base64 claims.v1.ErrorDetail: code 16, claim_id dcl_...>"}
  ]
}
```

REST, `POST /v1/trading/daily-claim/claim`:

```bash
curl -sS -X POST https://<api-host>/v1/trading/daily-claim/claim \
  -H 'Authorization: Bearer <session-jwt>' -H 'Content-Type: application/json' -d '{}'
```

```json
{
  "type": "https://polyester.dev/problems/claim-outcome-unknown",
  "title": "Service Unavailable",
  "status": 503,
  "detail": "claim payout result is not confirmed yet; check the claim status",
  "code": "CLAIM_OUTCOME_UNKNOWN",
  "claim_id": "dcl_..."
}
```

Then poll `GET /v1/trading/daily-claim` (ConnectRPC
`/claims.v1.ClaimsService/GetDailyClaimStatus`) until its `claim_id` matches and
its `state` is `CLAIM_CLAIMED`, or call `ClaimDailyReward` again.

## Migration

None: the contract only adds an error code and an error detail field. Clients
that treated `deadline_exceeded` from `ClaimDailyReward` as a failed claim
should show `CLAIM_OUTCOME_UNKNOWN` as a pending claim instead.
