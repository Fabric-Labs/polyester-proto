## What and why

A market order whose attached take-profit or stop-loss its own fill would trigger is now refused instead of placed. Before, the order filled and the protective leg fired within milliseconds, closing the position straight away, and preview said the order was admissible. A take-profit or stop-loss on the last price is checked against the best price the market order takes: the best ask for a buy, the best bid for a sell, at or past it counting as reached. Create, batch create and preview answer `ERROR_CODE_TRIGGER_WOULD_TRIGGER_IMMEDIATELY`, the code a trigger modify onto a reached price already returns, and nothing is placed. A take-profit or stop-loss on the index price is not checked at create or preview: the order is accepted, then rejected with the same reason before it trades when the index has already reached the leg's trigger price, and nothing is placed. A last-price leg the market reaches between acceptance and the order reaching the book is rejected the same way. Limit orders keep their existing rule: an attached take-profit or stop-loss must be on its profitable or protective side of the limit price (`ERROR_CODE_TRIGGER_PRICE_INVALID`). No message, field or enum value is added; only `ERROR_CODE_TRIGGER_WOULD_TRIGGER_IMMEDIATELY`'s documentation changes.

## How clients use it

REST `POST /v1/orders` and `POST /v1/orders/preview`, ConnectRPC `/orders.v1.OrdersService/CreateOrder` and `/orders.v1.OrdersService/PreviewOrder`. A market buy when the best ask is 73,438.18 with a stop-loss at 77,110.09 is refused:

```json
{"order":{"symbol":"BTC-USDT","side":"BUY","baseQty":"0.0001","marketIoc":{},
 "attachedRisk":{"stopLoss":{"triggerPrice":"77110.09","triggerPriceSource":"LAST_PRICE","child":{"marketIoc":{}}}}}}
```

The answer is HTTP 400 (ConnectRPC `failed_precondition`) with `ERROR_CODE_TRIGGER_WOULD_TRIGGER_IMMEDIATELY`; a preview answers `admissible: false` with the same code. A stop-loss below the best ask is placed as before. With `"triggerPriceSource":"INDEX_PRICE"` and an index already at or below 77,110.09, create answers the accepted order, which then ends `REJECTED` with that code as its `reject_reason` in order reads.

## Migration

None: no client code changes. A client that relied on a market order's attached leg firing at once gets the error and should place the market order without that leg, or choose a trigger price the market has not reached.
