## What and why

A checked bot now comes with its **flow**: what wakes it, what it checks and
what it may do, read from its code and manifest. The Studio draws it as a
graph, one lane per trigger, so a user can see a bot's logic without reading
its code.

- **New field `flow` (`StrategyFlow`)** on `VersionValidation` (8), so
  `SaveDraftVersion` and `CreateStrategy` return it, and on
  `GetStrategyVersionResponse` (9), so `GetStrategyVersion` and
  `GetStrategy` return it. Set only when the bot is valid; not set for a
  version stored before flows existed.
- **New messages:**
  - `StrategyFlow`: `nodes`, `edges`, `notes`, and `complete`.
  - `FlowNode`: `node_id`, `kind` (the `FlowNode.Kind` enum: `TRIGGER`,
    `CONDITION`, `ACTION`), `label`, `span`, `event`, `action`, and
    `settings`.
  - `FlowEdge`: `from_node_id`, `to_node_id`, and `branch`.
  - `SourceSpan`: `start_line` and `end_line`.
- **Node kinds:**
  - A trigger woken by a manifest event has the event, exactly as the money
    card names it, in `event`. Its `label` is the schedule in words for a
    schedule (`Every Monday 09:00 UTC`, `Every 15 minutes`), and the same
    text as `event` otherwise. Another trigger, such as an order filling,
    has a plain `label` and an empty `event`.
  - A condition is an `if` or `elif` test, with a `"true"` and a `"false"`
    edge out of it.
  - An action's `action` is one of BUY, SELL, CANCEL, LOG, NOTIFY, PAUSE,
    WATCH, UNWATCH, or TRIGGER.
- **Incomplete flows:** when part of the code can't be placed (a loop, or a
  helper function), `complete` is false and `notes` says what is missing.
  The graph then leaves out that part, and anything after it on the same
  path, but never shows an edge the code can't take.

## How clients use it

```json
POST /strategies.v1.StrategiesService/GetStrategyVersion
{"versionId": "sha256:…"}

{"versionId": "sha256:…", …,
 "flow": {
   "nodes": [
     {"nodeId": "t0", "kind": "TRIGGER", "label": "Every Monday 09:00 UTC",
      "event": "schedule mon 09:00 UTC"},
     {"nodeId": "c0", "kind": "CONDITION", "label": "RSI(BTC/USDT, 1d, 14) > 75",
      "span": {"startLine": 3, "endLine": 3}},
     {"nodeId": "a0", "kind": "ACTION", "label": "Skipped this week: …",
      "span": {"startLine": 4, "endLine": 4}, "action": "LOG"},
     {"nodeId": "a1", "kind": "ACTION", "label": "Buy BTC/USDT for budget",
      "span": {"startLine": 6, "endLine": 6}, "action": "BUY",
      "settings": ["budget"]}],
   "edges": [
     {"fromNodeId": "t0", "toNodeId": "c0"},
     {"fromNodeId": "c0", "toNodeId": "a0", "branch": "true"},
     {"fromNodeId": "c0", "toNodeId": "a1", "branch": "false"}],
   "complete": true}}
```

- Draw one lane per trigger, with every node reachable from it along the
  edges. Lines are 1-based and inclusive, so a client can highlight a node's
  code.
- Node IDs are stable within a version only; never compare them across
  versions.
- When `complete` is false, show `notes` beside the graph: the graph is
  then partial, not wrong.

## Migration

None. The field is new and optional, so existing clients are unaffected.
