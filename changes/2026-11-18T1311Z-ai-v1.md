## What and why

The assistant can now hand a request for a trading bot to a strategy coder, a
subagent that writes the bot, checks it, runs its behaviour examples and
backtests it, then proposes it for deployment. The coder never deploys,
trades or moves funds: it returns a link to the website's deploy page, where
the user deploys the bot with MFA and a wallet signature.

`WatchRun` streams the delegation as it happens:

- `SubagentStarted` gains `funding` and `credit_cap`: what pays for the
  coder's work, and the most credits it may use. The cap is shown before the
  coder starts. Each of the coder's model requests is limited to what is left
  of it, and a request it cannot cover is not sent: the coder stops there.
- `FundingMode` gains `SPONSORED`: Polyester pays, and the work uses no
  credits and no key of the user's. Only subagent work is sponsored.
- `ToolStarted` and `ToolFinished` gain `subagent_id`: set on the coder's own
  tool calls (validating, running examples, backtesting), so a client can show
  them as the coder's progress under its `SubagentStarted`.
- `SubagentFinished` gains `deploy_url`: the deploy page of the bot the coder
  proposed, when it proposed one.

## How clients use it

A run that delegates streams, in order:

```json
{"seq": "4", "subagentStarted": {"subagentId": "7Hq2Xb", "name": "strategy-coder", "funding": "SPONSORED", "creditCap": "500"}}
{"seq": "5", "toolStarted": {"toolCallId": "7Hq2Xb/call_1", "name": "validate_strategy", "input": {}, "subagentId": "7Hq2Xb"}}
{"seq": "6", "toolFinished": {"toolCallId": "7Hq2Xb/call_1", "name": "validate_strategy", "ok": true, "subagentId": "7Hq2Xb"}}
{"seq": "9", "subagentFinished": {"subagentId": "7Hq2Xb", "name": "strategy-coder", "ok": true, "summary": "Proposed Weekly BTC DCA.", "deployUrl": "https://polyester.com/bots/deploy/2Lx"}}
```

- Show the coder's calls (`subagentId` set) nested under its
  `SubagentStarted`, and the cap next to it: "up to 500 credits", or
  "sponsored" when `funding` is `SPONSORED`.
- Show `deployUrl` as a link or button to the deploy page. The assistant's
  answer names the same link.
- The assistant's own `ToolStarted` and `ToolFinished` events carry no
  `subagentId`, as before.
- `Usage` in `RunCompleted` and `RunFailed` already counts subagents' tokens.

## Migration

None. Every field is new: `funding` and `credit_cap` are plain proto3
scalars, so an older server sends neither (`FUNDING_UNSPECIFIED` and 0), and
`subagent_id` and `deploy_url` are optional strings. `SPONSORED` appears only in
`SubagentStarted.funding`: `GetUsage` never returns it. A client that ignores
the new fields shows the coder's calls as the assistant's own, which is still
correct.
