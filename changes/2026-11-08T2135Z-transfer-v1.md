## What and why

The REST reference described several REST amount fields with the integer
form that ConnectRPC uses: for internal transfers and trading withdraws it
said "0.5 is encoded as 500000000000000000". REST amount fields take and
return plain decimal strings in whole units of the asset, so a client that
followed the text sent 10^18 times the intended amount. The REST reference
now describes each of these fields as a decimal string with an example. No
request or response encoding changed.

REST fields with corrected descriptions:

- `POST /v1/trading/internal-transfers`: request `amount`, response `amount`.
- `POST /v1/chain/trading-withdraws` and `POST /v1/chain/trading-withdraws:wallet`:
  `payload.amount` and `payload.assetId`. `payload.assetId` is now also marked
  required in the REST schema; requests without it were already refused.
- Daily claim status and claim: `rewards[].amount`.
- Balances: `balances[].funding`, `trading`, `reserved`, `available`, and
  `balances[].symbol`, which is an asset symbol such as `USDT`.
- Ledger transfers: `transfers[].amount`, `balanceAfter`, and
  `transfers[].asset`, which is an asset symbol.
- Order and user trades: `trades[].fee`, `trades[].referralShare`.
- Sub-account policies (`/v1/auth/policies/subaccounts` create, get, list and
  `PATCH /v1/auth/policies/subaccounts/{policy_id}`): `maxOrderNotional`, a
  decimal string in quote asset units (USDT) with at most 6 decimal places.
  The text said "canonical quote microunits"; a client that sent `"500000"`
  for 0.5 USDT set a cap of 500000 USDT.

ConnectRPC descriptions are unchanged: those amount fields are 18-decimal
integers carried as U128 `{hi, lo}`, and `max_order_notional` is an integer
count of quote microunits.

## How clients use it

Send REST amounts as the decimal itself. Half a unit is `"0.5"`:

```http
POST https://<api-host>/v1/trading/internal-transfers
Content-Type: application/json

{
  "destinationSmartAccountAddress": "0x2222222222222222222222222222222222222222",
  "assetId": 7,
  "amount": "0.5",
  "idempotencyKey": "transfer-0001"
}
```

REST amounts accept at most 18 decimal places; a nonzero digit beyond the
18th is refused. The integer string `"500000000000000000"` means that many
whole units. ConnectRPC takes the same amount as the integer amount × 10^18:

```json
POST /transfer.v1.InternalTransferService/CreateInternalTransfer
{"assetId": 7, "amountE18": {"hi": "0", "lo": "500000000000000000"},
 "destinationSmartAccountAddress": "0x2222222222222222222222222222222222222222",
 "idempotencyKey": "transfer-0001"}
```

A trading withdraw over REST also sends `payload.amount` as a decimal, but
the signed authorization carries `amount_e18`, the amount × 10^18: for
`"0.5"`, sign 500000000000000000.

## Migration

None for clients that already send decimal REST amounts. A REST client that
followed the earlier text and sent integer strings, such as
`"500000000000000000"` for 0.5, must send the decimal (`"0.5"`) instead. The
same applies to a policy `maxOrderNotional` sent in microunits: send
`"0.5"`, not `"500000"`, for a 0.5 USDT cap.
