## What and why

The public contract now ships a second SBE schema: the SBE market data
WebSocket, `marketstream`, schema ID 20, version 0, `semanticVersion` 1.0.0.
It is a binary market-data stream for latency-sensitive clients such as
market makers: each spot pair's trades, best bid and offer, top-20 depth and
a deep live order book (a window of up to 1,000 levels per side, kept by a
snapshot and exact incremental updates) over one WebSocket at
`wss://<api-host>/ws/market.sbe`. Access is open: no API key is needed.

The publication carries it as `sbe/marketstream-v0.xml`. `manifest.json`
names the file under `paths.marketDataSbe` and describes it in the
`marketDataWebSocketSbe` block (`schemaId`, `schemaVersion`,
`semanticVersion`, `sha256`), beside the trading WebSocket's
`tradeWebSocketSbe`. Trades the stream could not deliver are recovered with
`marketdata.v1.MarketDataService/GetTrades` by trade identifier
(`after_trade_id`).

## How clients use it

Generate a codec from `sbe/marketstream-v0.xml` with Real Logic's `sbe-tool`
(Java, C++, C#, Go and Rust), connect, and send one `Subscribe` (template 1)
with a `requestId` and one item per pair and stream: `TRADES` = 1,
`BBO` = 2, `DEPTH20` = 3, `DEPTH` = 4. The server answers with one
`SubscribeResponse` (template 20), one result per item in request order,
then each stream's messages. `Unsubscribe` (template 2) ends streams the
same way: its `SubscribeResponse` answers `OK`, or `NOT_SUBSCRIBED` for a
stream the connection does not hold, and no message of an unsubscribed
stream follows it. Every message is one SBE message in one binary frame,
little-endian, with the 8-byte SBE header.

- `bbo` (`BestBidOffer`) and `depth20` (`DepthSnapshot`) are latest-only full
  state: keep the message with the highest `(bookEpoch, updateId)`; an equal
  pair is an unchanged re-send.
- `depth` starts with a `DepthSnapshot` (template 24) of the live window,
  whose `levelsPerSide` is the window size N, then sends a `DepthUpdate`
  (template 25) per book update. Apply an update only to a book at exactly
  `firstUpdateId - 1` of the same `bookEpoch`; each level sets its total
  quantity and 0 removes it; then truncate each side to the N best levels.
  A later `DepthSnapshot` replaces the book. On a gap, unsubscribe and
  subscribe again for a fresh snapshot. For depth beyond the window,
  `orderbook.v1.OrderbookService/GetOrderBook` serves a separate snapshot of
  up to `max_depth` levels per side at its own `(book_epoch, book_seq)`;
  never apply `DepthUpdate`s to it.
- `trades` (`Trades`) starts with a `TradesThrough` baseline and sends one
  every second. A `TradesSkipped` names trades the subscription will not
  receive live; fetch them by trade identifier, ascending and gap-free:

```bash
curl -sS https://<api-host>/marketdata.v1.MarketDataService/GetTrades \
  -H 'Content-Type: application/json' \
  -d '{"symbolId": 1, "afterTradeId": "4096", "limit": 1000}'
curl -sS 'https://<api-host>/v1/spot/markets/BTC-USDT/trades?afterTradeId=4096&limit=1000'
```

Continue from `nextAfterTradeId` until it reaches the skipped range's last
trade identifier; when it equals the cursor you sent, retry with backoff.
Prices are quote-asset units × 10^9, quantities are scaled by the pair's
`base_quantity_scale`, and times are Unix nanoseconds UTC.

Limits: 128 subscriptions per connection, 4 KiB per client message, a
WebSocket ping every 20 seconds with a 60-second pong deadline, and the
public WebSockets' per-address connection limits.

## Migration

None: the schema is new. Later versions of schema 20 add fields, messages
and enum values without breaking existing decoders, which skip what they do
not know by `blockLength` and `templateId`.
