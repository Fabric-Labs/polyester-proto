## What and why

Attached take-profit, stop-loss and trailing stop orders no longer trade with
the order they protect, and a self-trade prevention block is now visible in
the trigger's history.

- **The parent's rest is canceled when its attached exit fires.** When an
  attached take-profit, stop-loss or trailing stop fires while its own order
  still has an unfilled remainder resting on the book, the exchange first
  cancels that remainder, then places the attached order. Fills before the
  cancel stand and the remainder's reserved funds are released. The parent
  ends `CANCELED` with the new `orders.v1.CancelReason`
  `CANCEL_REASON_ATTACHED_EXIT_FIRED = 18`. Before, the attached order could
  meet its own parent on the book.
  An attached order the book cannot take (for example, no room for a new
  price level) is refused without touching the parent, which keeps resting.
  Once the parent ended this way it can no longer be modified: a
  `ModifyOrder` of it, its attached risk included, is refused with
  `ERROR_CODE_ORDER_ALREADY_TERMINAL`.
- **A self-trade prevention block is a fire refusal, not an end.** When
  self-trade prevention (`EXPIRE_TAKER` or `EXPIRE_BOTH`) expires an attached
  take-profit, stop-loss or trailing stop order because it would have traded
  with another of the account's resting orders, the attached leg stays live.
  Its trigger records one `EVENT_FIRE_REFUSED` with the new
  `triggers.v1.TriggerFailureReason`
  `TRIGGER_FAILURE_REASON_SELF_TRADE_PREVENTED = 249`, once per blocked
  episode: not again for every trade while the same order blocks it. The leg
  fires again at a new trade at or beyond its trigger price, or once the
  blocking order is gone or no longer at the best price.
- `orders.v1.ErrorCode` gains `ERROR_CODE_SELF_TRADE_PREVENTED = 307`, the
  error code of that refusal reason. No request is ever answered with it.

## How clients use it

No request changes. The new values appear where the enums already appear:

- An order's `cancel_reason`: `OrdersReadService.GetOrder`,
  `GetOrderHistory` and the private WebSocket's `OrderEvent`.
- A trigger event's `fire_refusal_reason` on `EVENT_FIRE_REFUSED`:
  `TriggersService.ListTriggerEvents` and the private WebSocket trigger-events
  channel.

```bash
curl -sS https://<api-host>/triggers.v1.TriggersService/ListTriggerEvents \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer <session-token>' \
  -d '{"triggerId": "<trigger-id>", "eventType": "EVENT_FIRE_REFUSED", "limit": 20}'
```

```json
{"events": [{"triggerId": "<trigger-id>", "eventType": "EVENT_FIRE_REFUSED",
  "childSeq": 2, "firePriceTicks": "104000000000", "tsNs": "<ns>",
  "fireRefusalReason": "TRIGGER_FAILURE_REASON_SELF_TRADE_PREVENTED"}]}
```

REST drops the enum prefix: `GET /v1/triggers/<trigger-public-id>/events`
shows `"fireRefusalReason": "SELF_TRADE_PREVENTED"`, and an order read shows
`"cancelReason": "ATTACHED_EXIT_FIRED"`.

With `TRIGGER_FAILURE_REASON_SELF_TRADE_PREVENTED`, `child_seq` names the
attached order that self-trade prevention expired. That order was placed and
ends `CANCELED` with `CANCEL_REASON_STP_EXPIRE_TAKER` or
`CANCEL_REASON_STP_EXPIRE_BOTH`; for every other fire refusal reason,
`child_seq` names an attempt that placed no order. The next fire takes the
next `child_seq`.

Trading WebSocket (SBE schema `tradews`, version 36): `CancelReason` gains
`ATTACHED_EXIT_FIRED = 18`, and `RejectCode` gains
`SELF_TRADE_PREVENTED = 307`, which no command is answered with.

## Migration

None: the enums gain values and no existing value changes. A client that
switches exhaustively over `CancelReason`, `TriggerFailureReason` or
`ErrorCode` should handle the new values; an unknown value should already fall
back to a generic text. A client that treated an attached leg's self-trade
expiry as the end of its protection should read the trigger's `status`: the
leg stays `STATUS_ARMED`.
